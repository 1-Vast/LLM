## 本轮结论与可复现结果

本轮修复的是“一个预测分布究竟凭什么产生”的证据边界，并未证明模型预测精度提高。
生产候选估计器为 `case-memory-production-2`，保持 `uncalibrated`，默认开关关闭。
冻结的旧外部评估结果和旧案例文件保留；新的代理案例写入单独文件。

开发诊断只使用原 65 个参考化合物，按机制类分层，以固定种子留出 11 个，54 个用于建库。
每次分割后重新计算质心、检测阈值与参考标签，参考标签的自身化合物从自身质心剔除。
原 26 个外部测试化合物不参与。预测器只收到候选假设、实验条件和状态为空的查询，
待预测的表达谱只在评分器中使用。这个实验评估条件代理读数分布，不评估机制发现能力。

| 指标 | 结果 |
|---|---:|
| 独立训练 / 留出化合物 | 54 / 11 |
| 可评分项 / 全部项 | 156 / 156 |
| 新估计器 NLL | 1.372004 |
| 相同数据、相同五种结局的 Jeffreys 频率平滑基线 NLL | 1.353464 |
| 每个化合物先取均值后的 NLL 差（新减基线） | +0.027286 |

结果不支持新估计器优于简单基线。11 个独立单元太少，不做显著性或外部泛化主张；
不根据这次结果继续搜索收缩常数。数值也不能和原外部评估直接比较：人群、标签空间、
数据分割和预测实现均不同。较高 NLL 表示对实际结局给出的概率较差，单凭 NLL 不能把原因
唯一归结为校准；它同时受分辨能力和校准影响。

## 已实施的修复

1. 删除“检索到案例就生成 0.8/0.5 概率”的回退。没有具有明确条件假设、对比对和实际结局的
   参考记录时，返回 `insufficient_outcome_support`；不从假设列表推断哪个假设成立。
2. 每个假设的结局分布只由该条件假设下的记录估计；另一假设缺少支持时，整体拒答，
   不把同一组记录改换标签后伪装成两个条件分布。
3. 实验匹配检查 assay、readout、cell、time、dose；同名 action 更换时间也不能复用旧结果。
   生物系统、干预类型、测量类型、对照设计从用户上下文传入，不再用空字符串代替。
   硬兼容规则没有放宽：缺少必要元数据可造成拒答，需要补元数据而非让所有数据兼容。
4. 支持量来自真正参与该动作估计的独立源单元，按 `provenance.independent_unit` 去重。
   Kish 有效支持由同一组实际权重计算，不把检索结果数或 hypothesis update 条数当作样本数。
5. 分布采用温度平滑和支持量/域偏移收缩；基准先验在动作结局上对称。
   因而两个条件下观察到完全相同分布时，不会仅靠“自己的假设”先验制造判别力。
   常数 8、1.5、0.75 是未拟合的候选设定，回执明确标为未校准，不是生物学经验概率。
6. `RealMeasurement` 新增可选的 `conditioning_hypothesis`、`contrast`、`label_kind`。
   默认字段不进入旧记录的序列化，保留旧摘要与追加版本链的兼容性。
7. 代理标签只能在显式研究模式中使用，进入证据资格判定时被拒绝。正常工具调用不能
   在内部偷偷切换成研究模式。未计划/缺失不计为结果，QC 失败不会推断生物机制。
8. 缓存包含完整动作语义和开关状态；撤销开关、改变动作条件或结果词汇会使旧缓存失效。

## 新案例文件的含义

`outputs/case_memory_integration/episodes/proxy_reference_cases.jsonl.gz` 含 65 个参考化合物，
244 个化合物×细胞条件，针对其他机制类展开为 976 个派生对比读数。
**独立化合物仍只有 65 个，976 不是独立样本数。**

每条读数记录具体对比假设和来源，`label_kind=derived_annotation_proxy`。
信号低于参考谱范数第 5 百分位的 `absent` 是基准中的操作性低信号定义，
不是经过实验验证的检测限，更不能解释为“靶点没有作用”。缺乏可用质心记为歧义，
不伪装成实验 QC 失败。质心相似性和 MoA 注释都不产生 qualified experimental evidence。
新文件中不进行生物假设淘汰，也不填充 qualified evidence。

## 如何找数据：先定义要证明什么

先把用户问题拆为可观测目标，例如“哪一个后续实验最能区分靶点作用和非特异应激”，
再寻找同时覆盖初始状态、候选干预、实际结局与对照的数据。只搜索“virtual cell dataset”
会得到大量表达矩阵，却未必能评估后续决策。优先下载元数据和清单，评估重叠与动作覆盖后
再下载表达矩阵，避免下载几十 GB 后才发现每个化合物只有一个可用动作。

| 资料入口 | 用途 | 必须检查的限制 |
|---|---|---|
| [CLUE 数据入口](https://clue.io/data)、GEO GSE92742 / GSE70138、LINCS 2020 | 化合物、细胞系、时间剂量条件与表达响应；做基础参照和化学外推 | 同一个化合物在不同研究中重复；Level 5 是聚合签名；平台与研究不能混称 |
| [sci-Plex 原始研究](https://doi.org/10.1126/science.aax6234)及其 Data availability/GEO 记录 | 单细胞药物响应、细胞状态异质性、剂量反应 | 剂量系列不等于纵向时间轨迹；破坏性取样不是同一细胞的前后配对 |
| [Tahoe-100M 数据卡](https://huggingface.co/datasets/tahoebio/Tahoe-100M) | 扩展药物×细胞上下文；先抽取具有对照与多个候选条件的子集 | 数据量大不等于独立药物数多；先审计所用预训练模型是否已接触该数据 |
| [全基因组 Perturb-seq](https://doi.org/10.1016/j.cell.2022.05.013)及其原始数据 | 遗传干预响应与候选机制的正交参照 | 基因敲低/敲除不等于药物结合或抑制；必须保留干预方式和效率 |
| [DepMap/PRISM](https://depmap.org/portal/download/all/) | 存活、药敏及细胞背景，作为表型层桥接 | 活力与转录响应不可当同一真值；需要化合物、细胞、暴露和版本匹配 |

本轮在线核对：CLUE、Tahoe 数据集 API、GEO 页面可访问；Europe PMC 返回 sci-Plex、
Perturb-seq 和 Tahoe 的文献记录。DepMap 下载入口在本环境返回 HTTP 403，未获取文件，
应使用其正常访问流程/公开镜像并核对授权，不绕过访问限制。GEO 的具体附件和平台映射仍需
逐项核对，不能仅凭 accession 页面可访问就声称下载、清洗或验证完成。

建议检索式：`perturbation single-cell dose response matched controls raw counts`；
`target engagement orthogonal validation drug transcriptomics`；
`Perturb-seq guide efficiency biological replicate control`。以原论文的 Data availability
追到 accession/DOI 和原始元数据，再查后续更新或撤回；不要把综述/模型生成摘要当数据来源。

## 如何构造数据：四种产品必须分开

1. **观测表**：study、batch、donor/细胞系、compound connectivity block/基因干预、时间、
   剂量与单位、对照、replicate、assay、feature space、QC、原始文件哈希。
   单细胞原始计数、归一化表达、logFC 与 L1000 z-score 必须显式区分。
2. **响应/转移表**：在同一批次和可比上下文中匹配对照，计算有符号变化、方差、通路响应和
   细胞群组成。没有真实前后配对时，标记 population response；不要造出单细胞轨迹。
3. **证据表**：靶点结合、近端功能、转录变化、表型分别建表；记录检测方法和证据等级。
   MoA 注释只能作分层信息/代理监督；不自动变成 target engagement 或因果真值。
4. **决策 episode**：用户当时已知的状态、竞争假设、合法候选实验、成本与前置条件、
   已执行实验的观测及 QC、预先注册的解释规则、之后采取的动作。失败和歧义也完整保留。

这四层的原因是：一个“完整漂亮的案例文本”无法判断信息何时可见，也无法防止把结论塞入
模型输入。案例库更适合充当带来源和适用域的经验支持集；规划器提出并比较动作，虚拟细胞
给出条件结局分布，只有真实新实验经过资格判定后更新证据。

## 预处理与分割的具体顺序

1. 先建来源 manifest，记录版本、许可、URL、哈希、获取时间、测量粒度和单位；冻结独立
   单元分组与分割，再计算任何需要拟合的统计量。
2. 化合物按结构连接块/必要的立体化学层次对齐；基因统一稳定 ID 并保留原始 ID；
   不把别名无法映射或多对多匹配静默丢弃。跨研究同时检查文件、化合物、细胞和模型训练重叠。
3. 原始计数先做样本/细胞 QC，再按合适的生物重复构建 pseudobulk 或分布响应；同一孔中
   几千个细胞不是几千个实验重复。不同基因的多行记录也不是 replicate。
4. 控制批次、细胞类型、时间和剂量；不把所有处理条件混为一条状态。缺失保留缺失，
   只在确属已测量且为零时记录零。差异响应必须保留方向，不能只留下范数。
5. 训练集拟合基因筛选、归一化参考、质心、阈值和校准参数；开发/测试只应用。
   质心派生标签的训练案例须 leave-one-unit-out；外层留出评估须重建所有训练统计，
   不仅是最后预测器中删掉该案例。
6. 拆分至少包括训练、开发校准和最终测试。按化合物/供体/研究分组，按用途补结构外推和
   跨实验室外推；用独立单元聚类的置信区间。不得随机拆单细胞/同一药物重复来冒充 OOD。
7. 除规范样例外必须纳入负响应、未检测、QC 失败和歧义，保留其比例和筛选过程。
   人工/LLM 合成案例仅验证解析与规划流程，不进入生物性能主终点。
8. 图文双核对：每个标签追溯到原始行；检查样本量表、重复关联图、处理/对照分布、
   缺失热图、分割重叠、剂量时间覆盖、校准图。视觉合理性不能替代统计检验或文件校验。

现有 `ProblemCompiler` 不是通用的原始 RNA-seq 分析流水线，不能把任意上传矩阵直接当成
已匹配对照的有符号差异。下一轮接入原始数据时，应先给它经过上述处理的、明确条件和
数值语义的 effect table，并单独验证 replicate 聚合与多条件处理。

## 下一步应如何证明价值

第一步，以简单频率平滑为正式基线，在独立的开发校准集拟合少量收缩参数；不要同时搜索
几十种相似度、池规则和终点。校准后锁定算法版本和数据清单，再运行第二次未触碰外评。
200 个独立单元可以是工程目标，但不是统计充分性的保证；应按最小有意义 NLL/决策效益差、
聚类方差和失败率做功效/精度规划，避免以固定数量替代设计。

第二步，构建每个 episode 至少两个合法候选动作、可比较成本和不同结局信息量的决策集。
oracle 与所有规划器必须共享相同效用、停止/拒答规则和预算；同时报告正确、错误、拒答、
覆盖率与总成本。不能把保守 oracle 的正确率和强制作答基线的正确率直接相减。
若最优可行策略没有正的效用提升空间，先修任务设计，不应继续调规划器。

第三步，用户前瞻性闭环：初始数据只进入 policy view；未来结局只进入 evaluator view。
智能体输出“下一步实验、为什么能区分假设、预测结局分布、支持案例及不确定性、
每种结果对应的下一步”，而非只输出一个最可能机制。完成实验后再更新 episode。
这才是案例库、虚拟细胞与智能体可以形成科学闭环的检验对象。
