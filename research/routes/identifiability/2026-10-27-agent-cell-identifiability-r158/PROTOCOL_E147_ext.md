# PROTOCOL E147-ext（预注册）：`expected_uninformative` 白名单的验证

2026-10-27，R158。**在任何计算前冻结。**

## 为什么

R157 里 `feature_audit` 把四档全部 FLAG，因为**每个留出药的身份 one-hot 列在评估集上恒定**——这是"未见"的定义，不是缺陷。

**所以工具需要一个"预期无信息块"白名单，否则任何替代实验都会被全线报警。**

**但白名单本身有风险**：R138 的死身份块**同样是"故意的"**，而它拖累了树。**如果当时有白名单，它会把那个缺陷藏起来。**

## 构造（真实数据，10 个药留出）

| 用例 | 期望 |
|---|---|
| `r157_no_whitelist` | **FLAG**（留出列恒定） |
| `r157_with_whitelist` | **PASS**（声明为预期） |
| **`r138_masked_with_whitelist`** | **PASS** ← **这正是危险：同样的声明会藏住真缺陷** |
| `prediction_alarm_with_whitelist` | **FLAG**（常数臂，不可被白名单压制） |
| `split_alarm_with_whitelist` | **FLAG**（训练/评估重叠，不可被压制） |

## 预测（写死）

- **H382（白名单按设计工作，且只有特征级可被压制）**：五个用例全部符合期望。
- **H383（过度或不足压制）**：任一不符。

**若 H382 成立 → 记下：白名单只压制特征级、只压被点名的列；但**它把"意图声明"变成信任前提，而 R138 说明意图声明可以错**。**

## 边界

- 第五个用例的重叠比例是新构造的，不代表真实划分。
- 回顾性；不涉及机制、临床、药物选择；不做元学习/RSI。
