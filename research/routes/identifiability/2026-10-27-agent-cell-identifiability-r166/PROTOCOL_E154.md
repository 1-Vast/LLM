# PROTOCOL E154（预注册）：**先验对哪些药有用**——增益是铺开的还是集中在少数通路水平

2026-10-27，R166。**在任何计算前冻结。** 只读 `gdsc_combinations`。

## 为什么

冻结结论给出的是**总体**增益（`通路−identity` ≈ +0.118）。但"适用条件"还差一层：**这个增益是均匀铺在 38 个通路水平上，还是由少数水平撑起来的？**

**若是后者，实践规则就必须加上"你的药得落在被覆盖的那几个通路里"。**

## 构造

- `both_unseen` 池、ridge、**内层 3 折 CV 选 λ**、40 划分、种子 **20261067**。
- 把评估键**按"未见的 anchor 药所属通路"分组成子集**（只取评估键 ≥200 的组）。
- **每个子集内**算 `ρ(+通路) − ρ(identity)`——即"已知 anchor 的通路、再知道 library 的通路，是否还有帮助"。
- 报：子集数、各子集增益、**集中度**（增益最高的 3 个子集占总正增益的比例）、以及各子集增益与子集大小的关系。

## 预测（写死）

- **H396（铺开）**：**正增益的子集数 ≥ 总子集数的一半**，且**前 3 个子集占正增益 < 60%**。
- **H397（集中）**：**正增益子集 < 一半**，或**前 3 个占 ≥60%**。

**若 H397 成立 → 实践规则加一条"先看该药的通路是否在被覆盖的少数水平里"。**
**若 H396 成立 → 规则可以不加这个限制。**

## 判据

- 每子集：评估键数、增益、CI（若可算）。
- 集中度指标与子集间增益的离散度。

## 边界

- 子集划分依赖 anchor 侧通路；**library 侧未单独分**（下一轮可补）。
- 子集内样本小 → **必须报每子集的键数与 MDE**，小样本子集的增益不作单独结论。
- 回顾性；不涉及机制、临床、药物选择；不做元学习/RSI。
