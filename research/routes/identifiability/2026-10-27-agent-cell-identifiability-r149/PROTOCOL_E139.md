# PROTOCOL E139（预注册）：把"每个特征是否携带信息"落成**可复用检查代码**

2026-10-27，R149。**在任何计算前冻结。** 只读 `gdsc_combinations`。

## 为什么

**同一类错误已经出现五次**：某个特征（或整臂）在评估条件下不再携带信息，却仍在改变模型行为：

| 轮次 | 症状 |
|---|---|
| R135 | `one_seen_only` 与训练集重合（样本内） |
| R144 | 边际臂在两药未见时 ≡ 常数 |
| R147 第一版 | 整数身份码给留出药**任意**分数（identity 假得 0.081） |
| R138/R139 | 死身份块（全 −1）拖累树 |
| R148 | 确认上述，撤回 C106/C107 |

**第九条规则我写进了文档，却还是靠下一轮才发现。所以规则必须变成代码。**

## 要建的东西

`research/tools/feature_audit.py`，三部分：

1. **特征级**：对每列报评估集上的 `std`、**评估值未在训练出现的比例**（类别码）、是否恒定。
2. **划分级**：报训练/评估键的重叠比例（抓样本内）。
3. **预测级**：对每个臂报预测在评估集上的 `std`（抓常数臂/退化臂）。

**任一检查触发即打印 `FLAG`，并把三部分汇成一个 `passed` 布尔。**

## 验证方式（这是本轮的实验）

**用四段历史配置重建当年的情形，看检查能否各自触发；再用 R148 的干净设计看它是否能通过。**

| 用例 | 期望 |
|---|---|
| `r147_attempt1`（整数身份码 + 留出药） | **FLAG**（unseen_frac 高） |
| `r138_no_identity`（身份码全 −1） | **FLAG**（恒定 + unseen_frac = 1） |
| `r144_marginal`（边际臂常数预测） | **FLAG**（pred std = 0） |
| `r135_one_seen_only`（样本内） | **FLAG**（键重叠 100%） |
| `r148_clean`（R148 的设计） | **PASS** |

## 预测（写死）

- **H364（检查能全部识别）**：五个用例全部符合期望。
- **H365（有遗漏）**：至少一个用例判断错误。

## 边界

- 检查是**必要条件**，不是充分条件：通过检查不代表实验设计正确。
- 只处理本项目的常见形态（整数码、键集合、预测数组）。
- 回顾性；不涉及机制、临床、药物选择；不做元学习/RSI。
