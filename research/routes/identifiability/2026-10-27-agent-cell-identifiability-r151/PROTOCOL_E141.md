# PROTOCOL E141（预注册）：跑通 `NEAR_DEGENERATE` 分支 + 阈值敏感性

2026-10-27，R151。**在任何计算前冻结。** 只读 `gdsc_combinations`。

## 为什么

R150 加了近似退化档，但**两个构造用例都走支配分支**，`NEAR_DEGENERATE`（std 比值）**从未被执行**。

**而且阈值（0.05 / 0.95 / 0.80）是拍的，误报率未知**——一个会误报的检查会被忽略。

## 构造

**20 个键级划分**（种子 **20261054**），每个划分跑九组阈值 × 四类场景：

| 阈值网格 | 值 |
|---|---|
| `ratio_threshold` | 0.02 / 0.05 / 0.10 |
| `dominant_threshold` | 0.90 / 0.95 / 0.99 |

| 场景 | 构造 |
|---|---|
| **`clean`** | R148 式干净设计（用于**误报率**） |
| **`scale_shrunk`** | 把 `ap_code` 在评估集**乘以 0.01**（保持形状、缩小尺度）→ 应触发 **`NEAR_DEGENERATE`** |
| `zeroed` | 评估集把 `ap_code` 99% 置零（R150 已验） |
| `dominated` | 评估集 96% 取同一值、训练集 60%（R150 已验） |

## 预测（写死）

- **H368（存在可用阈值对）**：存在一组阈值使 **误报率 ≤ 5%** 且 **`NEAR_DEGENERATE` 在 `scale_shrunk` 上检出率 ≥ 90%**，同时另两类退化仍被检出。
- **H369（不存在）**：所有九组都做不到。

**若 H368 成立 → 把该阈值对定为默认并记录。**
**若 H369 成立 → 近似档的阈值必须按用途分别设定，不能给一个默认。**

## 判据

- 每格报误报率、三类的检出率。
- **主结论只看 `scale_shrunk` 与 `clean` 两列**（前者是新分支是否可用，后者是否误报）。

## 边界

- 构造是人工注入；真实数据未出现这种形态。
- 只有 20 个划分，误报率的分辨率约 5 个百分点。
- 回顾性；不涉及机制、临床、药物选择；不做元学习/RSI。
