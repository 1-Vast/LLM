## 0. 结论摘要（只陈述审计事实，不做科学解释性外推）

1. **派生对比 Q 几乎完全由代数闭包决定**：92,039 个 Q 条目只是 **4,686 个聚合键**（cell × condition 的两级均值）的 ±1 线性组合；系数矩阵秩 = **3,005**，即 92,039 条目只含 **3,005 个独立数值**，**冗余 89,034 条（96.74%）**。可重构的显式恒等式：同行细胞传递 `Q(a,b)=Q(a,c)+Q(c,b)` 覆盖 **93.16%**，同列条件传递 `Q(p,r)=Q(p,q)+Q(q,r)` 覆盖 **50.74%**，二者并集 **96.74%**（与线性代数秩上界一致）；2,000 条抽样恒等式核验 `max|err|=0`。
2. **H197c 随机条目留出设计在代数上不可识别**：R197v2 的 H197c（随机留出 20% Q 条目，5 折，seed 20261106）**5/5 折的 18,408/18,407 个留出条目 100% 可由训练条目精确重建**（`‖A_test V_null‖=0`）；用**无特征、无调参的精确闭包重建**（最小范数解）即可把留出 Q 值复现到 `max|err|=0`、`100% ≤1e-9`。因此 H197c 上的 0.7206（B2）**不能作为"学到了闭包外结构"的证据**——该设计的天花板 1.0 由代数闭包免费给出；0.72 vs 1.0 的差距是模型/计算差距，不是结构证据。**这不否定 0.7206 的描述性，也不证明结构不存在**（C179 不变）。
3. **共享原始响应**：条目对层面重叠小（共享 ≥1 键的条目对仅 **0.48%**；共享 ≥1 板/run 的条目对 **1.85%**，上界 3.16%），但**全局复用极高**：每个键被 **中位 64** 个 Q 条目使用（最大 239），每块板（BARCODE run）进入 **中位 420** 个 Q 条目（最大 857）；每条目原始支撑 4 行（中位；最大 32），中位 4 块板（64.13% 条目 4 块不同板）。→ 闭包不是靠"条目成对共享"实现，而是靠**全局线性代数耦合**。
4. **身份/批次/端点来源**：229/229 条件对**同 anchor、同 anchor 浓度、同 library 浓度**，只有 2 细胞 × 2 library 变化；**单一 screen、单一端点**（SYNERGY_DELTA_EMAX，100% 条目）；Original 与 Validation 的 barcode 集合不相交（A0）。A0 冻结方差份额（只读引用）：加性条件 **1.43%**、加性 cell-pair **3.94%**、残差 **94.63%**（交互 48.50% + 噪声 46.13%）——这是 **Q 方差份额，不是可迁移规律总量**。
5. **剩余"独立信息"**：**3,005 个独立数值**（=秩），对应 3,005 个非重建条目，覆盖 **96/96 细胞、156/156 用到的条件、68/71 个 anchor→library 方向**；行内可重建比例中位 0.93、列内中位 0.38；不存在完全可重建的行/列（说明独立信息在每行每列都有分布）。用到的键只涉及 **18 anchor / 26 library / 156 条件**（匹配宇宙为 31/38/291）——Q 的条件对构造进一步收窄了可用条件。
6. **可迁移目标资格**：本地**只有 Jaaks Validation fitted screen** 是独立操作性目标，判 **`qualified_with_conditions`**（独立 screen/板/run、同实验室平台与端点定义、screen 与 batch 混淆、仅 9,154 匹配键、Validation 更小需预注册功效）；其余候选 **`not_qualified`**：DrugComb v1.4/v1.5（A3/C173 `data_insufficient`）、PRISM/BeatAML2 单药（`no_operational_target`）、GCP2020 蛋白组（`no_operational_target`/`data_insufficient`）、NCI-ALMANAC/O'Neil/VIS2024/Nyman2020/Hill2017/JUMP-CP/BATCHIE/GDSC2（本地空目录 `data_unavailable`）、同资源换端点/换聚合/barcode 分半（`same_resource_reencoding`——按协议明令不算独立目标）。**T4（不同测量/培养）本地不可得**。
7. **设计建议（只写设计，未执行）**：主对比 = 去闭包结构模型对独立目标的增量 vs 强基线（均值/加性/充分调参树/矩阵补全/GP/精确闭包重建/直接响应预测），等信息等预算；主目标优先级 **T3（独立 screen 新键）→ T2（独立 screen 同键）→ T1（同 screen 新键）**；δ_min=0.05、MDE80=2.802×cluster-SD、MDE80≤δ_min 为设计门；零模型（目标内置换/映射置换/随机特征/同资源换端点负对照）；失败类别 `data_unavailable / design_invalid / evaluation_cannot_distinguish / no_increment`；停止条件写死（见 §5）。**先独立挑战，后执行。**

## 5. 预注册评价设计草案（只写设计；完整定义见 PROTOCOL §6）

**目标分层（写死）**：T0 = H197c 派生随机条目（闭包主导，**仅审计对象**）；T1 = 同 screen 未测键（闭包不可能；结构插值，内部前驱）；T2 = 独立 screen 同键重测（跨 screen 复验）；T3 = 独立 screen 新键（跨 screen + 冷键；Validation-only 495 键，规划 MDE≈0.126 提示需聚类/功效设计）；T4 = 不同测量/培养（**本地 `data_unavailable`**）。
**主对比**：去闭包结构模型（只用源侧信息预测目标的**非闭包成分**）vs 强基线：均值、加性、充分调参树（DrEval 标准）、矩阵补全/低秩、GP/核、**精确闭包重建**（在新键目标上贡献按定义为 0，必须显式报告）、直接响应预测。**等信息/等预算/等成本**（同特征块、同调参预算、同计算上限），计费对照入表。
**切分与可识别性门**：按细胞/伙伴/条件/键分组留出；留出目标必须**不可被训练条目闭包精确重建**（重建率 ≤5% 才可作为主目标；否则 `design_invalid` 或换结构切分）——本报告 §2.2 的 100% 结果就是该门在 H197c 上失败的证据。
**指标/功效**：主指标 = 目标侧键级 Spearman；副指标 R²、top-q（描述性）；δ_min=0.05（operational：ρ=0.05 ⇔ τ≈0.0318 ⇔ ~1.59 pp 排序优势，近似换算，非决策效用）；**MDE80 = 2.802 × SD_cluster_bootstrap(Δ)（按目标侧独立单元聚类）**；设计门 **MDE80 ≤ δ_min**，否则 `design_invalid`。
**零模型**：目标矩阵内置换（保 mask）；源-目标映射随机置换；同维随机特征；同资源换端点负对照（量化泄漏，不作目标）。
**失败类别/停止条件**：`data_unavailable`（无合格独立目标→停，写所需测量规格）；`design_invalid`（MDE>δ_min、闭包重建率>5%、覆盖/不可辨识→停）；`evaluation_cannot_distinguish`；`no_increment`（主模型≤最强基线→停）；若增益只出现在闭包可重建条目→停"迁移"主张、保留评价成果。**不因结果换端点/切分/δ/预算。**
