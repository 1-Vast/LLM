# AMENDMENT_ON1-001 —— 关于 ON1 v1 数据门 DG3（技术重复完整性）的预注册修订提案（2026-10-27，**v1 资格运行之后、任何 v1.1 运行之前**）

> 性质：**修订提案**（不是对 v1 的改判）。v1 `PROTOCOL_ON1.md` FROZEN 文本与 `on1.py`/`on1.json` v1 结果**保持原样**；v1 判定仍为 `data_unavailable / replicates_missing`（DG3 字面门失败）。本文件预注册 v1.1 对 DG3 的修订，供 Lead/后续独立挑战审阅；**本任务不运行 v1.1、不运行效果/更新器比较**。

## 1. 触发事实（on1.json v1 实测，metadata/空值计数 only）

- v1 冻结 DG3 的字面门槛："viability1–4 四列存在且**非空计数 = 行数**"。
- 实测（368,832 行）：`viability1` 非空 **368,832/368,832**；`viability2` **368,754**（缺 78）；`viability3` **368,634**（缺 198）；`viability4` **363,090**（缺 5,742）。
- 因此 **DG3 字面门 FAIL** → v1 verdict `data_unavailable`（failure category `replicates_missing`）。
- 但同时：**行级 4 重复齐全率 = 363,090/368,832 = 98.44%**；每行可用技术重复数分布 `{1: 78, 2: 120, 3: 5,544, 4: 363,090}`；**完整成员上下文（46,104 个）中，≥95% 的 16 个网格行都有 ≥2 个非空技术重复的比例 = 99.66%**（最差上下文 = 93.75%）。即：缺失是**少量行级技术重复空白**，不改变"每单元有可用的技术重复"这一设计前提。
- 其余数据门/设计门全部 PASS（`on1.json → gates`）：batch1-target 单元 Δ **363,304**（≥5,000）、贡献目标细胞 **30/30**、上下文 **2,149**（≥200）、跨 ≥3 目标细胞上下文 **12,430**（≥10）、完整成员上下文 **100%**、伙伴-角色剂量集 100% 唯一匹配、非重叠目标细胞 30、Jaaks 重叠 0/30；设计门：5 折各 6 细胞、每折单元 71,004–74,580、每折上下文 427–432、保守 MDE80（σ_e=0.109, n_eff=6）**0.02204 ≤ δ_min=0.10**。

## 2. 修订（v1.1 的 DG3，预注册）

**DG3-v1.1（技术重复可用性）**，全部只做存在性/空值计数（不读响应值做效应）：
1. `viability1–4` 四列存在；
2. **≥95% 的原始行**（行数 = 368,832）四列均非空（v1 实测 98.44% → 满足）；
3. **≥95% 的完整成员上下文**（batch1 target 口径，共 46,104 个）满足：其 16 个网格行中 **≥95% 的行**有 **≥2 个非空技术重复**（v1 实测 99.66%，最差 93.75% → 满足）。

**执行期缺失值规则（与 DG3-v1.1 同时冻结，v1.1 若被批准后由效果协议继承）**：
- 每个网格行（partner dose × member dose）的响应 = 该行**可用技术重复**（≥1）的均值；若某行 0 个可用重复 → 该行按缺失处理，**不得插补**；
- 每个成员曲线均值 = 其**≥2 个可用重复的行**上的均值（要求每成员至少 **12/16** 行可用，否则该 `(c,member,partner,role)` 视为不可用、其相关 Δ 单元排除并计数）；
- 每个 Δ 单元的"已用 well 数"分布随单元一起报告；不得按响应值挑重复/挑行。

## 3. 为什么这是可审计的预注册修订、不是事后放宽效果

- 触发的是**数据完整性事实**（技术重复空白计数），发生在任何效果/模型/更新器比较之前；修订只涉及 **"重复可用性"数据门**，不涉及效应量、端点、切分、主判定、δ_min。
- 修订方向是**把过严的字面等式改为与设计前提一致的比例阈值**（≥95% 行齐全；每上下文 ≥95% 行有 ≥2 重复），阈值沿用本协议 DG2 的 95% 惯例，不是为让某个结果通过而设。
- **v1 verdict 不因此改变**：`on1.json` v1 记录 `data_unavailable / replicates_missing`；若 Lead 批准本修订，需要以 v1.1 协议**重新预注册 + 重跑资格脚本**（`on1_v1_1`），并保留 v1 记录。
- 即使 v1.1 通过，仍然：仅 O'Neil 内部开发性细胞留出；**不得**称独立确认/迁移/决策收益/机制；不比较更新器（须另立效果协议 + 独立挑战）；不得与 Jaaks ΔEMAX 拼端点。

## 4. 影响面

- 不改变：DG1/DG2/DG4/DG5、DSG1–DSG4、δ_min_provisional、MDE 公式、5 折设计、端点/聚合规则、批次处理（batch1 主分析）、目标细胞集（30 个非重叠）。
- 改变（仅 v1.1 提案）：DG3 由"每列非空=行数"改为"行级 4 重复齐全率 ≥95% 且完整成员上下文 ≥95% 行有 ≥2 重复"，并新增执行期缺失值规则。
- v1 产物不动：`PROTOCOL_ON1.md`（FROZEN v1）、`on1.py`、`on1.json`、报告/记录保持 v1 判定与数字。
