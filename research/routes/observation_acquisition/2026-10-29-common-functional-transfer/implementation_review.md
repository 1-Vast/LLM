# C4 v2 实现审计

2026-10-29。审阅 `e_c4_budget.py` 与更新后的 `protocol_c4_v2.md`。这是实现契约核对，不是重复科学同意，不是独立科学结果复核。原 `independent_challenge_v2.md` 保留。requested Sol/high，effective unknown。

## 结论

**当前实现不宜直接消费真实功能值。发现1项核心信息边界偏差、1项必补日志缺口，以及1项诊断命名/分组偏差。** 没有发现主端点、SVD、后验公式、13次动作、三个主对照或缺失差界的算术错误。全部科学结论仍未经真实数据运行验证。

## 必须修复

### I1：测试全矩阵在动作前已被数值化，不符合按角色/选择消费的冻结边界

当前主函数顺序为：

```python
test = read_values(meta['source'], test_cells, menu)
test_finite, test_event = labels(test, low, high)
# 之后才逐cell生成actions
standardized = (mu-test[i])/sd
```

`read_values` 会把全部测试cell×64菜单条件的已选记录 LN_IC50 转为 float。`labels` 会在任何策略动作前构造全部真值和缺失mask。`standardized` 也对未选择目标执行数值运算。这不同于协议“数值只按角色和所选条件消费；同进程oracle”的受控访问：目前没有oracle角色或查询边界，只是同一个控制循环持有全部测试真值。

**没有证据表明当前策略公式把未选目标反馈用于选药。** 逐行数据流看，rank/ridge/kNN选后5条只使用8探针的有限值，静态对照也不看目标。因此这不是已发现的分数泄漏，而是冻结信息契约没有被实际实现、且日志无法证明访问范围。

最小修复：训练冻结以后，建立同进程oracle；策略只能按cell/condition查询已尝试条件，查询时才转换该条值，缺失也计一次；记录策略、cell、condition、尝试序号、有限/未知。最后5条须先一次性固定再查询，不能逐次反馈后改变5条。每个策略的13个动作全部固定后，才让评分角色转换剩余标签并生成真值矩阵。oracle可保留原字符串，协议已容许读取原CSV字符串和字节；不要求安全进程隔离，也不要求额外服务。不要为了通过审计而把协议改成允许提前消费所有数值。

### I2：缺少用于实际选择的反馈前后概率及顺序

`predictions` 当前只保存rank8的反馈前后连续s均值；实际选药依据是窗内事件概率，其还依赖反馈后的方差。`query_trace.jsonl` 保存最终各策略动作与有限探针数量，没有保存反馈前/后候选概率及对应排序，不能直接检查协议要求的“保留相同8条反馈前后预测/顺序”。连续均值排序也不等于窗口事件概率排序。

最小修复：对rank8保留反馈前后64条件的事件概率、在相同未尝试候选集合上的稳定排序，以及实际后5条；与I1查询记录关联。无需增加新的探索图表、算法或统计门。日志改变本身仍不可当成收益。

### I3：窗外和边界诊断目前被合并且名不符实

`finite_below_minimum_test_entries` 实际统计 `x <= log L+1e-8`，含边界和边界内极近值，并非严格低于最低浓度。上界字段同理。协议要求报告“窗外/边界值计数”，当前两项合计不能区分窗外与边界。主事件判断本身没有错，但输出名易把未认证的边界值说成窗外外推。

最小修复：按既定1e-8约定分别给出低于窗、下边界带、窗内、上边界带、高于窗的互斥计数，或至少将现字段改为“低端排除/高端排除”并另报边界带。不得据结果调整事件边界或阈值。

## 已核对且符合协议的部分

- **行选择**：先按role cell、DATASET、冻结drugID和精确raw窗过滤，再按整数NLME_RESULT_ID/source_row_index选择；选定后才转换其LN_IC50。所选较早记录缺失时不会回退到后面有限记录。不可解析resultID自然抛错停止。
- **训练菜单**：覆盖和SD只由训练细胞计算，ddof0正确，少于64会资格停止。实现使用eligible[:64]，本次仅从metadata验证其192条件已按SHA256(C4-drug|id)排序，因此等价于冻结规则。没有依测试缺失率选择菜单。
- **响应模型**：标准化方向s=(mu−x)/sd、缺失填0、行均值偏移、残差SVD、Z=U*S、A=[1,L]、经验先验均值/样本协方差+1e-6I、有限训练位置噪声MSE下限0.0025均匹配。协方差更新和直接解公式匹配。
- **8+5策略**：探针按全64条件方差减少总和选8，排除已选且稳定打破并列；假想值影响均值但不影响用于设计的P，因此给假想0不改变探针规则。后5条一次选择，不会因其后收到反馈再选新动作。所有策略检查13个不同条件，缺失不补测。
- **静态/盲对照**：global分母是有限训练标签；tissue的5个全局伪样本及无组织回退正确；probe_blind固定相同8条，剩余按tissue选5；random hash格式正确。
- **简单对手**：rank1使用rank8面板；ridge目标有限训练行、lambda1、截距不罚和缺失输入填0均匹配；kNN使用实际已见探针子集、训练缺失填0、稳定前5邻居和1/(距离+0.1)权重，目标无邻居标签时回退global，符合协议。
- **端点/概率**：strict窗内、自然对数µM、x<=0及非有限未知正确。CDF区间方向正确，空区间返回0。
- **缺失差界**：集合共有项先抵消；仅第一策略未知增加上界，仅第二策略未知减下界。事件数组中缺失为False与此界公式配套。
- **统计与主门**：同一份2000×243有放回SIDM索引用于全部比较；seed20261029；np.quantile当前默认linear，分位数.025/.975符合协议。主门使用差下界均值≥0.5和CI下端>0，且恰为global/tissue/probe_blind三者全部成功。rank1/ridge/kNN并未被错误纳入主门。
- **冻结顺序**：实现/协议hash、training_model、menu/probes/train/test identities在测试读取前写入；收到回放后不会自动重跑（receipt存在即停止）。但只有I1修复后，访问日志才能支持更细的按条件消费声明。
