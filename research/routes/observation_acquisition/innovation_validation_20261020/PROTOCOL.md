# Protocol (frozen before any evaluation stream was scored)

Question: does experimental feedback create reusable scientific procedures that improve later drug-combination decisions beyond strong conventional methods under matched information and resources?

## Mechanism (implemented: `iv_core.py`, `iv_gates.py`, `iv_search.py`)
* **Competing numerical response programs** for the residual `e = A − (A_ref + z1)` of a new background: `N` null, `U` unexplained (inflated variance; weight > 0.5 = *unresolved mismatch*), `C` continuous latent factors (basis Procrustes-aligned to a stored reference), and one **gate program** = up to 4 learned binary hidden states ("gates", optionally with conjunction terms) with scope classes, pair-level effects, diagnostic probe order, state posterior and observable applicability. Gate identity = scope + signs + canonical orientation, never a list position. An unprobed gate keeps its prior marginal (missing ≠ zero).
* **Before each probe** the system records the competing programs and weights, their different predictions for the candidate probe, the nominations that could change, the acquisition score and the best alternatives. **After each measurement** program support and predictions update before the next probe. A probe whose decision value is below 0.0003 is not taken; the budget goes to direct measurement of the best candidate or stops.
* **Acquisition** = knowledge-gradient preposterior approximation of downstream shortlist value (128 sampled worlds × ≤40 screened candidate probes; a directly measured candidate keeps its recorded value). Approximations: diagonal predictive draws; cont posterior moved only through the Kalman gain. Conventional rules on the same library: random, variance, BALD-like mutual information, A-optimal (latent), exploit (direct).
* **Inherited skills** = gates (scope, effect profile, probe plan, state transformation) kept in a library; they can be invoked, adapted inside their declared scope (profile refit with weight 0.5) or composed with fresh gates found on the residual. Every task row records the programs actually used; the library snapshot records ancestry and evidence cells.
* **Lifecycle** (identical code for every arm): ≤12 candidates per generation (restart arm: 12 × generation, from an empty library, same raw data); candidates are fitted on cells released **before** the newest batch and validated on the newest batch (never used in any fit) by offline campaign replay against the incumbent. `demonstrated` needs gain ≥ 0.004, wins > losses and wins ≥ 2; ties and zero gain never promote; `noninferior` programs go to a bounded archive (≤3) that is not capability; refit failure on the full release rolls back to the base library; checkpoints report the program actually deployed afterwards. Deployed capacity ≤ 4 gates.
* Fixed external evaluator: realized published-outcome utility of the 5 nominated pairs (`svc_world.realized_utility`). Simulator predictions are never truth.

## Contracts and endpoint
* **E** end-to-end (primary): 4 probes per task from the whole pool of 378 pairs, probed pairs keep their recorded value in the shortlist. **T** transfer: probe half and target half of the pairs are disjoint. **FO** fixed observations: every method receives the same seeded probe list (T mask) and the same released history.
* **Primary endpoint:** absolute shortlist utility (K = 5, budget 4, common pool, same cells) averaged over the 12 tasks of batches 2–4 per stream. Margin δ = 0.01 (engineering threshold with rationale in `CONFIG.json`; not a fraction of oracle headroom). Secondary: budget–utility curves (2, 4, 8 probes), budget to a fixed target, anchor checkpoints, search time, retained capabilities.
* **Shared information:** H0 (8 cells) released; each batch of 4 task cells is released in full to every arm after its campaigns (same source-data release). Anchor backgrounds (A_old, A_new; 4 each) are never released and are evaluated at every checkpoint. Query accounting: released wells = released cells × 378 pairs (identical for all arms); discovery and validation use released labels only (0 new wells, counted as candidate evaluations and validation replays); deployment = ≤ 4 probe measurements per task.

## Arms
Library arms (E, T, FO): `inh_kg` (library evolution on, policy fixed), `inh_pol` (evolution on + diagnostic-policy adaptation by validation), `rst_kg` (restart control), `fix_kg` (structure fixed after the first search, parameters refit), `fix_pol` (structure fixed + policy adaptation). 2×2: evolution × policy adaptation = {`fix_kg`, `fix_pol`, `inh_kg`, `inh_pol`}.
Same library, other acquisition: `inh_bald`, `inh_var`, `inh_rand`, `inh_exploit`. Ablations: `inh_del_all` (delete the deployed procedure), `inh_del_old` (delete older-generation gates), `broadcap_transplant` (transplant the deployed gate program into the broad-capacity baseline). Conventional pipelines: `prior`, `direct`, `lat_aopt`, `lat_var` (latent factors), `broadcap_bald` (fixed broad capacity: ranks 1–6 + U), `gbm_var/ucb/exploit` (nonlinear contextual model meta-trained on released backgrounds with simulated probe sets). Witness-to-target control: *decoupled* alias and compose streams (class gate states drawn independently in task and anchor cells; anchors, nuisance and noise unchanged).

## Streams and statistics
Four generators (`null` with shared-anchor nuisance, `lowrank`, `alias`, `compose` with late-appearing gates and a conjunction), 24 independent streams each (seeds 1–24) plus 24 decoupled streams each for alias and compose; dev streams 9001–9004 were used for timing and to pick the comparators. The stream is the unit; paired stream-level percentile bootstrap (20 000 resamples). Primary hypotheses, all in contract E on the pooled mechanism conditions (alias + compose), each at a 98.33 % interval (Bonferroni over three): **H1** `inh_kg − lat_aopt`; **H2** `inh_kg − rst_kg`; **H3** `inh_pol − inh_kg` (best single adaptation on dev). Verdict: SUPPORT if the lower bound ≥ δ, NO_SUPPORT if the upper bound < δ, else INCONCLUSIVE. H2 is reported SUPPORT only if the deletion ablation and the decoupled control are also compatible with an inheritance-specific effect. H5 = marginal value of the deployed library on never-released anchors (`inh_kg − inh_del_all`): growth on A_new from checkpoint 1 to 4 ≥ δ with retention on A_old not falling by more than δ and bounded capacity. Failures are reported per task family; no endpoint, world or comparator was changed after scoring.
Stop rules (no effectiveness claim): ordinary methods match or exceed the system; inheritance contributes nothing; gains appear only where the generator creates the skill; deletion does not remove the gain.

## Measured data
Development replay only, on the already-released H0/D1/D2/D3 cells (18 of 39) through a restricted export; A/T backgrounds, G/F outcomes, unacquired C outcomes and sealed ALMANAC/PRISM assets are not touched. One external source is qualified by observation structure only (`EXTERNAL_SOURCE_QUALIFICATION.json`); nothing is imputed; if it does not qualify H4 is NOT_ESTABLISHED.

## Ceilings
≤ 4 generations, ≤ 12 candidates per generation, ≤ 180 min comparative wall time, optional API arm ≤ 6 HTTP attempts and ≤ 30 000 tokens (a failure must not block the deterministic experiment), one documented repair cycle with pre-repair outputs preserved, write-once stage outputs (`RUN/LEDGER.json`).
