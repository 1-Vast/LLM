# GDSC 同板表型实验：背景信号存在，播种密度增量不成立

本轮真正执行了公开已测数据分析和受控揭示的离线回放，没有新增物理实验。
**在冻结的三个药物动作和后来日期、未见供体的确认集上，加入播种密度相对
背景模型的收益为 −0.52 个 ATP 抑制百分点，97.5% 区间 [−1.69, +0.65]。**
在本次区间的抽样假设下，这个已测试策略的上界低于预先规定的全部
2/5/10/20 个百分点敏感性阈值。停止为该密度模型增加复杂度或测量投入。
这不是所有低成本状态输入的无效性证明。

组织、培养方式和培养基的简单背景模型相对固定动作有 +3.32 个百分点的
辅助正向信号，但区间仍跨越 2 和 5 个百分点；净成本收益、前瞻分子状态价值、
STATE 优势和机制判别仍然未知。培养基等背景注释来自后来的公开版本，
并非对 2015 年每个实验实际决策时可用信息的认证。

## 3. 真正运行的实验

每个输入臂都在开发集进行 5 折供体分组交叉验证：Ridge α=1/10/100，以及
64-tree Random Forest（depth=3/6、leaf≥10）。按**动作差值 MSE**选择，不按
确认收益选择。两个臂均选中 Ridge α=10；森林未获得保留依据。
固定动作由开发集等供体平均选择，为 Afatinib 2 μM。

预测表征只有任务绑定的三个 ATP 表型响应及其差值，保留了此线性菜单决策需要的
信息，没有重建 RNA。输入作用于各药物响应的回归系数，动作由精确药物、浓度和
时间绑定。这是普通条件响应预测器作为最小 world core 的基线，**不把它包装成
新型世界模型贡献**。新检验的唯一输入假设是：登记播种密度在 C 之外能预测
可泛化的相对药物收益；它在本次策略检验中未得到支持。

确认集真实效用（单位均为标准化 ATP 抑制百分点）：

| 策略 | 实测平均效用 | Afatinib / PLX / PD 选择次数 | 动作差值 RMSE | 所选动作 RMSE |
|---|---:|---:|---:|---:|
| 开发固定 Afatinib | 25.54 | 222 / 0 / 0 | 不适用 | 不适用 |
| 背景 C | 28.87 | 144 / 9 / 69 | 24.13 | 22.17 |
| C + 播种密度 | 28.35 | 144 / 9 / 69 | 24.15 | 22.79 |
| C + 同背景内置换密度 | 27.98 | 144 / 9 / 69 | 24.12 | 22.19 |

相同动作总数不表示逐板动作相同。置换保持组织、培养方式、培养基分层；
无法置换的单例保持原状。这是破坏密度与具体单位对应关系的输入负对照，
没有认证生物学可交换性，因此**不报告置换检验 p 值**。

| 比较 | 平均增量 | 区间 | 具体动作切换 | 判断 |
|---|---:|---:|---:|---|
| **C+密度 − C（主要）** | **−0.52** | **97.5% [−1.69, +0.65]** | **12/222** | 测试策略的收益上界低于 2/5/10/20；停止这一输入增量主张。 |
| **C+密度 − 固定（主要）** | **+2.81** | **97.5% [−0.03, +5.64]** | **78/222** | 对 2/5 未定；未认证有意义收益，更非净收益。 |
| C − 固定（辅助） | +3.32 | 95% [+0.96, +5.69] | 78/222 | 正向背景信号；跨越 2/5，保留简单方案待独立验证。 |
| C+密度 − 置换（辅助） | +0.37 | 95% [−1.02, +1.76] | 20/222 | 未看到值得投入的密度对应关系价值。 |

两个主要比较采用各 97.5% 区间作 Bonferroni 家族处理。区间使用等供体权重的配对
差值，取供体、日期及 two-way cluster 方差三者最大值，t 自由度为较小簇数减一
（确认为 18）。这是有限簇下**近似、依赖抽样及跨簇误差假设**的区间；它不覆盖
固定位置系统偏差、未知发表选择、全部未来培养物或生物学因果误差。
共享对照通过板内动作差和整板/供体/日期结构保留。没有把 well 当独立生物重复。

7/222 次“加入密度”的推荐比 C 的实际读数低超过 2 个百分点；6 次低超过 5 个百分点。
这是有噪声的观察损失计数，不能称为真实机制误判率或校准的错误推荐风险。
此次没有拒答变化，故结果增量来自具体动作选择，不是拒答计分。

### A：这个菜单是否只有一个普遍最优动作？

确认集 Afatinib 相对 PLX 平均 +6.21，98.33% 区间 [1.90, 10.52]；相对 PD
平均 +5.85，[0.58, 11.12]。这是**平均**优势，不是普遍占优。
背景策略在不同单位切换动作且获得上表正向信号，说明不能用边际均值否定交互。

开发集中还有 43 个细胞系的不同日期重复：用**第一次**实测结果选择动作，在
**最后一次**独立读数上评分，相对开发固定动作增量 +10.90，描述性 95% 区间
[3.90, 17.89]；三对动作差的前后相关约 0.76、0.89、0.57。
这不是对同一行取最大值的乐观 oracle。37/43 使用相同 CELL_ID 扩增，因此只证明
部分 assay 重复性和可利用的历史响应信息，不认证新亲本泛化；43 个重复对象也
是选择性子集。结果不得作为全部人群的收益上界或免费前状态。

### B、C：输入和模型的研究分支

密度未改善动作差值预测或所选动作收益；将“廉价”从实验设置升级为廉价分子状态
没有证据。完整 RNA、少量实测标志物和同 checkpoint 状态遮蔽均**未运行**，因为
本面板没有认证输入，不能补零喂给 STATE。当前结果只给出已测试密度策略的增量界，
不是所有可预测交互的总 headroom 上界。

没有理由新增 JEPA、ensemble、多智能体或更多 STATE seed。保留普通条件预测基线
与严格揭示路径；大型世界模型相对这个强简单参照的增量尚未验证。

## 4. 双核心接线、成本与工程验证

[gdsc_screen.py](gdsc_screen.py) 提供 prepare/develop/confirm 三阶段，保留原生
source row、scan、well、共享对照、精确药物/浓度和 QC。预测器只能使用列白名单。
[gdsc_replay.py](gdsc_replay.py) **复用**现有 `DecisionPath`、`CaseStore`、预算和
prediction/result 绑定：固定任务 → 离线决策可用输入 → 冻结表型预测 → 选择 → 登记计划
和预测 → 原生测量揭示 → 精确条件核对 → 停止。没有另建账本或改变生产默认策略。

四臂共 **888 个离线 case**，预测臂读取 **1,998 个真实训练所得的预测条目**。
原 v1 计划在确认结果分析前登记；全部 888 个真实结果配对成功，重复导入不重复扣预算；
一次揭示后原有预算门阻止第二次执行。**888 是重复使用 222 个历史板的策略回放次数，
不是 888 个独立实验或新增测量**。没有用模型填补观察值，没有通过预测更新机制信念。
独立亲本数未知，生产的要求独立单位认证的正式评分接口保持关闭；研究点误差单独评价。

最后复核发现 v1 回放的输入溯源缺陷：C 臂也登记了未使用的密度，置换臂登记的
仍是原密度，且模型文件内的 C/CS 成员未分别绑定。各 case 的缓存独立，原预测和
选择未被串用，但记录不能准确证明输入身份。修正适配器后，在新的
`20261002_gdsc_replay_v2` 中重新接线；**这是结果已打开后的工程复现，不是新确认**。
从修正后实际登记的输入重新计算 1,998 个预测值，和冻结值最大差 9.71e-17；
888 个动作、来源行及效用全部不变。旧 v1 文件保留，并明确由 v2 接替输入溯源。

输出声明模型适用范围、效用与时间、动作差、已观察的开发误差、未覆盖的不确定性和
未知货币成本。确定性模型不需要 MC 加算；本任务没有经验证的补测后果模型，所以
不虚构额外检测的 VOC。完整“加算/补测/干预/停止”策略仍未验证。

| 4 信号在哪里损失 | 此任务没有 EGR1 零值瓶颈；密度既未改善差值 RMSE，也未改善选择。不能倒推 STATE 的能力。 |
| 5 多 seed 稳定什么 | 新模型确定性，不增加种子；生物抽样与日期依赖进入独立分析。旧 STATE MC 精度问题不变。 |
| 6 双核心怎么协作 | 首次在本轮新真实表型任务上执行完整预测—选择—揭示—停止；密度改变 12 个动作但无增益。没有四路最优调度证明。 |
| 7 什么证据支持什么 | ATP 读数只支持该 assay 表型；靶点注释、模型系数均不成为机制证据。 |
| 8 收益归因 | 背景基线优于密度扩展；较复杂森林没有开发优势。未运行多智能体，未声称架构协同或 STATE 真实收益。 |

**最值得保留**：可复现的同板表型、跨供体及跨日期的简单策略检验，以及能接到现有
事实账本的真实测量回放。**应放弃**：在当前密度输入上叠模型；为旧 EGR1 任务加种子
来替代缺失的可比较表型。

**唯一下一步：对简单 C 策略做独立启动亲本、随机孔位的同菜单复测。**
它直接区分“背景确实预测相对药物响应”与“固定位置/发布选择/培养批次使其看似有效”。
可先做 12 个细胞系、每系 2 次独立冻存启动的先导；按冻结 C 模型三种推荐各选
4 系，选择只用元数据和预测，不能用本轮结局挑选。每个亲本随机分配 3 药×2 技术孔、
4 vehicle、4 blank、2 time-zero sister 孔，即 **24 个亲本块、384 个基础孔位**。
同系两次启动安排在不同日期，每个日期包括全部 12 系；336 个终点孔分布在 4 张
96-well 板，破坏性的 48 个 time-zero sister 孔另用每日期一张板，总计至少 **6 张板**，
早期板另设相应培养基空白孔，实际耗材和失败余量另报价。所有尝试、排除、失败和成本都登记。time-zero 只作
独立 sister 测量，不能称同一物理细胞轨迹。预留基线明场图像或样本即可，不先购买完整 RNA。

这个富集先导只检查孔位、重复性和测量方差，不估计原总体策略收益；后续确认必须
恢复明确目标总体和权重。其继续条件是：关键动作差方向在随机孔位与独立启动下
可重复、结局/QC有效、成本被实际报价和计时认证；若优势只随固定孔位出现则修改
背景策略主张；若新确认的策略收益上界低于所选任务 δ，则停止该菜单的复杂策略。
小先导区间跨零仍是未知，不能凭此宣布不存在收益。

功效不能来自当前 well 数：假设供体层策略差 SD 为 10/20/30pp、真实收益为 10pp，
希望 95% 区间下界超过 5pp、80% power，正态独立单位近似需 **32/126/283 个供体**
（还未加日期相关和失败膨胀）。这些是情景假设，不是已认证生物方差或本轮效应预测；
如果真实收益只有本轮 C 的 3.32pp，增加样本也不能让它成为 >5pp 的收益。
没有实验室接入，本轮**没有执行**这一物理方案。

## 6. 复现

使用 Python≥3.11，安装 numpy、pandas、scipy、scikit-learn、pyreadr、openpyxl；
精确本轮版本见验证回执。pyarrow 仅用于接手阶段元数据检查，正式入口不依赖它。
在仓库根目录运行，替换 `NEW_*` 为不存在的目录，不覆盖任何旧输出：

```bash
export PYTHONPATH=src
export OPENBLAS_NUM_THREADS=1
export OMP_NUM_THREADS=1
python -m research.astra.gdsc_screen prepare \
  --raw research/astra/data/gdsc_screen_v1/gdsc_example.rda \
  --annotations research/astra/data/gdsc_screen_v1/Cell_Lines_Details.xlsx \
  --passports research/astra/data/gdsc_screen_v1/model_list_latest.csv.gz \
  --compounds research/astra/data/gdsc_screen_v1/screened_compounds_rel_8.5.csv \
  --out research/astra/results/NEW_FREEZE
python -m research.astra.gdsc_screen develop --freeze research/astra/results/NEW_FREEZE --out research/astra/results/NEW_DEV
python -m research.astra.gdsc_replay plan --freeze research/astra/results/NEW_FREEZE --development research/astra/results/NEW_DEV --out research/astra/results/NEW_REPLAY --reproduction
python -m research.astra.gdsc_screen confirm --freeze research/astra/results/NEW_FREEZE --development research/astra/results/NEW_DEV --out research/astra/results/NEW_CONFIRM
python -m research.astra.gdsc_replay reveal --plans research/astra/results/NEW_REPLAY --confirmation research/astra/results/NEW_CONFIRM
python -m pytest -q research/astra/test_gdsc_screen.py research/astra/test_decision_path.py tests/test_case_memory_scientific_boundaries.py tests/test_decision_sensitive_acquisition.py
```
