# Dual-core data and task readiness review

The available evidence supports a reproducible dual-core engineering loop and development diagnostics on exposed data. It does not establish a joint terminal-decision benefit from STATE and a research reading world model. Resolve prediction targets, query availability, source linkage and timing contracts first; more model or planner complexity has no supporting evidence yet.

This document and `data_readiness.json` are new review artifacts. The review read registries, processed tables, frozen receipts and source code. It did not train, download, deserialize arbitrary pickle files, alter frozen results or repeat the complete Round2 replay. Numbers come from inspected files or explicitly identified historical receipts. Each numeric statistic in JSON carries a source ID, key and derivation; the final table records the computed file SHA-256.

## Root-cause priority and minimal implementation

1. **Target and eligibility contract.** Keep production STATE condition-response prediction, WorldV2 reading prediction, case-memory outcomes and hidden-result oracle separate. Refuse mismatched targets, feature identities, contexts or histories by name. Close a deterministic recorded-episode loop in which predictions enter selection and measured results update evidence.
2. **Source and availability.** Record source unresolved, missing outcome, QC failed, missing design and future/unpurchased states separately. Incomplete coverage requires partial-identification bounds over reachable legal paths; predictions cannot synthesize outcomes.
3. **Menu and validator.** Use existing paths to decompose changed-action/unchanged-terminal cases into no elimination, redundant evidence and repeated readings. Hidden results must not construct a deployable strategy, and endpoints must not change to obtain a gain.
4. **Selected-action risk.** Report wrong-among-decided, coverage, correctness and cost together. Abstention caused by forecast unavailability does not establish general policy superiority.
5. **STATE / WorldV2 prerequisites.** STATE uses registered contexts, feature/control identity and explicit design only. WorldV2 needs its original fitted artifact or a complete frozen bank; do not refit to complete a comparison. Without valid pre-action measured state, retain the unidentified result.

The minimal proposed experiments are contract_vertical_slice and readiness_and_source_guard in JSON. Success means correct boundaries, legal actions, evidence updates and matching hashes. cached_path_bottleneck can follow; do not choose combinations using test results. The historical premise census still marks the biological joint task NOT_READY; independently labeled premise and forecastable-readout joint support is recorded under `premise_census` / `decisions`.

## Recommended data-validation step

A future engineering entry point can read JSON, compute source hashes, rescan public/hidden joins, forbidden fields, unit-fold membership and menu sets, recount CSV/JSON statistics using their derivations, and reject modifications to frozen source discrepancies. New execution should use a new output directory. The seven recorded checks distinguish actual scans in this review from inherited receipts.
Proposed contract tests should plant hidden-field leaks, cross-fold units, missing action results, future/unpurchased prompts, backend target mismatches and predictions promoted to measurements, requiring stable named refusals. This is a recommendation for subsequent work, not a claim that a new benchmark-rescanning validator was implemented. Current root verification covers frozen-file SHA-256 and production tests.
