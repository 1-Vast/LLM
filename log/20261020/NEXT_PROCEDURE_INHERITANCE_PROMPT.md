Your objective is to determine whether a reusable, observation-conditioned
experimental procedure creates practical value beyond ordinary model refitting
and planning. Do not optimize for a positive verdict. A reproducible negative
decision that closes an unhelpful mechanism is a complete outcome.

The repair audit found that the old KG computation was inconsistent, deployment
could silently refit away a program, gate identity was lossy, and archive counts
were inflated. It also found that branching diagnostic plans and archive reuse
were not implemented. The old H2 did not match resource budgets, the decoupled
control did not isolate a witness dependency, and real utility remains untested.
Do not call these missing mechanisms validated self-improvement or open-ended
evolution. The repaired eight-stream run is development evidence only.

1. Define one falsifiable research unit before building more infrastructure.

Use a fixed response-model family shared by every arm. Define a small executable
procedure containing an applicability condition, a first measurement, an
observation-dependent second measurement, a posterior/state update, a downstream
drug-pair shortlist, and explicit unknown/stop exits. The procedure must actually
change which measurement is executed after different observations. Distinguish
this from storing factor loadings, a textual explanation, or an unused probe list.

The primary question is: on later backgrounds, can a procedure learned from
earlier feedback achieve the same useful shortlist quality with fewer measured
assay units or less total planning computation, while retaining old-task quality?
Choose ONE primary resource estimand and define it before outcomes are examined.
The other resource remains reported, not hidden in preprocessing or library
construction. Count all discovery, fitting, validation, adaptation and invocation
costs. Specify whether costs are per deployment or amortized across how many uses.

Use the existing measured-data inventory to check whether a defensible drug
discovery action/readout/downstream endpoint mapping exists. Reused O'Neil data
remain exposed development. Do not open old G/F, unacquired C, consumed A/T, or
sealed ALMANAC/PRISM data as new confirmation. Do not invent assay costs, lineage,
mechanism labels, paired endpoints or wet-lab sample sizes. If a measured mapping
does not exist, label the work synthetic methodology development and explicitly
leave drug-discovery effectiveness untested; do not initiate dataset procurement.

2. Build the smallest mechanism test and fair comparators.

First demonstrate both branches and the unknown exit on analytical/synthetic
fixtures. These establish implementation only. Keep the response model, data
release schedule, legal actions, query budget and evaluation endpoint identical.
Use a 2x2 design: response-factor inheritance OFF/ON crossed with executable-plan
inheritance OFF/ON. Include a conventional fresh planner using corrected KG or
two-step lookahead at a comparable computation budget, and an amortized policy
distillation baseline. Count offline planning/distillation costs as well.

Do not cap the conventional response model to manufacture representational
inferiority. If a plan merely caches what cheap fresh planning does, report the
actual break-even reuse count and compare against ordinary caching/distillation.
Delete or transplant the actual learned plan to test its contribution separately
from factor parameters. Make artifact identity cover executable content and
history; every invocation must use and serialize the same validated fit.

If a witness control is needed, predefine disjoint diagnostic and target sets,
retain stage-specific activation marginals and nuisance/noise, and break only the
claimed dependency. Any target conjunction must use the target-side independent
state. List surviving alternative information paths. Do not reuse the old
per-class Bernoulli(0.5) control as causal evidence.

3. Freeze one bounded development experiment before running it.

Use at most 8 new synthetic development streams, 4 generations, 12 candidate
evaluations per arm per generation, one numerical thread, and 30 elapsed minutes.
Record actual process CPU and elapsed time; a shared candidate cap is not equal
total computation. Fix seeds, tasks, all arms, primary contrast, practical margin
rationale, resource accounting and stopping rules in advance. These small runs
are not powered biological confirmation; do not produce a SUPPORT label merely
because their mean is positive. No repeated seed replacement, threshold lowering,
post-result generator redesign, or selective deletion of failed worlds.

Optional language-model proposals are unnecessary for this first mechanism
test. If an API is used, keep it as a separately labelled proposer control with
explicitly bounded calls/tokens and identical acceptance rules. Do not let it
change evaluators, frozen endpoints, costs, eligibility or hidden-state access.

4. Decide before expanding the project.

Report plan execution correctness, later-task utility, total costs, retention,
ablation/transplant results and all failed cases. Separate evidence for useful
procedure inheritance from ordinary model learning and search acceleration.

test supports at most bounded procedure reuse; open-ended evolution remains a
longer-term hypothesis requiring expanding tasks, actual archive reuse, and
sustained improvement beyond a fixed finite search family.
