# MAESTRO: qualify a measured self-repair research unit before building another agent

Workspace: `D:\MAESTRO`.

Read `research/procedure_inheritance_20261020_audit1/REPORT.md` first, followed
by its corrected statistics and behavior audit. Preserve every closed study,
including the original procedure-inheritance package and its negative decision.
This task is a research qualification exercise, not permission to launch another
large synthetic evaluation or tune the closed task until a positive result appears.

The previous experiment tested compiling an existing planner into a small
observation-conditioned plan. Ordinary lookahead and distillation largely
explained its utility. The designated regime-5 novelty challenge appeared only
in the final batch, so its detection, knowledge revision and later benefit were
not tested as a complete sequence. Earlier profile/plan updates do not establish
repair of this failure. Treat scientific self-repair as an untested hypothesis,
not as a conclusion rescued by an audit.

Produce one concrete, falsifiable research unit for drug-discovery functional
decisions, or a precise finding that no such unit has been established. The
candidate question is whether a virtual-cell scientific agent can identify a
decision-relevant failure of its existing response knowledge, obtain a
discriminating observation, revise an explicit model assumption or experimental
procedure, and improve decisions on subsequent backgrounds beyond ordinary
refitting and active learning. Merely changing parameters, storing another
profile, caching a plan, or retrieving text is insufficient evidence of a new
scientific capability. A finite successful test would still not establish
open-ended evolution.

Use only authorized development material. First inspect metadata, source receipts
and schemas for existing measured assets. Exposed, released development data can
support a clearly labelled feasibility analysis; they cannot become independent
confirmation by changing a split or downloading them again. Do not open old G/F,
unacquired C, consumed held-out A/T, restricted ALMANAC/PRISM tiers, or anything
the existing access contracts exclude. Do not purchase data, contact authors or
start wet experiments. If an eligible payload can be examined under the existing
authorization, inspect only the minimum needed to establish its observation unit.

Do not impose requirements that belong to stronger claims:

- Mechanism-recovery claims require independent mechanism-specific evidence;
  pre-existing labels are one possible source, not a universal prerequisite.
  Labels are unnecessary for learning latent response structure or assessing
  measured functional decisions.
- Monetary costs are needed for monetary savings claims. An explicit, defensible
  query-count budget can support a relative measurement-efficiency study.
- Independently validated hits are needed for that confirmation claim. Measured
  in-vitro response can itself be a functional endpoint, with that limited label.
- Complete whole-dataset coverage is unnecessary if a common measured action
  subpool can be defined before evaluating policies. Do not fabricate missing
  outcomes or call model predictions new experimental observations.

For each candidate source, provide evidence for the following eight items and
select at most one research unit:

1. Exact drug/pair, dose, time, background and endpoint identities. Explain how
   action meaning is preserved across contexts; numeric pair IDs alone do not
   establish semantic correspondence.
2. A legal measurement menu with recorded observations, exposure status and
   missingness. State the query unit and what practical resource it approximates.
3. A specific existing-model error that can alter a downstream drug decision.
   Show why a strong conventional predictor/planner leaves meaningful headroom.
   Do not reopen the consumed O'Neil evaluation or present the closed pair-ranking
   estimand as a fresh confirmatory experiment. A distinct, authorized development
   unit must establish its own decision opportunity.
4. Two numerical competing explanations that predict distinguishable outcomes
   for the SAME available observation. Functional response hypotheses can suffice;
   complete mechanism identification is not a prerequisite for a functional claim.
   Quantify uncertainty when data permit;
   otherwise mark the distinction unestablished. A hidden new effect outside
   every legal observation is unidentifiable, not a threshold-tuning opportunity.
5. A downstream measured target that could falsify the proposed repair, with
   traceable pairing, shared reference terms, batch and replicate dependencies.
6. An explicit sequence: prior task -> observed failure -> diagnostic query ->
   revision -> later task. The revision must precede the task used to evaluate
   its benefit. Cross-sectional replay is not a real chronological intervention
   unless the data support that interpretation.
7. Comparators: fixed-model refitting, ordinary active learning or KG/lookahead,
   and an appropriate caching/distillation or drift-repair method. Separate the
   benefit of revision on identical observed data from the benefit of the full
   acquisition-and-revision procedure at equal measurement budgets. Include an
   appropriate conventional model-selection baseline if choosing among revisions
   could explain the gain. Name exactly what would distinguish the proposed
   mechanism from these, and account for fully measured history or released
   batches as shared prior resources or explicit additional costs.
8. A claim table separating software correctness, exposed measured development,
   independent functional validation, mechanism evidence, real economic value
   and pharmacological efficacy. Do not prescribe a sample size without an
   estimand, variance/dependence model, practical margin and target power.

Output one concise qualification document, an evidence manifest, and a proposed
experiment only if the observation unit is supported. Cite precise local source
records and verified primary literature for any novelty claim; distinguish ideas
from demonstrated results. Do not create another architecture, multi-agent
framework or broad world-model package at this stage. If a requirement fails,
identify the exact missing link and whether a smaller functional claim remains
possible. Do not return the blanket conclusion that no measured research is
possible merely because independent confirmation is unavailable.

If the unit qualifies, the proposal must freeze the endpoint, primary resource,
comparison, sampling unit, access boundary and stopping condition before any new
evaluation. Promotion must require the actual primary objective, not only
secondary superiority. Time short invocations in sufficiently long repeated
batches and report clock resolution; do not infer precise break-even counts
from mostly-zero per-call CPU measurements. No API is needed for qualification.
