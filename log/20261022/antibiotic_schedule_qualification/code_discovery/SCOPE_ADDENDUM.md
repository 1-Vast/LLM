# 范围更正：共同prefix不是所有replay的前提

2026-10-22。追加澄清，不改写已结束的4请求报告/来源或原始资格结论。

`REPORT_ADVOCATE.md` 最后一节“共同prefix第二动作分支...才可考虑dev-only数值合同”表述过宽。精确范围如下：

- **跨实验query/update research-agent replay**：只需每个合法schedule action有对应真实条件/终点、预算与失败分母，及允许的源任务/支持查询/未来未查询目标。可以每次购买一个独立静态schedule实验；不要求相同colony先经历相同prefix后被随机改派第二动作，也不要求真实state-feedback部署。
- **基于当前state选择第二动作的同colony/匹配prefix控制，或由相同prefix续行动反证state充分性**：才需认证共同prefix下的真实替代continuation菜单、相应state测量与未来结局。不能用不同初始背景/不同prefix的静态schedule替代其因果对照。

因此，当前未认证完整处理—轨迹—功能join的结论保留，但不能因缺共同prefix自动关闭合法跨实验query/update replay。后续数值合同应按实际主张选择相应资格，避免给较弱但合法任务增加无关门槛。也不能用较弱replay的阳性支持更强feedback-control主张。
