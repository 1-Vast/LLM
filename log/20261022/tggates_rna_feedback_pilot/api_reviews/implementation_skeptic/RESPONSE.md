## 严重度：阻断（必须先修，否则数值执行不能放行）

### 1. `ReducedRidge.fit` 在 `rho_0` 下把 `sqrt(0)` 作为块尺度传入 `Blocks.transform`，得到全零块；`Ridge` 的 WLS/中心化对零列是允许的，但 `ReducedRidge` 的 SVD 数值秩阈值与 `weights` 语义不一致
- 位置：`linear_models.py:ReducedRidge.fit`；`pilot_core.py:feedback_fit_predict` 的 `rho_0` 分支。
- 事实：协议第 5 条要求 `rho0` 保留零列与两 block 尺度；代码用 `[1, sqrt(rho)]` 作为 `Blocks.transform` 的 `weights`，当 `rho=0` 时第二块整列乘以 0，再除以 `sqrt(len(blocks))`。这确实保留零列，但 `ReducedRidge` 随后用 `x.mean(0)` 和 SVD 的 `tol=(s[0])*max(shape)*eps`，零列不进入有效秩；这本身可接受。真正的问题是 `ReducedRidge` 的 `self.weights` 在 `predict` 时再次乘到查询块上，而 `fit` 时已把权重乘进 `x`，`predict` 又乘一次——对 `rho_0` 第二块是 0，对 `rho=1` 是 1，对 `rho=0.5` 是 `sqrt(0.5)` 两次。`fit` 的 `x` 已含权重，`predict` 的 `x` 再含权重，等价于查询侧块尺度被平方，训练侧只乘一次；这与协议“两 block 尺度、sqrt(rho) 只作用一次”不一致。
- 可复现：构造 `rho=0.5`，比较 `ReducedRidge.fit(...).predict(q)` 与手工 `transform(q, weights)` 后代入 `fit` 的同一 `xmean/left/right`。预测与 `fit` 时 `x` 的块尺度不匹配。
- 最小修正：`ReducedRidge.fit` 内部用 `x=self.transformer.transform(blocks, weights)` 后，`predict` 必须用同一 `weights` 变换查询，但 `fit` 的 `xmean` 是在已加权 `x` 上算的；因此 `predict` 也应先 `transform(blocks, self.weights)` 再减 `xmean`。当前代码正是这样，所以问题不是二次乘权，而是 `xmean` 与 `predict` 的 `x` 都含权重，二者一致。重新核对：`fit` 中 `x=self.transformer.transform(blocks,weights)`，`self.xmean=x.mean(0)`；`predict` 中 `x=self.transformer.transform(blocks,self.weights)`，再 `x-self.xmean`。两者一致。**此条撤回，不构成 bug。** 保留说明：`rho_0` 零列不进入 SVD 有效秩，符合“零列保留”的存储语义，但 `ReducedRidge` 没有显式断言零列在 `left/right` 中对应零贡献；若下游依赖 `left` 的列数等于输入维数，需检查。当前 `left=vt.T@...` 的 `vt` 来自 `x-self.xmean` 的 SVD，零列在 `vt` 中仍有坐标，`left` 形状为 `(p, r)`，零列对应行可非零但被 `x` 的零列抵消。可接受。

### 2. `Base.export` 的 `slope` 维度/缩放与 `training_targets` 的 `u@r['slope']` 不匹配协议中的 `g` 对 `x` 的导数
- 位置：`pilot_core.py:Base.export` 与 `training_targets`。
- 事实：`h` 的输入块为 `[x, design, b]`，`Blocks` 对三块分别中心化并按块 RMS 缩放，再除以 `sqrt(3)`。`h` 的线性系数在变换后空间为 `self.h.dual` 对应的 `x` 块系数 `self.h.x[:,:p].T@self.h.dual`，但 `predict_transformed` 的映射是 `(x_transformed - xmean)@self.x.T@dual`，其中 `self.x` 已含 `sqrt(w)` 和块缩放。`slope=self.h.x[:,:p].T@self.h.dual/(self.h.transformer.scales[0]*sqrt(3))` 试图还原到原始 `x` 坐标。检查：`h.predict([x,design,b])` 对 `x` 的线性部分为 `((x-m)/s/sqrt(3)) @ (self.h.x[:,:p].T@self.h.dual)`，所以对原始 `x` 的导数是 `(self.h.x[:,:p].T@self.h.dual)/(s*sqrt(3))`。代码一致。**此条不构成 bug。** 但注意 `self.h.x` 是加权后的 `x`，`weights=None` 时 `sqrt(w)=1`；`Base` 中 `h` 拟合未传权重，所以一致。
