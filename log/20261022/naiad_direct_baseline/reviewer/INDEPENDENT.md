## Architecture and exact implementation distinctions

Default MLP embedding path: learnable G by d table; shared Linear(d,d), Dropout(.1), ReLU, Linear(d,d) applied per gene; sum two encoded vectors; Linear(d,d), Dropout(.1), ReLU, Linear(d,1). Phenotype path is Linear(2,h,bias=False), Dropout(.1), GELU, Linear(h,h,bias=False), Dropout(.1), GELU, Linear(h,1). Output is branch sum. This is neither fixed linear addition nor a state transition model. Intermediate branches are not uniquely identified causal additive/interaction effects.

Author initialize_model uses n_train/G, not average two-endpoint appearances 2*n_train/G. It takes largest schedule key STRICTLY LESS than that value. Schedule keys/outputs are 0:2,2:2,4:4,10:16,20:16,30:32,40:64,60:64,80:128,100:128. For full-fit G103 budgets128/512/2048 this yields2/4/16. Inner-training dimensions must use the actual inner-training count, not total outer budget. Strict inequalities matter at exact knots. Table9 calls the quantity average times genes seen and gives approximate dataset-size examples inconsistent with treating the code rule as an exact paper implementation. Do not silently multiply by two and call it the unmodified author default.

Paper Table9 Norman recipe:500epochs, phenotype hidden64. Class defaults: hidden256; tutorial100epochs for its example and200 for replicate function. Model class standalone default hidden512 is superseded by NAIAD.initialize_model default256. Freeze one clearly named recipe before seeing outcomes; a paper-aligned500epoch/hidden64 run with exact author dimension rule is a transparent hybrid, not bitwise paper reproduction. Any second recipe is extra search/cost and must be declared beforehand.

## Leakage and selection controls required

1. Canonicalize unordered gene pairs and collapse guide/replicate outcomes before pair splitting. Neither reversed orientations nor replicate guides may cross folds. Keep the exact shared pair universe; do not quietly drop pairs via author dropna joins. Independently assert all103 singleton scores exist and are finite. Singles must come only from singleton controls, never pair-label marginal averages.
2. Do not use load_naiad_data or prepare_data to reshuffle a benchmark already split. Build author datasets from fixed IDs and order. No diagonal/control rows should be introduced as additional pair training examples. Full known gene vocabulary is permissible transductive metadata; unseen-in-training gene embeddings remain random and are a real limitation.
3. Budget counts all labels used for fitting OR checkpoint/hyperparameter selection. Inner validation must be drawn from the128/512/2048 feedback pool. The tutorial's1000extra validation labels are not free. Training plus inner validation may yield a selected checkpoint without refit; if refitting all labels, freeze an epoch count selected inside budget and count the additional fit. Outer development is already exposed historically and remains exploratory, but must not choose this phase's recipe or checkpoint.
4. Author train_model evaluates every nontrain loader each epoch, including test. Supply only train and inner val during fitting; outer predictions must be separate after checkpoint freeze. Never supply protected labels even if code only evaluates them. Author best_model is selected exclusively by validation loss; default generate_preds uses final model unless use_best=True.
5. Train-derived target normalization, if any, must be frozen per fit and inverted before original-scale MSE. The paper/tutorial do not require pair-target normalization. No global residual fit, quantile cutoff, or target centering using outer labels. Data-preparation tutorial fits a descriptive linear regression and residual quantiles on all data; those are not a valid benchmark training recipe.
6. Author load_naiad_data randomly swaps IDs and matching scores with global RNG before set_seed in tutorial. EmbedPhenoDataset additionally independently shuffles scalar phenotype columns once with generator seed0; embeddings are sum invariant, but scalar MLP is not exactly invariant. Freeze deterministic preprocessing and demonstrate ordering treatment. Averaging predictions over both scalar orders guarantees invariant inference and is a disclosed adaptation with inference cost; it does not imply exact author reproduction. Alternatively preserve exact author shuffle behavior and report orientation sensitivity without selecting the better orientation.
7. Explicit model.eval() and no_grad() on the chosen checkpoint at inference. generate_preds lacks these guards; selected best_model happens to be copied while in eval mode, but relying on incidental mode is fragile. Squeeze can produce a scalar for batch size1 and break extend; flatten output safely. MSE sum scaling is the author optimizer behavior and must not silently become mean under weight-decay/LR comparisons.

## Minimal stronger controls and cost

Keep established ordinary RNA KRR/nuclear predictors as practical bars. Add a same-single-information scalar control fitted only on feedback: intercept plus shared singleton sum and singleton quadratic terms (or the already established quadratic predictor), with its penalties selected on exactly the same inner split. NAIAD pheno-only ablation with identical architecture/training separates identity embedding value from scalar nonlinear fitting; this is an extra declared fit, not a free control. These are ordinary controls, not new mechanisms. Freeze candidates/seeds before results; do not increase search to rescue a negative result.

For default MLP h, G and d, parameters excluding unused rank head: G*d + 3*d*d + 4*d + h*h + 3*h + 2. At G103,h64,d2/4/16, these are4516/4766/6770; check sums mechanically before reporting. Author allocates an unused rank_ffn too; optimizer does not train it in normal regression, so report both allocated/trainable and actually optimized parameter counts if using author module. Cost is dominated by h*h phenotype operations, not small embeddings. Per fit report epochs, batches, selected epoch, actual optimizer steps, wall time, CPU/GPU and threads, peak memory where measurable. With batch1024 and small budgets many fits use one or two batches per epoch; warmup is10percent of actual steps and scheduler decays toward0.1ofLR, not zero despite docstring. No empirical runtime/accuracy claim is available from this source-only audit.
