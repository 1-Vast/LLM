## Frozen interface for the driver

`DATA.npz` contains `full` and `without_mono` float32; `effect`, `dose`, `raw_dose`, and `y` float64; `episode` int32; `pair` int16; `role` fixed Unicode; `valid_mask` boolean. `effect` is the two paid endpoint mono means, `dose` is per-drug normalized log10 uM, and `raw_dose` is canonical A/B uM. The inputs-stage test y is entirely NaN. All active nominal target rows are retained, including target missingness and input abstentions.

`ROWS.json` is a list aligned one-to-one with data rows, with `episode_id`, `targetkey`, `position`, `role`. `EPISODE_META.json` is a list with episode/cell/role/target pair, two query pairs/keys, two residual means or null, input validity and abstention reason, and logical two-bundle/row costs. `PAID_SUMMARIES.json` is a list with unique paid `key`, `role`, `pair`, `mean_residual`, and `rows`. `PAID_OBSERVATIONS.json` retains the allowed raw paid fields and exact dose strings for audit. Physical unique-matrix deduplication does not reduce logical per-episode purchase cost.

Each paid full matrix is canonically oriented and sorted by exact Decimal dose then integer POSITION. Its 49 padded rows expose doses, both raw mono observations, combination, structural present mask, and three observed masks. The without_mono rows expose doses, combination, present, and combination-observed mask. These arrays are the same purchased data across methods. Partial missing raw mono is zero plus observed-mask=0; observed zero retains observed-mask=1; structural padding has present=0. Finite group means use arithmetic mean and Decimal-equal doses are pooled without clipping.

Root and skeptic resolved an actual boundary found during cross-review: **any drug/exact-dose group in either complete paid witness**, including the non-target partner, without a finite observed mono mean makes the entire episode a common abstention. Any nonfinite paid combination also abstains. This makes valid episodes compatible with own-grid Bliss residuals for local offset. No witness is swapped, no nominal target is dropped, both purchases remain charged, and finite purchased information may remain encoded under valid_mask=False. Driver fits/predictions/scoring must use the common mask.

For test opening, `verify_predictions` verifies all three files before any archive extraction: `TEST_PREDICTIONS.npz` against `predictions_sha256`, `TEST_ACTIONS.json` against `actions_sha256`, and `SELECTION.json` against `selection_sha256`. It returns the three verified hashes, which are bound into the target receipt. It additionally checks frozen preparation code/protocol/design/schema and input DATA/ROWS/EPISODE_META hashes. Only then may selected test `inhibition` be converted; `TEST_TARGETS.npz['y']` has the full DATA y shape, non-test entries NaN, exact source key/POSITION lookup. STARTED markers and existing stage artifacts prohibit overwrite.

## Actual cross-review and resolved objections

I read the skeptic's complete protocol review and the preparation code was independently read by the skeptic. We agreed that utility actions must be selected on all nominal rows and sealed before opening targets; recommendation coverage is the **intersection** valid-input AND all-nominal-target-finite over all frozen nominal episodes, not two independent 95% checks. Every preassigned MASTER must contribute to each endpoint or qualification stops. This avoids silently changing the macro/bootstrap population. Training weights are explicitly episode-balanced, not cell-balanced; all arms share the same fit weights. Root has incorporated these rules.

I challenged the skeptic's proposed stronger recommendation selection on budget/asymmetry grounds. Root resolved it prospectively: reuse all 48 paid validation fits to select endpoint-specific policies for each candidate and comparator, including jointly selected offset eta; deduplicate up to 14 final (base,config) refits. Two separately optimized policies do not support a single-same-parameter two-endpoint claim. This is a legitimate protocol adjustment before numeric access and must be costed as implemented.

I statically read driver.py and metrics.py. Offset priors deduplicate paid matrix keys and reject duplicate summaries; reference roles are train for validation and train+validation for test. Episode offset is computed from only that episode's two witnesses relative to frozen historical priors, without cross-episode weight updates. TEST_ACTIONS and SELECTION are written and hashed alongside predictions before test opening. I found and reported a temporary driver/metrics return-interface mismatch (nested metric keys and bootstrap lower/upper versus a ci95 lookup); root owns and is correcting that integration before freeze. This report does not certify a driver revision not yet rechecked.

The remaining scientific limitations are those in the independent data draft and measured protocol: source-conditional retrospective oracle, uncertain raw mono provenance, no prospective independence or causal instrument guarantee, no new world-model/agent/inheritance/RSI contribution. Passing preparation tests validates access/mapping behavior under synthetic cases; it provides no performance evidence.
