# Metrics interface

`research/az_paid_reference_gate_20261022/metrics.py` contains no file loading, model fitting or role selection. All arrays passed to one scoring call must describe **all nominal rows of one upstream role**; the upstream driver is responsible for selecting that role and passing the frozen assigned MASTER list.

`make_actions(pred, effect, episode, valid_mask, k=5)` returns an integer episode-keyed dictionary of lists of row indices in the supplied arrays. Indices are global within these supplied arrays, never local within an episode. Its only numerical inputs are predicted combination outcome and paid monotherapy effects. It ranks `pred - max(effect[:,0], effect[:,1])`, descending, with ascending original row-index ties. Only fully valid-input episodes with at least k nominal rows get actions. It never reads target labels and does not use a target-finite menu. If the caller supplies a role subset of a larger array, it must translate these positions to original positions before sealing.

`evaluate(y, pred, episode, master, effect, valid_mask, actions, *, assigned_masters, k=5, minimum_coverage=.95)` evaluates already fixed actions. `score(...)` has the same first six arrays and keyword arguments, with `nominal_actions=None`; it generates actions when omitted, otherwise passes the supplied fixed action dictionary to evaluate. Validity must be constant within an episode. Valid-input rows require finite predictions and paid effects; a failed prediction raises rather than silently changing the common target panel. Action dictionaries must cover every input-valid nominal episode with at least k rows, including those whose target values later prove incomplete.

Forecast uses every finite target row in an input-valid episode with at least five finite target rows. Recommendation and full-grid oracle regret use only input-valid episodes whose **entire nominal target matrix is finite**. No target values, effects, or predictions are clipped. Both endpoints aggregate row values within episode, then episodes within MASTER, then equal MASTER means. Explicit `assigned_masters` order defines all `per_master` vectors; zero contributions appear as `None`, are listed in coverage diagnostics, and force coverage failure. A displayed aggregate over available values after a failed gate is descriptive only and must not be used for candidate ranking or bootstrap.

The result is JSON-friendly with top-level `mae`, `utility`, `oracle_utility`, `regret`, `coverage_pass`; nested `input`, `forecast`, `recommendation` coverage diagnostics; `assigned_masters`; `per_master` vectors for those four metrics; and `per_master_episode_counts`. Nominal episode/row denominators retain input abstentions. Input, forecast episode, forecast finite-row, and recommendation episode coverage must each reach the threshold. Each endpoint and input coverage also require at least one contributing episode for every explicitly assigned MASTER. Forecast and recommendation may have different common panels by their preregistered missing-target rules, but each panel is shared across policies.

`paired_bootstrap(candidate, baseline, *, higher_is_better=False, n_boot=10000, seed=20261022)` requires aligned finite MASTER vectors, with missing contributors rejected. It returns `gain`, alias `mean`, `ci95`, aliases `lower`/`upper`, number of MASTERs, number of resamples and seed. Positive gain always favors the candidate: baseline minus candidate for MAE, candidate minus baseline for utility. Resampling uses one shared MASTER index draw for paired differences and percentile 95% bounds. It does not align identities automatically; callers must pass vectors in the same explicit assigned-MASTER order and only after qualification.

All verification is synthetic. `METRICS_SYNTHETIC_RUNS.jsonl` preserves every test run and `METRICS_SYNTHETIC.json` records the latest result, source hashes, failures, and biological-read/fit counts of zero. These tests do not establish biological performance or complete-driver correctness.
