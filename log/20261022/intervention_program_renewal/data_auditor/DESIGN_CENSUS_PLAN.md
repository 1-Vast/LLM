# Minimum design-only census, proposed but not executed

2026-10-22. This is a concrete proposal for root to freeze under a separate access protocol, **not an authorization to open responses now**. No download follows from this document. Initial reviewer allocation of8GETs is exhausted. Both current FSI/CCIP candidates fail earlier gates and do not justify spending this source. A census can establish one honest static functional task for a later distinct mechanism; it is not itself an innovation result.

## One source object, honest exposure vocabulary

Use only Figshare25266697.v2/file45451363: `matrix_well_stats_GDSC_007_010_plus_Spiper1.zip`,241088863bytes, MD5`ff3dab95ad59a1c956e3b11c397dcbd8`, CC BY4.0. Existing local manifest and receipt are sufficient to identify the target. Root must define bounded request/redirect/time/body policy before downloading; the8MiB discovery cap cannot silently become a241MB download. Do not automatically retry/resume, substitute another version or execute author code. Retain full successful archive/failed body and receipt under this phase's log; avoid a second copy in a global data tree.

Downloading the ZIP **is contact with source bytes containing numerical responses**. Checksum calculation also reads the whole compressed source. Reading CSV headers inflates compression blocks; streaming a row to project selected columns processes bytes that also encode response fields. A standard `usecols` implementation may tokenize them. Consequently no honest description can promise zero response-byte contact.

The enforceable promise is narrower and useful: **no target value is shown to the human/model, converted to a number, output to logs, aggregated, ranked, fitted, joined by magnitude, or used in eligibility/split/model selection**. Numeric drug IDs and declared dose coordinates are design metadata and may be parsed after explicit approval of that column whitelist. Source QC and missingness masks are response-derived information and must be exposed as such if used. The access receipt should have distinct fields for `source_response_bytes_contacted=true`, `target_values_output=false`, `target_numeric_conversion=false`, `target_value_used_for_selection=false`; do not call the resulting whole source pristine.

## Two short sequential stages

**A. Archive identity and header-only report.** Verify exact download length and MD5 against the locked manifest before parsing. Read ZIP directory, member filenames, compressed/uncompressed sizes, CRC and compression method; hash the archive. Do not extract member files wholesale. For CSV members, read only the header line with a fixed small header-byte cap and record column names/encoding/delimiter; never print a first data row or a dataframe preview. Stop on an unexpected format, missing expected assay namespace, bad checksum or header overflow. No response field may be used to infer data types by sampling values. Save a schema report and freeze it before row processing.

**B. Predeclared metadata projection and counts.** Root reviews the actual header names, selects an explicit whitelist and freezes the script/whitelist hash **before reading rows**. Names below describe required semantics, not already certified raw-schema names. Do not adaptively guess ambiguous columns or permit `.*value.*` wildcards. If the raw file does not contain the necessary keys, report the gap and stop; do not automatically download the8MBsummary.

| Allowed semantic field | Purpose and boundary |
|---|---|
| source screen/experiment/member | Separate Sandpiper1/GDSC007–010 and track source membership; never turn screen count into independent task count |
| SIDM/COSMIC/cell-line name; tissue/cancer type if present | Canonical background identity and task grouping; repeated/renamed models stay together |
| drug IDs/names, library-axis identity | Symmetric pair IDs and exact compound mapping; no target-family grouping inferred solely from drug name |
| declared concentration and units, matrix row/column | Actual measured dose geometry,7×7vs5×5, dose-menu differences |
| plate barcode, drugset, well coordinates; replicate/occasion/date/stock if present | Preserve shared plate/control/occasion structure; dates are not automatically independent lots or causal chronology |
| explicit untreated/DMSO/positive/blank/control-role annotations | Count purchasable controls and map which wells support which normalization; no actual control intensities |
| author-provided QC/pass/status flags, **only if separately allowed** | Identify released/QC-filtered design; classify as response-derived structural exposure; never recompute QC from values |

Response columns, raw intensity, normalized inhibition, fitted curve parameters, IC50/Emax/AUC, Bliss/HSA expected/excess and molecular-value columns are denied. If a CSV parse error can contain a data row, sanitize the exception to filename/row number/column count rather than raw line/token. Do not persist unprojected CSVs, notebook previews, parser warnings with values or temporary full tables. A streaming standard-library projector can retain only whitelisted fields; it must not compute target dtype, min/max, histogram or nonfinite-value counts.

**Missingness nuance:** field presence is insufficient to certify that every recorded design row has a usable target. The minimal stageB can count design rows and author QC masks without target inspection, leaving a response-availability gap explicit. If root wants null/non-numeric target masks, that is a separate, explicit structural-exposure extension: compare only predefined missing-token strings without numerical conversion, save only availability masks/counts, and prohibit value-based filtering. A target parse failure must not be treated as an occasion to print the token. Thus missing-target QC cannot be smuggled in under a claim of zero target-field access.

## Deliverables that resolve the real questions

1. A source/member/header manifest, field whitelist and hashes; no human-visible target values. Counts of records and unique `(screen,SIDM,canonical drug pair,actual dose coordinates,plate,occasion)` at their genuine granularity.
2. A coverage ledger beginning with the paper's nominal **82×755+27×376=72062** pair-line slots and its stated **68816** observations, gap**3246**. Distinguish nominal design, available SIDMs, actual unique pair-line keys, duplicates, screen overlap, author QC filtering, missing panels and removed AZD1775 doses. Do not assert that all3246are QC failures unless the released keys/flags show that mapping. If the reported number uses an unrecoverable publication-specific definition, preserve `UNRESOLVED_COUNT_DEFINITION` rather than force an exact reconciliation.
3. Common eligible measured menus by SIDM and screen; count the largest genuinely shared rectangles and task-specific masks. Removed or absent actions remain unqueryable. If a global rectangle is small, a fixed per-task measured menu shared by all policies can still support a valid task; intersection≥64is one proposed application setting, not a universal law.
4. An explicit replicate/control map. Enumerate whether the seven named control lines have eighteen valid measurements, fewer after QC, or keys insufficient to reconstruct occasions. `DRUGSET_ID` is not asserted to equal occasion/lot just because author code groups by it. Repeated control lines support reliability diagnostics; they cannot manufacture independent later cellular contexts.
5. A Jaaks overlap ledger using **old exposed design metadata only**, initially `SIDM × exact compound-pair identity`, then actual dose/assay design where comparable. Track overlapping lines even for disjoint pairs because shared line history can leak context. Use known source-specific IDs/names and vetted aliases; unresolved mappings stay unresolved. Keep all occasions of a SIDM and known related/duplicate model in a single role. Reserve fully non-overlapping contexts if an independent-context claim is intended, or explicitly frame overlap as same-world adaptation. Do not claim the nine/4790publication overlap accounts for every lineage overlap.
6. A proposed outcome-blind task manifest with episode/context, legal actions, query bundle cost, observation fields, inherited objects, sequence and final withheld roles. Report the **available** background/tissue distribution first; select the task and uncertainty unit for the scientific question, then freeze before outcomes. My independent draft's16cancer-type/64pair example is retractable and does not disqualify every alternative static task. No arbitrary16cancer-type requirement should be elevated into general source availability.

Stop after these deliverables if they resolve source structure. Do not fit, optimize acquisition, calculate decision headroom, re-estimate assay noise from target values or choose a promising panel from responses during the census. A later development-only usefulness test requires its own fixed question and response access plan. All final-task numerical targets remain inaccessible to candidate tuning.

## Why the8MBsummary is not the default first object

Figshare22362808.v2/file44311796, `gdsc-010_matrix_results.csv`,8026089bytes, is a **single-screen matrix-summary** object. Its smaller size is not evidence of sufficient schema or no outcome exposure. Author scripts show summary fields such as`BARCODE`,`DRUGSET_ID`,`SIDM`,`lib1_ID`,`lib2_ID`; that could help an extremely narrow one-screen identity census, but no inspected manifest proves it carries every well/control/dose/occasion key. It cannot establish all-five-screen coverage, raw well query costs, all-source missingness or normalization-control access. Downloading it then the raw ZIP adds another response-containing object and extra namespace/version joins.

Recommendation: **if root chooses an all-screen/well-level design census, go directly to the single locked241MBZIP under the new protocol**. The summary is a justified alternative only if root deliberately defines a single-GDSC010matrix-level task that does not require well/control reconstruction; its restricted scope and lack of current raw-schema certification must be explicit. Neither choice is necessary to falsify today's FSI/CCIP proposals.
