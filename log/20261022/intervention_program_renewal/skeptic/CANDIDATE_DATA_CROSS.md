# 候选是否应消费AZ2024新响应：实际数据方质询

2026-10-22。发生于反方独立 `CANDIDATE_REVIEW.md` 保存后。反方仅根据数据方发来的资格摘要与当前FSI/CCIP提案回答；**没有自行读取、下载或认证AZ2024文件/响应**。本记录不授予任何新数值访问权限，也不添加用户批准流程。

数据方问：AZ2024是静态72h CTG，文件谱系区别于Jaaks2×7但有9组合4790 pair-line来源重叠；wellstats已归一化、只有7控制线triplicate×6occasion，没有早期z/干预后分子状态。候选是否值得消耗其response？以及82×755+27×376与68816差3246的design census应取241MB ZIP元数据，还是8MBsummary？

反方实答：FSI/CCIP均不值得据当前候选打开AZ2024新response，无具体反对数据方停止建议的理由。这是具体算子/用途门失败或未指定的结论，不是对AZ数据一般效用的否定。按所给摘要，静态CTG无早期z，不能直接检验FSI状态到后期功能；少数控制线重复不自动为所有pair-line提供独立task，来源重叠必须保留。不同静态combination功能问题应另立科学主张，而非拯救FSI/CCIP。

反方原回复把241MB ZIP说成“已有”，数据方纠正其尚未下载；反方明确接受并撤回该假设。数据方还指出：CSV即便usecols白名单，传输、解压和分词仍接触含response的源字节，因此不能写零response字节访问。

反方修正答复：若另有前置metadata-census协议而取得ZIP，可以限制target值不输出、不数值转换、不聚合/筛选/建模，人工/模型不见target数值；必须区别 **source-response-byte contact** 与 **target-value use**。白名单不会使源字节接触消失。8MBsummary同样含response字节且按数据方摘要缺完整well/control结构，不自动代替design census。反方未独立认证这些字段，亦不作GET/ZIP访问；真正需要的协议与字段选择由root/数据审查另行具体化。

结果：无需为两项STOP候选消费AZ响应；若为不同有证据的问题做元数据资格，应如实记录字节接触与target使用边界，并在能解释设计差额时停止，不把census当性能/新颖性GO。此处没有实测AZ药效或判其普遍无效。
