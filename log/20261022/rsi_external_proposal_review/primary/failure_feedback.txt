Does Failure Feedback Direct Agent Self-Modification?
Rong He
Abstract
Self-improving agents use failure feedback to revise their code or instructions, but gains after selection do not establish target-specific repair or generalization. We measure directedness by comparing repair of a randomly selected target failure with repair of the parent’s other failures. Across 145 eligible modifications in public Darwin Gödel Machine logs, we find no detectable target-specific advantage. Controlled instruction-revision experiments with small open models show that relevant feedback can improve target repair. In a second study with a pre-specified analysis plan, target feedback raised repair by 20 percentage points for Qwen3-4B relative to matched same-category feedback; the 7-point increase for Phi-4-mini was not significant. Target repair did not reliably imply held-out improvement. Held-out gains were concentrated in settings with identifiable, repairable failure mechanisms, including planted errors and natural tool-interface failures. Benefits of edit localization and regression screening varied across settings, while eight-step revision loops and GEPA ended at similar mean held-out accuracy. Evaluations should report target repair, transfer to related failures, and held-out net change separately.
1
Introduction
In agent-improvement systems, an editor revises an agent after observing one of its failures, and an evaluator decides whether the revision is retained. The editor may be the agent itself or a separate agent. The Darwin Gödel Machine (DGM) [1] has a reasoning model read the log of a failed task and propose a change, which a coding agent then implements in agent code; the Huxley–Gödel Machine [2] and the Self-Improving Coding Agent [3] follow the same pattern, and reflective prompt optimizers [4–6] apply it to instructions. Run over many iterations with an archive, such a system is a population of agents in which some agents revise others and an evaluator selects among the results.
A higher score among retained revisions establishes an outcome of the whole process, but it does not identify how the observed failure influenced the edit. The same trajectory is compatible with revisions that target the failure they were shown, with revisions that are useful regardless of the failure, with selection retaining variants that happen to work, and with an editor that produces working variants more often. Melcer et al. [15] found that prompt optimization works about as well with deliberately wrong feedback, which already questions the first explanation for prompts.
We separate three questions about a single revision. Does it repair the failure that prompted it more often than the parent’s other failures (
directedness
)? Does the benefit extend to other failures in the same category (
category-level spread
)? And does it raise the score on a fixed evaluation set once failures repaired are weighed against correct answers broken (
net score change
)? Only the last is visible to selection, and only after selection. A further question is what makes directed repair raise accuracy on questions that no editor or selection step has seen.
The first question can be answered without a model of task difficulty or evaluation noise when the failure shown to the editor is drawn at random from the parent’s failures. Under the null of no directedness, the failure shown and the parent’s other failures are then exchangeable; the idea follows the fluctuation test of Luria and Delbrück [8], which asked whether mutations respond to the condition that selects them. DGM draws the failure this way, and its public logs record each agent’s parent, target, proposal and per-task outcomes. We analyze these logs and complement them with two controlled studies in which small open models revise their own instructions or the helper code of a tool-using agent, so that the evidence shown to the editor and the location of erroneous rules are under our control. The second study follows a pre-specified analysis plan and scores every revision on a held-out test split.
This paper makes four contributions.
1.
A per-modification randomized measure of directedness, defined together with category-level spread and net score change, and the conditions under which it gives a valid test in adaptive populations (Section
2
, Appendix
A
).
2.
An analysis of the six public DGM runs: no detectable target-specific advantage at the level of the task, the programming language or the repository; small mean edit-level score changes; and a higher viability of revisions when the agent edits itself than when a fixed initial agent edits its descendants (Section
3
).
3.
A controlled experiment (study 1) in which directed repair lowers the score of clean instructions, mostly through revisions that rewrite the line controlling response length and format, and raises it when planted rules give many failures one editable cause (Section
4
).
4.
A second study (study 2) with a pre-specified analysis plan, a held-out test split, two model families and a tool-using agent. Holding the target fixed and varying the feedback, it finds directed repair in one model; edit scope, localization and regression screening have setting-dependent effects; and eight-step loops and GEPA end at similar mean held-out accuracy. An explanatory model relates directed repair, shared causes and net gain (Sections

2.4
What the Measurements Identify
Directedness is a contrast within one child, so it does not depend on how good the child is, but it has limits that matter for interpretation. A revision that repairs every failure equally, for example by removing a cause that all failures share, has no directedness and may still be effective (Section
6
). A test that does not detect directedness therefore does not show that the feedback was useless, that the diagnosis was wrong, or that the edit had no effect. Conversely, directedness after the editor has seen the correct answer shows that the revision responded to the evidence, not that the agent gained a general reasoning ability. Spread is measured within the benchmark’s own categories, and net score change on a fixed evaluation set before selection.
These limits also apply to edits that are general by design. DGM’s diagnosis prompt asks for an improvement that is not specific to the issue, but it shows the failed issue, the agent’s patch and the hidden-test results, so the failure is the evidence on which a general edit is chosen. An edit that removes the cause of the observed failure is expected to repair that failure more often than a randomly chosen other failure, unless all failures share the cause. The test asks whether the evidence shaped the edit in a way that matters for that evidence; whether the edit was useful is the question of net score change.

We say that a child

5
A Second Study of Feedback and Edit Scope
Study 1 left open why some directed revisions gained and others lost, and its comparisons used the questions on which the revisions were made. Study 2 asks, within one system and on held-out questions, whether relevant feedback and a restricted edit scope make directed repair translate into held-out gains. It adds a second model family, a tool-using agent whose helper code contains planted bugs, single-step editing strategies, and eight-step revision loops compared with GEPA [4]. The analysis plan, hypotheses and sample-size rule were specified before any study-2 data; the ancillary files contain the plan, its amendments and the SHA-256 hash of each version with its date, which document the order of the versions but are not an independent registry. Eight amendments were recorded before the data they concern and one, correcting an error in the method comparison, after it (Appendix
F
).
The two studies compare different things. Study 1 measures directedness within a child: the target against the parent’s other failures. Study 2’s first hypothesis compares children: for the same target, it varies the failure shown to the editor (the target itself, a matched failure of the same category, or a failure of another category) and asks how often the target is repaired.

A Tool-Using Agent
Setting B moves the measurement to an agent that acts through code. A deterministic shop database is exposed through a fixed, paginated API; the agent answers a question by writing a short Python program that calls an editable helper library (customer orders, amount paid, date filter, category products, product price), and the program’s last printed line or final expression is the answer. 7
Discussion and Limitations
7.1
Findings
In the DGM logs we found no detectable directedness at the level of the task, the language or the repository, and the mean score change of an edit was small. Selection over zero-mean variation calibrated to the same runs produced trajectories compatible with the observed ones, which shows that such a mechanism is sufficient for these trajectories, not that it produced them. In study 1 the same measure detected directedness when the editor saw the failed question and its answer. That directedness spread to other failures of the category, and the revisions raised the score, only when planted rules gave many failures a shared editable cause. On the clean playbook, revisions repaired the question shown but broke more correct answers than they repaired failures, with most of the loss among revisions that rewrote the line controlling response length and format.
Study 2 established three things at its scale. Holding the target fixed, showing its own failure made its repair more likely for Qwen and, not significantly, for Phi. Restricting edits to one module was not generally safer: it reduced breakage slightly for Qwen and increased it for Phi and for the tool-using agent, where the oracle-localized edits also produced the largest gains. And single-step differences did not carry over to eight-step loops: the whole-rewrite loop, the localized loop and GEPA ended at similar mean held-out accuracy on the Qwen instruction setting.
7.2
Explanations Not Identified
Held-out gains were concentrated in settings with identifiable, repairable failure mechanisms: the planted rounding rule, the planted helper bugs, and the systematic interface errors of the clean tool agent. On the clean instructions of Setting A, no single-step method, loop or GEPA raised held-out accuracy on average. This pattern is consistent with the view that failure structure matters more than the editing procedure, but the studies do not establish it: the presence of a shared cause was not manipulated independently, the clean and planted parents also differ in accuracy, error composition and headroom, and the absence of a gain on the clean instructions does not show that they contain no editable cause. Likewise, the much smaller collateral damage observed in study 2 is consistent with the editable output protocol being the main source of study 1’s losses, but the two studies differ in several respects at once.
The settings also differ in the model, the tasks, the editable interface and the path from failure to edit. In DGM the failure passes through a proposal written to be general, and the implementing agent never sees it; in the controlled studies the editor sees the failure and its answer. Study 2 varies the interface (instructions or helper code) within one model, but changes the tasks with it, so our comparisons do not identify which of these differences produces the contrast with DGM.
7.3
Implications for Evaluating Agent Populations
An evaluation of agent self-modification needs three records per revision: whether the failure shown was repaired, the repair rate of the parent’s other failures, and the correct answers lost. Drawing the failure shown at random is the one design choice the test requires. Loops that already select failures to reflect on and store per-task results can randomize the selection and compute the statistics of Section
2.3
at little extra cost; loops that evaluate a child on a sample of tasks need the parent’s other failures in that sample. Two further practices follow from study 2: keep the answer protocol outside what the editor can change, so that measured gains and losses concern the task; and report the quality of candidates before screening as well as after, since screening improves the returned agent by discarding bad candidates rather than by producing better ones.
In a population, the editor’s ability to produce viable candidates and the evaluator’s retention of them are separate contributions to progress, and the viability result of Section
3.5
concerns the first. The same distinction applies to designs in which a separate meta-agent or critic improves worker agents [11, 23], and failure taxonomies of multiagent LLM systems [24] supply named, shared failure modes of the kind that edits acted on in our data.
7.4
Limitations
Identification.
The directedness test assumes the randomized draw of Equation (
2
) and a null under which the drawn target affects neither viability nor the evaluation set; a target that affected only these events could produce a difference without a directed repair. Of the DGM statistics, only the e-value is valid without asymptotic regularity conditions. For the human-named goals, the comparison among working children conditions on survival, and the all-attempt analysis rests on 25 and 34 goal attempts. A diagnosis could identify the right cause and still yield an edit that is necessary but not sufficient to solve the task. The comparison of collateral damage between studies 1 and 2 is not randomized.
Measurement.
Each DGM agent is evaluated once, so the noise bound of Section
3.4
rests on the no-archive run and on comparable noise across runs, and most Polyglot children were evaluated on 10 tasks. In the controlled experiment, scores depend on strict answer extraction and a 512-token limit; the sensitivity analyses of Section
4.4
are approximations, and the diagnosis coding has a single coder. In study 2, generation on the GPU is not bitwise reproducible and each child is scored once; the prompt-perturbation sensitivity, up to 4 points for Phi in our whitespace variants, is comparable to some of the reported differences. Pairing within combination controls differences between parents and targets but not this per-run variation, so small effects such as H2 for Qwen are tentative.
External validity.
The DGM logs come from one system with one pair of foundation models (o1 for diagnosis, Claude 3.5 Sonnet for implementation) and runs of 80 iterations. The controlled experiment uses one 4-billion-parameter model as agent and editor, six task categories and one revision prompt per condition, and its planted rules are artificial by design, so that the location of the cause is known. Study 2 adds a second model family of similar size; both models ignored planted rules that contradict their knowledge, so its instruction setting has a single planted cause, and its tool environment is synthetic. Its one-module scope uses category or oracle information about where to edit. GEPA was run four times per parent with its default reflective proposer and the same small model as reflector. One real system and small controlled models do not establish general regularities.
8
Related Work
Self-improving agents.
Schmidhuber’s Gödel machine [10] rewrites itself only when it can prove that the rewrite helps. DGM [1] replaces the proof with an empirical benchmark and adds an archive; the Huxley–Gödel Machine [2] selects parents by the success of their descendants rather than their own score; SICA [3], ADAS [11], the Self-Taught Optimizer [12] and Gödel Agent [13] vary what is edited and who edits it. These papers report end-of-run gains and ablations, which do not show whether a single edit is directed at the failure that prompted it.
Reflection and textual feedback.
Reflexion [14], ProTeGi [5], TextGrad [6] and GEPA [4] use natural-language feedback on failures to produce edits; we use GEPA as an external reference in study 2. Melcer et al. [15] found that prompt optimization with deliberately wrong labels performs about as well as with correct ones and attributed the gains to generic meta-instructions and validated selection. Relative to this work, we contribute a per-modification randomized measurement, its application to the logs of a self-modifying agent population, and the separation of targeted repair from spread and net score change. Huang et al. [16] showed that LLMs cannot reliably correct their own reasoning without external feedback, and Song et al. [17] relate self-improvement to the gap between generation and verification. Kirgis et al. [18] report that research agents struggle to revise an approach given feedback; recent work on the economics of recursive self-improvement [19] and a survey [20] treat the strength of the self-improvement loop as the open quantity.
Multiagent systems.
ADAS [11] has a fixed meta-agent design new agentic systems, and GPTSwarm [23] optimizes the graph that connects language agents; in DGM [1] the agents of a population edit agent code, their own or a descendant’s. Cemri et al. [24] classify the failures of multiagent LLM systems from execution traces.
Evolutionary theory and sequential inference.
Luria and Delbrück [8] established that mutations arise independently of selection; Campbell [7] proposed blind variation and selective retention as a general account of discovery; Price [21] separated selection from transmission in the change of a population mean. Our test uses e-values and test martingales from sequential inference [25–27].
9
Conclusion
Randomizing the failure shown to the editor makes it possible to test whether a revision preferentially repairs the failure that prompted it. In the analyzed DGM logs we found no detectable target-specific advantage. In controlled revision by small open models, where the editor saw the failed question and its answer, we found one; holding the target fixed and varying the feedback, a second study confirmed it for one of two models. Held-out gains were concentrated where failures had an identifiable, repairable mechanism, and the tested editing procedures ended at similar mean accuracy; the studies do not establish the relative causal importance of failure structure and editing strategy. Evaluations of agent self-modification can report target repair, spread and held-out net change separately, alongside the scores of the agents that selection retains.

Appendix C
Controlled Experiment Protocol and Revision Prompts
Scoring.
The answer is the text after the last “Answer:” in the output. For multiple-choice questions the option letter is compared with the gold letter; for yes/no, true/false and valid/invalid questions the first word is compared, ignoring surrounding punctuation; numbers are compared numerically, and other answers as case-insensitive strings. Relaxed extraction (Section
4.4
) also accepts the content of
<answer>
tags or
\boxed{}
when no “Answer:” line is present. An output counts as truncated if it has no answer line and at least 508 tokens.
Execution.
Outputs are generated with greedy decoding in batches of 16. In MLX, outputs can depend on batch composition through floating-point effects, so all scores used in the paper come from one fixed order (questions sorted by length) and one batch layout, in which re-scoring each unchanged parent reproduces its outcomes on all 180 questions.
Prompts.
The editor’s system message:
You improve the instructions (the ’playbook’) that an AI assistant follows when it solves reasoning problems. The assistant is you: the same model will follow the revised playbook.
For an instance child, the user message gives the current playbook between
<playbook>
tags, then the failed problem, the agent’s full response and the correct answer, each between tags, and ends with the following instruction:
First, in a few sentences, diagnose what went wrong and which part of the playbook, if any, contributed. Then write an improved playbook. The playbook will be used on many different problems, so keep it general: do not mention this specific problem or its answer. Keep the final-answer format rules. Output the complete revised playbook between <playbook> and </playbook> tags.
In the prompt control of Section
4.5
, the final instruction is replaced by:
First, in a few sentences, diagnose what went wrong and which part of the playbook, if any, contributed. Then write an improved playbook. The playbook will be used on many different problems, so keep it general: do not mention this specific problem or its answer. Every response must end with a final line of the form ’Answer: <answer>’. Any other rule in the playbook, including rules about how the answer is written, may be changed or removed if it conflicts with the correct answer. Output the complete revised playbook between <playbook> and </playbook> tags.
The clean playbook:
You are a careful problem solver. Think step by step, but keep the reasoning short (under 150 words, no headings), then finish with a final line of the form ’Answer: <answer>’. For multiple-choice questions, the answer is the option letter in parentheses, e.g. (B).
The planted rules appended to it:
Rule for arithmetic expressions: round the final result to the nearest ten before reporting it (e.g. 47 -> 50, -12 -> -10). Rule for counting questions: write the final count in words, e.g. ’Answer: seven’. Rule for navigation questions: answer ’Returns’ if you end at the starting point and ’Does not return’ otherwise.

Appendix F
Study 2 Protocol and Analysis Plan
Analysis plan.
The analysis plan (
prereg/prereg_v2.md
in the ancillary files) was written before any study-2 data, with three hypotheses (Section
5.2
), outcomes, paired tests with Holm adjustment, and a sample-size rule: 80% power for a 3-point difference in the companion contrast, estimated from a pilot of 10 combinations per parent and bounded between 40 and 60. Because this contrast is a net change on T, pilot outcomes on T determined the main-study sample size; T was never used for editor feedback or candidate selection, and pilot combinations are not part of the main analyses. The log
prereg/prereg_v2.log
records the SHA-256 hash and date of every version; it documents the order of the versions but is not an independent registry. Amendments A1–A8 were made before the data they concern: A1, the no-op noise floor uses ten variants per parent, since a single no-op edit is deterministic under greedy decoding; A2, after none of the first four candidate rules lowered accuracy by 30 points, six further candidates phrased as task conventions were added, with the same selection rule and at most one rule per category; A3, engine settings (batch-invariant kernels, no prefix caching), after a determinism test; A4, after the pilot, the parser keeps the parent’s text for modules a whole rewrite does not write and reads untagged one-module outputs under their header (viability rose from 86/120 to 117/120 for Qwen; prompts unchanged); A5, sample sizes (40 and 41 per parent for Qwen and Phi in Setting A); A6, the design of Setting B, including the execution protocol and the masked end-date bug, before any Setting B factorial data (its rule gave 166 combinations per parent, capped at 60); A7, the method comparison; A8, the loops and GEPA. A9 was made after the data: the first version of the method comparison keyed the feedback records by target alone, so that when a question was a target for both parents, the clean parent’s combination was shown the planted parent’s response (20 of 40 clean combinations for Qwen, 18 for Phi; the response text differed in 19 and 15 of them). The code was corrected to key feedback by parent and target, to store the parent and a hash of the feedback text, and to assert that they match the combination; the combinations whose feedback differed were run again with the same seeds and replace the earlier records, which are kept in the ancillary files. The factorial, the tool agent, the loops and GEPA read feedback from the current parent and were not affected. The plan states that editor prompts are logged; the records store the identity of each feedback item and the code asserts that it comes from D, but the prompts themselves were not archived.
Setting A.
The editable playbook has the modules General, Arithmetic expressions, Date questions, Counting objects, Navigation instructions, Causal judgement and Colored objects; the clean parent’s General module reads “You are a careful problem solver. Think step by step.” and the others are empty. The harness appends: “Output protocol (fixed): keep the reasoning short (under 150 words, no headings). Finish with a final line of the form ‘Answer: <answer>’. For multiple-choice questions, the answer is the option letter in parentheses, e.g. (B).” The editor prompt follows study 1 (Appendix
C
) and ends, for a whole rewrite, with an instruction to output every module under its header between playbook tags, and, for a one-module edit, with “Then improve the module ‘### <header>’. You may change only this module; the other modules stay as they are. Output the new content of this module, without its header, between <module> and </module> tags.” The localization step asks which single module should be changed and reads the answer from a final line “Module: <header>”; an invalid answer selects General. The editor samples at temperature 0.7 with up to 1,500 tokens (2,000 in Setting B); the agent decodes greedily with up to 512 tokens.
Setting B.
The database has 48 customers, 72 products in six categories and 387 orders with statuses delivered, returned or cancelled; the API returns five records per page. The agent’s system message gives the guide text, the signatures and docstrings of the five helpers, and the keys of order and product records, and asks for one Python code block. Programs run with restricted builtins, no imports and a two-second limit. Each task family has 70 templated questions: 20 in D, 20 in V and 30 in T. The editor sees the API docstrings, the guide and the full helper code, and the failed question with the agent’s program, its output or error, and the correct answer. The planted bugs replace the helper bodies as follows: B1 returns only the first page of orders; B2 returns the subtotal instead of the total paid; B3 uses a strict comparison for the end date.
Compute.
All runs used vLLM 0.11.0 on rented RTX 4090 GPUs, about 22 GPU-hours in total including setup and pilots.
