Abstract
In-silico optimization of nucleic acids relies on predictive oracles that imperfectly capture biological function, so sequences optimized against one model may exploit model-specific artifacts and fail to generalize to independent models. Recent studies have shown that not all designers generalize equally well to independent models. In this work, we use agentic program search to iteratively propose, execute, evaluate, and revise code for nucleic-acid designers. We describe the successful strategies used to prompt the search. AutoNovo designers achieved the best observed mean among the evaluated methods on 3/3 DNA-design tasks in terms of in-silico performance, and 6/6 transfer tasks in terms of independent models. The designers come from a family of discovered nucleic acid designers rather than a single universal best designer. We plan to release the resulting designers. These results are the first steps in creating nucleic acid designers that maximize cross-model generalization, and thus improving the odds that in-silico designed sequences reflect real biology.
1
Introduction
Drug developers have been attempting to improve the therapy development process by computationally designing nucleic acids (in-silico design), which is a significantly faster and cheaper method than running large screens in a wetlab. One way of performing in-silico design of nucleic acids is to use a predictive sequence-to-function model (the oracle), that takes a sequence as input and predicts a scalar property such as translational efficiency, stability, or cell-type specific expression, and optimize the input sequence to maximize or minimize the property using a designer algorithm. A major hurdle to this in-silico design process is that the resulting synthetic sequences are often predicted to have excellent properties, when they actually do not perform well in real biological systems
[
10
]
.
It is expensive and time consuming to synthesize synthetic sequences in a wetlab to validate their performance in real biological systems. A cheaper and faster technique used in the field is to validate synthetic sequences using “orthogonal validation.” These models are trained to predict the same property, but differ in their training data, model architecture, or both. Note that this orthogonal validation is akin to a one-way test: agreement between the oracle and an orthogonal model does not guarantee that a synthetic sequence will perform well in real biological systems, but disagreement often indicates that the synthetic sequence is more an artifact of the oracle model rather than representing some aspect of biology.
A recent benchmark of nucleic acid design algorithms found empirically that designers differ significantly in their ability to agree with orthogonal models
[
13
]
. In this paper, our central question is:
can agentic program search discover nucleic acid design algorithms that outperform human-designed baselines
, with an eye towards generating synthetic sequences that perform well on oracles not used during program search? Such designers, we hope, would create sequences that were significantly more likely to perform as predicted in real biological systems, and therefore be more useful for real-world applications such as therapy design.
AI code tools are a powerful technique for designing algorithms. Recent works such as AlphaEvolve
[
7
]
, Empirical Research Assistant
[
3
]
, SkyDiscover
[
6
]
use evolutionary or tree-based methods to iteratively improve code generated by LLMs to optimize a given objective function and demonstrate it on a range of mathematical, scientific, and engineering problems. The ERA system closes an automated loop around code generation, execution, oracle evaluation, and program revision.
In this work, we use ERA to create designers and term our approach AutoNovo. Specifically, each ERA run searches for designer programs using an objective comprising one or two optimization oracles and, in most runs, an orthogonal evaluation oracle hidden from the designer, evaluated on a small set of start sequences. The use of LLM-based evolutionary algorithms like ERA introduces the concern that an AI-generated designer might overfit to the tasks it was evaluated against and not generalize to others. We take a two-pronged approach to address this. First, we prompt it to (re-)implement specific hand-crafted designers providing high-level information of the algorithmic approach. The prompt also includes some notes (see Appendix) on generalizing to other tasks (
task generalization
). Second, the optimization function is set to design on a specific task, and evaluate both on the task it designs on and another orthogonal task. All tasks are chosen from the recent NucleoBench
[
13
]
benchmark.
Our experiments indicate that AutoNovo-generated designers against NucleoBench tasks show successful optimization and favorable task generalization. The AutoNovo designers achieved the best observed mean performances even compared with human-designed baselines on 3/3 DNA design tasks, and 6/6 cross-oracle transfer tasks (design using model X, evaluate designed sequence on model Y). The most performant AutoNovo candidates are not the same across all tasks, motivating an analysis of what distinct algorithms the agent discovered, and future work that will discover a single designer superior in all contexts.
2
AutoNovo: Agentic program search for sequence designers
Given a problem description, a seed implementation such as the function signature, and a scorable objective, code optimization systems like AlphaEvolve
[
7
]
and ERA
[
3
]
rewrite candidate programs and evaluate them to iteratively make improvements. ERA uses a tree search with an upper-confidence-bound rule which decides candidates to expand and modify. Each rewrite is executed end-to-end; the resulting metric is read from the run, and search continues toward programs that improve it. The output is ordinary, inspectable code. In summary, the agent searches over programs that implement designers, where each resulting designer searches over biological sequences. AutoNovo therefore contains two nested optimization loops: ERA searches over programs that implement designers, while each generated designer searches over biological sequences.

In our initial experiments, we had ERA train and evaluate on a single task. For the 4 algorithms, with 2 seeds, we had 8 implementations. ERA based reimplementations of FastSeqProp and Ledidi were more performant than NucleoBench baseline implementations. The reimplementations of GrAdaBeam was not performant. On stack ranking them, we picked both seeds of FastSeqProp, one seed of Ledidi, and one seed of PEX where ERA was able to show substantial improvements.
Using the selected seeds, we ran five ERA searches. In four of them, the generated designer optimized sequences against one oracle, while ERA evaluated candidate programs using that oracle and one additional orthogonal oracle; the third oracle in the panel was used by neither and was reserved as a fully held-out evaluation task. The fifth uses both BPNet ATAC and ChromBPNet for optimization and scores both, leaving Enformer held out from the designer and from ERA.

5
What Algorithms Did AutoNovo Discover
Overall, AutoNovo discovered a family of optimizers that explicitly took advantage of time/compute budget and successfully blended strategies from other designers. Their most consistent ingredients are hard-sequence gradient optimization, explicit preservation of the best sequence, and relatively simple mechanisms for restarting search after temporarily slowing progress.
The best programs use a hybrid of continuous and discrete search.
Most successful designers optimize continuous sequence logits with gradients, convert those logits into discrete sequences, retain the best discrete sequence found, and perturb the continuous state when progress stalls. Every best observed mean in
Tables
2
and
3
comes from a FastSeqProp-seeded program. Eight of the nine winning table entries come from programs using a straight-through estimator (STE), which evaluates a hard one-hot sequence while passing gradients through a soft relaxation.
The strongest programs implement this common pattern in different ways. FSP-Best-Anchored STE, which performs best on direct ChromBPNet and ChromBPNet
→
\rightarrow
Enformer, periodically pulls its logits toward the best sequence found so far. FSP-gradient memory STE, which performs best on direct BPNet ATAC and ChromBPNet
→
\rightarrow
BPNet ATAC, accumulates gradient magnitudes and uses them to make guided jumps after stalling. FSP-sparse restart STE, which performs best on direct Enformer and both Enformer-origin transfer tasks, restarts around a sparsely mutated version of its best sequence. In each case, gradients guide the search through discrete sequence space.
Designers often performed best on the oracle pairs used during their search, and some generalized to other tasks.
One of the four transfer objectives used during ERA search is won by a program searched on the corresponding oracle pair: FSP-Best-Anchored STE for ChromBPNet
→
\rightarrow
Enformer. Both BPNet-origin directions are instead won by programs searched against BPNet ATAC and ChromBPNet together.
The generated program cannot query the orthogonal oracle directly, but ERA uses its score when selecting programs. This lets the outer loop favor algorithms whose sequences transfer even though the inner designer sees only its optimization oracle.
Two-oracle searches produced both BPNet-origin transfer winners.
Four designers were searched against BPNet ATAC and ChromBPNet together. “FSP-Ledidi-PEX annealed STE” has the best observed mean in BPNet ATAC
→
\rightarrow
Enformer, even though Enformer was queried by neither the designer nor ERA at any point in its search. This improvement transfers to an evaluation oracle absent from the entire program-search loop. The decoupling runs the other way too. “FSP-Ledidi-PEX two-phase saliency” has the weakest direct BPNet ATAC score of any AutoNovo designer, yet it wins BPNet ATAC
→
\rightarrow
ChromBPNet. Scoring well against the design oracle and producing sequences that survive an independent oracle are not the same objective, which supports this paper’s hypothesis that careful selection of
f
opt
f_{\mathrm{opt}}
and
f
orth
f_{\mathrm{orth}}
can improve generalization.
No program is best everywhere, but some programs transfer beyond the configuration in which ERA discovered them.
The best example of a generalizing designer is FSP-sparse restart STE
: ERA searched for it using ChromBPNet as the optimization oracle and BPNet ATAC as the orthogonal evaluator, yet it is the best program when Enformer is used for design. It also wins both Enformer-origin transfer tasks. This is evidence that ERA discovered an optimization strategy that transfers to an oracle and sequence length not used for its inner-loop optimization during search.
On Enformer (large model), memory-efficiency outperforms large candidate batches.
FSP-diverse batch STE generates a batch of roughly thirty candidates during discrete search. This designer performs second-best on BPNet ATAC
→
\rightarrow
Enformer. The same designer runs out of memory when Enformer becomes the design oracle, due to the longer sequences.
FSP-sparse restart STE takes the opposite approach. It follows a single STE trajectory, evaluates one discrete sequence at a time, checks candidates more frequently near the deadline, and uses sparse mutations after stalling. It is the strongest Enformer designer. The comparison suggests that under a fixed wall-clock and memory budget, candidate batching and evaluation frequency strongly determine scaling properties.
Different seed algorithms converge on similar mechanisms.
The Ledidi-seeded programs also moved toward the same continuous–discrete design. The Ledidi description given to ERA emphasizes an explicit
L
1
L_{1}
edit-distance penalty, but none of the four generated programs had one. Instead, they use the same general ingredients as the FastSeqProp-seeded programs: logits, Adam, STEs, best-sequence tracking, discrete mutations, and recovery after stagnation.
The seeds therefore acted as loose priors rather than constraints on the final algorithms. All seed families converged toward a similar set of mechanisms. This could mean that the benchmark strongly favors this hybrid design, that the language model has a strong prior for it, or both. The prompt also explicitly suggested adapting gradient use to task and runtime, so the broad idea of adaptive gradient use was supplied to ERA.
Strong scores did not imply clean or reliable code.
Several generated programs use sequence length as a proxy for oracle identity and change their use of gradients accordingly. One Ledidi-seeded program disables gradients on Enformer-length inputs and performs poorly there. Other programs contain unused controls, continue using stale gradients after switching away from gradient optimization, or include comments that do not match the executed condition. None sets random seeds. These defects do not prevent the program family from performing strongly, but they show why agent-generated scientific code still requires inspection, reproducibility checks, and targeted ablations.
6
Agent and Harness Design Observations
The following are strategies we found in our AutoNovo experiments to improve the ability of ERA to generate correct designers:
Ban
try
/
except
.
LLM-written designers often wrapped buggy code in
try
/
except
blocks, which propagated broken code. To get it to write code that worked and was written cleanly, our prompt forbids exception handlers, and the harness AST-checks the
Designer
class: any
try
with a handler receives the worst-case score. Crashes then surfaced and were scored as failures (correctly).
Seed with NucleoBench algorithms.
Initial prompts asked ERA to “improve a designer with gradient information”. While these worked reasonably fine, the performances were subpar relative to the top hand-crafted designer. Subsequently we included detailed descriptions of existing designers GrAdaBeam
[
13
]
, FastSeqProp
[
5
]
, Ledidi
[
11
]
, and Proximal Exploration
[
9
]
, each in separate runs which resulted in substantially improved performance. We also added the insight from NucleoBench that gradients help on some tasks (GATA2, ATAC) and hurt on others (JUNB, OTX1), possibly because they are uninformative or too slow. This information, along with a note to generalize helped the system match or exceed performance of the chosen original algorithm.
Pass the wall-clock budget and require that it be used.
NucleoBench evaluates designers on time, not step count. Results showed that algorithms which
see
the remaining budget outperform those that do not. The interface was adapted to accept
run(allowed_runtime_secs)
. The prompt states this explicitly and asks the designer to meaningfully use it.
Tell the designer that gradients are optional and costly.
Because evaluation is itself a time-bounded optimization, a backward pass that does not significantly improve performance is harmful. Prompts state that gradient usefulness varies by task and even by phase of a single run, and that a design goal is to decide
when
to use them.
Make failures expensive, and show how to take gradients.
Timeouts, crashes, and the
try
/
except
ban all map to a large penalty, to discourage them. Errors must be as informative as possible. Separately, the notebook includes working PyTorch gradient snippets for each oracle. Those cells are not the rewrite target; they exist so ERA does not spend generations on framework code.
7
Conclusion
This study explores whether agentic program search can improve nucleic acid design algorithms. Across three chromatin-accessibility oracles, an AutoNovo-discovered designer achieved the best observed mean on each of the three direct optimization tasks and all six cross-oracle transfer directions. Multiple AutoNovo designers also surpassed the strongest baseline on several tasks, although different generated programs performed best on different oracles. We also identified practical factors that improved ERA’s ability to generate useful designers, including providing strong algorithmic priors, exposing the available wall-clock budget, and allowing the designer to decide when gradients are worth their computational cost.
These results show that agentic program search can produce scientific optimization algorithms whose improvements can extend beyond the oracle pair and optimization configuration used during program discovery. However, the evidence remains limited to in-silico evaluation of one biological phenotype using three related predictive models, and cross-oracle transfer does not establish wet-lab validity. Future work should test AutoNovo on additional biological design problems, determine which algorithmic changes account for successful transfer, and evaluate whether cross-oracle improvements predict performance in biological experiments.
