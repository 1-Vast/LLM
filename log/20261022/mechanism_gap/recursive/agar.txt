 AGAR: A Reinforcement Learning Substrate
 for LLM Program Evolution 
 
 
 
 
 Haoran Li, Zengle Ge, Xiaomin Yuan, YUI LO, Haoxin Li, Songlin Zhou,
Qianhui Liu, 
 Jiahua Ying, Yuanhang Liu, Mingju Chen, Annan Li,
Jianmin Wu, Dawei Yin, Dou Shen 
 University of the Chinese Academy of Sciences  Baidu  Tsinghua University 
 Institute of Automation, Chinese Academy of Sciences  Shanghai University 
 
 

 Abstract 
    
 Given a task and an evaluator, a language model can rewrite a candidate program
while a search loop decides which rewrites survive — a practical route to
algorithm discovery. But that loop is governed by five constants set by
hand — which parent to select, how hard to mutate, how to keep diversity, what
to remember, and a scalar score that never says which part of the program earned
it — and reinforcement learning already has an estimator for each. The
obstacle is that program evolution is not usually written down as a decision
process. We
formalize it as a Markov decision process whose action is the  modular
prefix the model is conditioned on, not the program it emits , so that credit
assignment, value estimation, adaptive exploration and experience memory each
attach to a distinct component. AGAR ( Algorithm Generation As RL )
provides the substrate this licenses: any estimator can be replaced or switched
off without touching the controller, making the transfer auditable one mechanism
at a time, with no gradient training of the backend model. Across 19 tasks, two
backends and three seeds under one harness, AGAR improves on the stronger of two
published baselines on most tasks, with the gains concentrated on the
competitive-programming family.
The formalization also yields a checkable
reading of prior work: these systems are implicitly zero-discount, not by choice
but because fitness is exogenous to an individual rather than a return over
successors, leaving a discount factor nothing to act on. 
  
 
 
 
 
 
 
 
 
 
 
 1  Introduction 

 
 A long-horizon algorithm optimization task — find a program that scores well on a
task-specific evaluator, given a budget of iterations and no gradient of the
score with respect to the program text — is a sequential decision problem. It
is usually not  written down  as one. It is written down as an evolutionary
loop: maintain a population of programs, ask a language model to mutate or
recombine them, evaluate the offspring, keep what scores well, repeat
 ( Romera-Paredes et al., 2024 ;  Novikov et al., 2025 ;  Lange et al., 2025 ;  Sharma, 2025 ) . The
results are real: improved bounds on open combinatorial problems, faster kernels,
better heuristics. 
 
 
 The thesis. 

 
 We take the position that such a task  can be
modelled as an RL problem , and that doing so is not a re-labelling exercise: the
modelling choices determine which machinery is applicable, and the machinery then
determines the system. Concretely, we formalize the loop as an MDP whose action is
the  modular prefix  the model is conditioned on — not the program it emits
— and we show that under that choice each load-bearing idea of modern RL
 ( Sutton and Barto, 2018 )  attaches to a distinct component of the loop.
 M 1 M_{1}  (credit assignment),  M 2 M_{2}  (value estimation),  M 3 M_{3}  (adaptive exploration)
and  M 4 M_{4}  (experience memory) are the places the modelling says the estimators go.
We are deliberate about the strength of that claim: the formalization forces which
 kinds  of estimator the objective requires and whether each is an action
factor or retrieved context, but it does not force that there are four of them,
and the boundaries we draw between  M 1 M_{1} ,  M 2 M_{2}  and  M 3 M_{3}  are a factorization we
chose rather than one the mathematics uniquely picks out. What we contribute is a
 general evolutionary substrate  that carries this decomposition: an interface
in which any one of the estimators can be replaced or switched off without touching
the controller, so that the transfer is auditable one mechanism at a time. 
 
 
 
 The gap and the obstacle. 

 
 What the LLM contributes today is the
mutation operator. Everything that decides  where to mutate, how hard, and
what to remember  is a hand-set constant: five decisions, each with an estimator
RL already has. The obstacle is not reward density — RL routinely operates under
terminal-only reward, and LLM-driven program evolution does receive intermediate
signal which the mutation operator consumes. The real difference is structural. In
RL the value of a state is defined  recursively  over its successors, so
terminal credit is propagable in principle. In evolution, fitness is an
 exogenous property of an individual ; no Bellman equation relates a parent’s
fitness to its children’s, so there is no recursion to propagate along at all. We
make this precise in § 2.1 . The formalization below makes the
recursion  definable  over the search without claiming to make the backup
 empirical : the value it recurses on is estimated in text space rather than
learned from observed returns, and that boundary stays exactly where it is. 
 
 
 
 A checkable reading of prior work. 

 
 Because the action is a prefix
conditioning a frozen black-box model, the objective is
 J ⁡ ( π ) = 𝔼 ⁡ [ ∑ t γ t ​ r t ] + λ ​ H ​ ( π ) J(\pi)=\mathbb{E}[\sum_{t}\gamma^{t}r_{t}]+\lambda H(\pi) .
Setting  γ = 0 \gamma{=}0  recovers the selection rule every system in this literature uses
(Observation  1 ): immediate fitness plus a population entropy term.
This is not a metaphor but a degeneracy — and not a criticism, since without a
recursion a discount factor has nothing to act on. Making the recursion definable
is what turns  γ \gamma  into a tunable knob. 
 
 
 
 A substrate, not a system. 

 
 The substrate (§ 5 )
carries the transfer: interchangeable modules, interchangeable execution backends,
native asynchrony. Its engineering problems are those of asynchronous RL
post-training stacks  ( Luo et al., 2025 ;  Zhu et al., 2025 ;  miles Contributors, 2025 ;  Hou et al., 2026 ) ; the
optimand differs (text, not weights) and there is no gradient. 
 
 
 
 Contributions. 

 
 
 1.  
 
 A modelling of algorithm optimization as RL and the substrate it
licenses  (§ 3 ). Action-as-prefix makes five RL tools
expressible in text space, each replacing a named fixed rule in a specific module.
The  γ = 0 \gamma{=}0  degeneracy falls out of the same formalization. The contribution
is an  interface  auditable one mechanism at a time, not a uniqueness result. 
 
 2.  
 
 Modular TextGrad: policy improvement in text space 
(§ 4 ). Each module’s persistent  guidelines  — the
text-space analogue of policy weights — are optimized without gradient training.
We report a measurement of the operator: a local-edit and validation-revert design
that replaces the original rewrite operator (§ 4.2 ). 
 
 3.  
 
 Asynchronous execution and the credit-assignment problem it creates 
(§ 5.2 , § 5.3 ). The streaming scheduler creates
staleness: credit is assigned against a population that no longer exists. We
characterize  τ \tau  empirically (naive  τ ≤ W − 1 \tau\!\leq\!W{-}1  is refuted in practice)
and relate it to asynchronous RL post-training  ( Hou et al., 2026 ) . 
 
 
 
 
 
 
 2  Background: Two Independent Lineages 

 
 Evolutionary computation searches by maintaining a population, perturbing it, and
keeping what scores well. Genetic programming applied this to program spaces
decades ago  ( Koza, 1992 ) ; the LLM era replaced the syntax-tree mutation
operator with a language model, which is what made the approach competitive on
real algorithm-design problems  ( Romera-Paredes et al., 2024 ;  Novikov et al., 2025 ) . Later
systems differ in how they manage the population — ShinkaEvolve adds a bandit
over LLM backends and novelty sampling  ( Lange et al., 2025 ) ; SMC-based
variants replace generational selection with sequential Monte Carlo resampling
 ( Jiang et al., 2026 ) ; EvoX makes the search strategy itself the object of
evolution  ( Liu et al., 2026 )  — but they share the  structure  of the signal.
Fitness attaches to a completed individual, not to a step of a trajectory, and
intermediate information informs the  generation  of the next candidate
without ever accumulating into a return. The search state — which lineages are
productive, which regions are exhausted — is therefore carried implicitly in the
population rather than estimated. 
 
 
 Reinforcement learning developed a different toolkit because it assumed a
different structure, a trajectory over which value is recursively defined: credit
assignment propagates outcome information backwards along it  ( Sutton, 1988 ) ;
value estimation predicts return before it is observed  ( Mnih et al., 2015 ) ;
adaptive exploration makes the explore/exploit trade-off a decision rather than a
constant  ( Auer et al., 2002 ;  Garivier and Moulines, 2011 ) ; entropy regularization turns
diversity into an objective term  ( Haarnoja et al., 2018 ) ; and experience replay
makes the run’s history a learnable resource  ( Lin, 1992 ;  Schaul et al., 2016 ) .
Our five transferred tools are these five, and § 3.3  states what
each had to become. 
 
 
 2.1  What actually separates them 

 
 It is tempting to say that RL has dense reward, evolution has sparse reward, and
that this is the obstacle. That is inaccurate in both directions: RL routinely
operates under terminal-only reward, and LLM-driven program evolution does receive
intermediate signal which the mutation operator consumes. The real difference is
structural. In RL, the value of a state is defined recursively in terms of its
successors, and terminal credit is in principle propagable along that recursion via
returns or TD( λ \lambda ) — sparse reward makes this  statistically  hard,
but the problem stays well-posed. In evolution, fitness is an  exogenous
property of an individual ; a child is not a successor state reached by acting in
the parent’s state but a new object emitted by a stochastic operator, and no
Bellman equation relates a parent’s fitness to its children’s. There is therefore
nothing to back up  along , which is why evolutionary search assigns credit
by  survival  rather than by attribution. 
 
 
 The formalization of § 3  supplies the missing
 structure : by defining the action as a prefix and the transition as one
generation step, it makes a Bellman recursion well-posed over the search. It does
not supply the missing  signal : our  V M 2 V_{M_{2}}  is an estimate produced by a
text-space heuristic, not a value learned by backing up observed returns. What
 is  live is the forward half — the estimate computed at dispatch —
through two channels active in every reported run: the  M 3 M_{3}  selection rule
 f ⁡ ( p ) + γ ​ V ​ ( p ) f(p)+\gamma V(p)  and the  M 2 M_{2}  lineage ranking. So: 
 We make the recursion definable. We do not make the backup empirical. 
 This also explains Observation  1 : prior systems are  γ = 0 \gamma{=}0 
not because their designers chose greediness, but because without a recursion a
discount factor has no successor value to act on. 
 
 
 
 2.2  Positioning 

 
 The recurring distinction between AGAR and the closest prior systems is that a
rule which is fixed elsewhere becomes a learnable, replaceable component here
(Appendix  D.6  gives a row-by-row comparison). A parallel line of
work builds substrates for applying RL to agents at scale
 ( Luo et al., 2025 ;  Zhu et al., 2025 ;  miles Contributors, 2025 ) , together with
asynchronous post-training systems such as SAO  ( Hou et al., 2026 ) . These are our
closest methodological relatives: they share our engineering problems —
decompose the loop into independently swappable components, make rollouts
asynchronous, bound the staleness that asynchrony introduces — but in every one
of them the learnable object is a set of model weights updated by a
policy-gradient estimator, whereas here the model is frozen and the learnable
object is the  text  that conditions it.

 We model one evolutionary step as a transition in an MDP

 State  s t s_{t}  is mixed-granularity by necessity: an individual-level part
(the parent program, its fitness, its lineage, its age, its mutation history) and a
population-level part (fitness statistics, a diversity measure, budget progress and
remainder). Both are required — credit assignment and value estimation are
questions about an individual, exploration and entropy about a population — and
neither subsumes the other: a purely individual state cannot express “the
population has converged”, and a purely population-level state cannot express
“this lineage has stalled”. 
 
 
 Action  a t a_{t}  is a modular prefix, not a program.  This is the load-bearing
choice of the formalization. It is tempting to call the generated program the
action, but the program is sampled from a frozen black-box LLM: it is a
 product of the transition , not something the search policy emits. What the
policy emits is the text that conditions that sampling, so we define

a text-emitting object improvable without touching model weights
(§ 4 ), and the module boundary is fixed by which factor of  a t a_{t}  a
component writes rather than by taste.

The third is  pluggable , which is where value-guided selection enters

 Observation  1  is an algebraic identity, not a metaphor, and it is
the cleanest reading the formalization gives us of the prior art:  γ \gamma  is a

 We read this as a consequence of § 2.1  rather than a shortcoming
of prior work. A discount factor needs a successor value; absent a recursion over
the search there is none, so  γ = 0 \gamma{=}0  is the only setting available. What
§ 3.1  contributes is not a better choice of  γ \gamma  but the structure
that gives  γ \gamma  a referent at all — with the honest counterpart that the

observed returns. 
 
 
 
 3.3  The transfer 

 
 Table  5  in Appendix  D.7  is the centre of the
paper. Each row names an RL tool, the evolutionary fixed rule it displaces, the
module it becomes, and — most importantly —  what had to change  given
the absence of an empirical backup (§ 2.1 ). 
 
 
 We stress the direction of derivation. We did not choose four modules and then
find RL names for them; the four factors of  a t a_{t}  in Eq. equation  1  plus
the retrieved context  M 4 M_{4}  are what the transfer produces, and the fact that
 M 4 M_{4}  is  not  a factor of the action — it is context — is a
consequence of the formalization rather than an implementation detail. 
 
 
 Instantiations. 

 
 A choice of implementation for each of  M 1 M_{1} – M 4 M_{4}  defines a point in a
configuration space (§ 5.1 ). Throughout the paper we report
two such points,  Base  and  Combo , differing in the  M 2 M_{2} 
estimator and the  M 3 M_{3}  decision rule (statistical vs. LLM-based; rule-based
vs. discounted-UCB). They are sampled points, not competing systems; we do not
argue for one over the other. 
 
 
 
 
 3.4  Critic independence, and what it forces 

 
 Each module is improved against its  own  critic, which judges only whether
that module’s output was correct on its own terms — was the attribution
consistent with the observed lineage? did the predicted ranking match the realized
ordering? — and never attempts to apportion final fitness across modules. The
reason is structural: all four outputs are concatenated into one prefix
(Eq.  1 ) and consumed jointly by a black-box LLM, so their
contributions to the resulting program are not separable from the inside. This has
a design consequence: which transferred tool carries the gain can only be answered
by external leave-one-out ablation, not from inside the system. We do not report
that decomposition: at  n = 3 n{=}3  the level-to-level differences of
Table  2  already sit inside the noise. See
Appendix  D.1  for the full module data contracts. 
 
 
 
 
 4  Modular TextGrad: Policy Improvement in Text Space 

 
 Section  3  defines what we optimize. This section defines
how: the method is TextGrad  ( Yuksekgonul et al., 2024 )  applied to a target its original
formulation already fits — an objective with no analytic gradient, computed by an
external system, over a variable that is itself text. The frozen backend model
writes code; each module’s  persistent guidelines   θ i \theta_{i}  are the
variable being optimized; the loss is  r ^ \hat{r}  of § 3 ; and
the “gradient” is the rollout context shown to the LLM critic. Appendix  D.5 
gives the full operator definitions and the RL-to-text correspondence table. 
 
 
 Two features of our instance are unlike the tasks TextGrad was demonstrated on.
First, the variable is  modular : the policy is a concatenation of per-module
guidelines, so the gradient must be taken per module and a critique that conflates
them is unusable. Second, the loss is measured over a  period  of noisy
evolutionary steps rather than a single forward pass, so the update rests on a
small-sample signal and must decide what to do when that signal is inconclusive.
The second feature is what § 4.2  is about. 
 
 
 4.1  Operators 

 
 For each module  i i  we define a per-module textual gradient operator  G i G_{i}  and a
shared update operator  U U  (full definitions in Appendix  D.5 ).
The object  θ i \theta_{i}  is the module’s  persistent guidelines : a block of
text that survives across evolutionary steps and conditions every subsequent
invocation of that module — not the module’s per-step output, which is an action,
not a policy parameter. Optimizing the output instead of the guidelines would fail
to persist and therefore cannot constitute policy improvement. 
 
 
 
 4.2  What we measured, and why the operator was replaced 

 
 The rewrite operator — critique in, new guidelines out, unconditionally — is
the direct transposition of TextGrad to this setting. Two measurements over 206
runs (9,844 update pairs) forced its replacement.  (i) The variable was
resampled, not improved : the guideline block hit its 2000-character budget at the
 first  update of every run and stayed there; textual similarity between
adjacent versions was 0.18, between first and last 2–6%, without exception.
 (ii) Nothing closed the loop : a rewrite that made things worse persisted
until the next rewrite replaced it, so there is no mechanism by which  θ i \theta_{i} 
at step 100 should beat  θ i \theta_{i}  at step 1. 
 
 
 The repaired operator  replaces  U U  with a local edit plus deferred
validation. The policy is an explicit numbered rule list;  G i G_{i}  returns at most
one  ADD  and one  EDIT / REMOVE  per period
( NONE  is an expected answer); validation is deferred  verdict_lag 
periods because a new rule’s children are mostly leaves at install time, making
immediate scoring equivalent to  γ = 0 \gamma{=}0 . Cost falls from  8 8  to  2 2  LLM
calls per update (only  M 1 M_{1}  and  M 4 M_{4}  are edited; the other two were writing
guidelines no code path read). The budget is bounded by construction, and the
operator became legible: discrete rules with provenance can be reported at run end,
which the rewrite operator made impossible. Full measurement detail is in
Appendix  D.5 . 
 
 
 
 
 5  Substrate: Extensibility and Asynchronous Execution 

 
 A modelling choice only becomes a system if the interfaces it implies are real.
This section describes the two properties of the substrate the transfer actually
depends on — replaceable components and native asynchrony — and one problem
the second creates for the first. We develop the asynchronous part against the
closest engineering precedent, the asynchronous RL post-training systems surveyed
in § 2 .

 any  completion, dispatch a replacement immediately — with the controller
as sole writer of the population and the  W W  in-flight rollouts reading a
dispatch-time snapshot and writing only their own trajectory. The four pipeline
stages ( select ,  generate ,  evaluate ,  judge )
are the substrate’s; the replaceable modules sit in the  select  slot.
Shared resource pools are acquired per use and returned. Bottom: the same loop
in the three moments used throughout this paper, with  τ \tau  defined as the
population-version difference between dispatch and landing. 
 
 
 5.1  Extensibility, stated so that it can be checked 

 
 “Extensible” is easy to assert, and every substrate paper asserts it. We give
three measurable forms. (a)  Configuration space : the choice of
implementation for  M 1 × M 2 × M 3 × M 4 M_{1}\times M_{2}\times M_{3}\times M_{4}  spans 180 configurations,
of which we have evaluated 14;  Base  and  Combo  are two of those
points. (b)  Integration cost : replacing  M 3 M_{3} ’s LLM explore/exploit call
with the discounted-UCB bandit of  Garivier and Moulines (2011)  added 236 lines in one
new module file and changed 0 lines in the controller or the module protocol —
and  deleted  26 lines of hand-written budget and stagnation heuristic that
the discounting subsumes. That deletion is the part we would point to: the claim
is not that new mechanisms are cheap to add, but that adding a principled one can
remove a hand-tuned constant. 
 
 
 (c)  Interchangeable backends , and a non-obvious cost. Backends register
through a single entry point and can be swapped between a thread pool and a
distributed runtime. During development this produced a failure worth reporting:
under the distributed backend, per-task serialization gives each rollout an
isolated module instance for free, while under the thread-pool backend a shared
evaluator instance guarded by an environment lock caused rollouts to be
 silently serialized  — no error, no warning, and worse the longer each
evaluation takes, i.e. exactly on the workloads where concurrency matters most.
The fix was explicit per-task isolation of module state. The general lesson is
that  extensibility is not freedom; it is an obligation on the interface to
state its isolation semantics . An interface permitting a backend swap without
specifying whether state is shared has not made the system extensible, only
replaceable. Appendix  D.9  gives the integration diff in full. 
 
 
 
 5.2  Asynchronous execution 

 
 The scheduler is streaming rather than generational: it fills  W W  in-flight
rollouts, waits for the first to complete, folds the result into the
population, and immediately dispatches a replacement. There is no batch
barrier, so a single slow evaluation delays one slot rather than the whole
generation — which matters here because per-rollout times across the tasks we study
span  3.7 × 3.7\times  (median  269 269  s on the fastest task against  1007 1007  s on the
slowest), so a straggler holds a slot for several times the median. As an engineering decision this needs no
justification: it is what every production RL stack does, and the reasons are
the same. 
 
 
 The interesting part is what the asynchrony does to the  learning rule ,
and it is here that the evolutionary setting diverges from the RL one. 
 
 
 Comparison with asynchronous RL post-training. 

 
 The asynchrony forces single-rollout consumption, which is the native form for
evolutionary rollouts (each offspring is scored against the population, not against
siblings) rather than a concession. SAO  ( Hou et al., 2026 )  reaches the same design
from the post-training side; Appendix  D.9  details the two
further points of contact that look like correspondences but are not. 
 
 
 
 
 5.3  Staleness: what asynchrony does to credit assignment 

 
 The dispatch path samples a parent, computes the  M 2 M_{2}  estimate, and runs the
 M 3 M_{3}  decision  at dispatch time ; the resulting fitness lands some number
of population updates later. Call that gap  τ \tau , so  τ ≡ 0 \tau\equiv 0  is the
synchronous case.  τ \tau  has  no  a priori upper bound: because the
scheduler is streaming, a slow rollout can outlive an arbitrary number of faster
ones, and  τ \tau  is bounded only by the tail of the evaluation-time distribution.
Bounding it at  W − 1 W{-}1  would require the generational synchronisation we rejected
for throughput. We therefore characterise  τ \tau  empirically rather than
bounding it; the measured distribution is in Appendix  D.4 , where
at  W = 8 W{=}8  the maximum is  22 22  against a naive bound of  7 7 . 
 
 
 The consequence connects to Table  5 : credit is assigned against
a population that no longer exists.  M 2 M_{2} ’s baseline statistics are  τ \tau  updates
old;  M 3 M_{3} ’s selection rule consumes a value estimate computed against a
superseded population;  M 4 M_{4} ’s novelty distances are computed against a stale
population; and the Meta layer consumes a rollout buffer produced under
superseded guidelines — which is precisely the sense in which
§ 4 ’s operator is off-policy. The standard correction does not
transfer: SAO’s clipped importance ratio needs the two policies to be comparable
 per token , and our “policy” is a block of natural language that an update
may replace wholesale. A clipping-style correction would require first defining a
distance between two texts and arguing that it bounds a likelihood ratio, and we
have no such argument. We report the delay instead of correcting it.

 7  Discussion 

 
 What the transfer does and does not establish. 

 
 The formalization of § 3  buys three things: a precise sense
in which the prior art is a special case (Observation  1 ), a
factorization of the loop into modules that the objective constrains but does not
uniquely determine, and a vocabulary in which mechanisms from the RL literature can
be stated, implemented and compared inside an evolutionary loop. What it buys, in
one sentence, is that the Bellman recursion becomes  definable  over
evolutionary search. What it does not buy is an  empirical  backup: the value
the recursion consumes is estimated in text space rather than learned from observed
returns. The two data-backed limitations and the full unverified list appear in
Appendix  D.8 . 
 
 
 
 Future work. 

 
 The most direct next step is wiring the TD correction into the loop, turning  M 2 M_{2} 
from a one-shot estimator into a learned one.
Beyond that: importance correction for staleness  ( Hou et al., 2026 ) ;
cross-model critics; leave-one-out module ablation at larger  n n ;
standardizing the  V V  scale so  γ > 0 \gamma{>}0  can be tested cleanly; and using
the 180-configuration space of § 5.1  to ask which regions of
mechanism space are worth exploring — a question that only becomes askable once
mechanisms are interchangeable.

 D.8  Limitations (full list) 

 
 
 •  
 
 Per-module attribution is unresolved.  The substrate ladder
(Table  2 ) reports end-to-end gain but no leave-one-out
decomposition of the four transferred modules; which of  M 1 M_{1} – M 4 M_{4}  carries the
gain is open. 
 
 •  
 
 M 2 M_{2}  is an estimator, not a value function.  It is not trained
against realized descendant fitness, so the  γ ​ V M 2 \gamma V_{M_{2}}  term carries whatever
bias the text-space heuristic has, with no mechanism to correct it over the run. 
 
 •  
 
 V V ’s “orthogonality” is partly self-inflicted.   V V  correlates
negatively with fitness, which we read as carrying information fitness cannot see;
but  V V  is also what selects parents, and those descendants’ gains are what define
 V V . The correlation is in part manufactured by the selection rule itself. 
 
 •  
 
 γ \gamma  only discriminates among individuals with descendant
evidence.   lineage_return  carries a horizon: programs born within the
last horizon iterations score  V = 0 V{=}0  and the ranking tie-breaks back to fitness,
so  γ \gamma ’s discriminative power applies to  older  individuals. 
 
 •  
 
 Unequal LLM budget.  At matched evaluations we spend
 2 2 – 4 × 4\times  the baselines’ calls; we report no LLM-call-matched arm. 
 
 •  
 
 TextGrad has no convergence guarantee , and its measured effect is
confounded by the redundant signal path identified in § 4 . 
 
 •  
 
 M 2 M_{2}  bootstrapping.  The estimator calibrates itself with its own
estimates; we observe no divergence but offer no argument that it cannot occur. 
 
 •  
 
 Critic and module share a backend model , so self-evaluation blind
spots are possible; a cross-model critic is left to future work. 
 
 •  
 
 Scope.  3 seeds support qualitative conclusions only; 2 backend
models; main runs are single-worker. 
 
 •  
 
 Baseline fairness.  Baseline systems are ported by us; our ports
are released so the conditions can be checked independently. 
 
 
 
 
 
 D.9  Extensibility case study 

 
 The integration reported in § 5.1 (b) replaces  M 3 M_{3} ’s LLM
explore/exploit decision with the discounted-UCB bandit of
 Garivier and Moulines (2011) . The arms are  exploit  and  explore ;
on each update every arm’s discounted pull count and reward sum decay by a
factor  g g  before the played arm is credited, and the decision is
 arg ⁡ max a ⁡ s a / n a + c ​ log ⁡ ( N + 1 ) / n a \arg\max_{a}\,s_{a}/n_{a}+c\sqrt{\log(N{+}1)/n_{a}} . Cold start plays the
least-pulled arm until both have at least one discounted pull. 
 
 
 The diff is 236 lines in one new module file. The new class subclasses the
existing  M 3 M_{3}  and overrides parent selection; it preserves the output contract
exactly ( result.selection  plus the  m3_prefix  and
 m3_decision  metadata of Appendix  D.1 ). Neither the
controller nor the module protocol is modified: the substrate contains zero
references to this mechanism, and it is selected by one configuration key. 
 
 
 Integrating it also  deleted  26 lines — the hand-written budget and
stagnation decay heuristic that the discounting subsumes. That deletion is the
part we would point to: the claim of § 5.1  is not that new
mechanisms are cheap to add, but that adding a principled one can remove a
hand-tuned constant, which is the same claim the paper makes about the transfer
as a whole. 
 
 
 We note the limit of this case study honestly. The bandit is off by default and
is not used in any reported run (§ 7 ), so what this
demonstrates is that the interface admits the mechanism at the stated cost —
not that the mechanism helps.
