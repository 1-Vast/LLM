# API提案独立审查：2×2交互差分约束与规则继承

2026-10-22。实际阅读api/RESPONSE.md，未读取root或skeptic本轮API评语；不打开ALMANAC旧响应或reserve，不开展实验。**结论：NO_CORE_PROMOTION / STOP当前创新主张。** 它有清晰的标准约束学习表达，但尚未给出与忠实ordinary counterpart不同的操作，也没有可支持功能或RSI保证的证书。

## 差分可识别性和真实观测合同

完整b=y11−y10−y01+y00需同一可比较背景、剂量、测量尺度的四格。只保留“一条干预差分”不能识别交互；例如缺y11时，任何b都能通过改变未观测y11得到。同样，只有单药剂量阶梯不等于两个可组合干预；不能把Jurkat同一药物两个剂量直接解释成g和h的独立组合。

ALMANAC已有同背景组合网格和匹配单药，但API尚未说明用哪一种四格：内部两个药剂量各二level需要四个组合条目；单药/组合边界四格则还需vehicle基准、合法单药与组合。vehicle不是凭空0；若使用作者growth归一化后vehicle=1，是明确的归一化约定及共享测量依赖，不是额外独立实测值，也不能在原始OD或负增长计算语义下无解释地替换。真实四格单位、允许揭示集合、noise与控制成本未冻结。不得为此打开后20cell，或把四个组合揭示仍计为原B1一次anchor。

g,h在这里是同时组合的因素，四格混合差分测量非加性；并没有观测g后h与h后g两个干预顺序。因而“交换证书”不能解释成干预交换性、动力学组合或因果可交换的认证。

## 证书究竟保证什么

若四格预测fij再加任意主效应ui+vj，交互差分不变。故交互约束对这些加性方向没有识别力；一个在所有格上整体偏移的大误差模型与原模型可共享零违规证书。更一般地，药物行/列主效应可以改变剂量面误差与部分功能排序而不改变b。固定六单药可约束某些边界值，但除非提案指定完整规则、边界与可识别条件，不能用它消除所有未约束模式。

因此“证书通过”只说明**被测交互差分**在epsilon范围；不保证绝对growth、未测组合、跨细胞迁移、药对排序或生物机制正确。四条标签压缩成一个约束还舍弃了三个线性方向的信息；计算/测量更省不是自然成立。WM预测b与b本身的偏差可以相关于面误差，也可以无关；Spearman正相关不是一个功能保证，更不是创新必要证据。

epsilon需要独立noise/容差合同，不能先见违规就放宽以使继承通过。“不可行放宽epsilon”若没有固定代价和停止规则会让证书失去否证能力。真实实验误差有共享vehicle/plate协方差，四格差分并不天然更低噪声。

## 忠实普通对手与简洁性

若规则对参数r线性，bhat=Ar，则提案就是最接近r0的二次规划，约束为|Ar−b|≤epsilon；这是标准带线性不等式的约束最小二乘/最小范数更新。若规则非线性，低维不自动使全局投影易解，也未定义优化器、唯一性或证书计算。不能把一般MSE梯度重训当唯一对手，再声称投影不同即创新。

忠实counterpart应首先是**同一规则表示、同一r0、同一四格、同一epsilon、同一最小改动目标与硬约束求解器**；该标准程序逐步执行相同操作。其次才比较直接ridge/RBF联合四格监督、约束加soft loss、普通元学习/在线最小二乘。API提出的低秩适配+辅助loss并不是最强忠实同操作对照；硬约束与soft loss有差别，但这不把硬约束本身变成新算法。现没有给出一个新计算、目标或信息优势。

覆盖表+bandit选高冲突/未覆盖模式属于常规主动约束选择/组合bandit，需要定义真实效用与探索预算；不是仅因继承一张表就出现递归改进。固定强bandit、后验更新与等预算约束搜索必须获得同一完整历史与模式标签。

## 继承和RSI审查

“零反馈不更新”只是无操作合同，不是继承收益。第二轮达到某违规率的反馈更少，可能因第一轮已覆盖这些模式、初始规则更好、任务更容易或证书容差变宽。要证明改进策略更有效，应从相同fresh模型/规则与初始archive出发，只替换旧/新改进策略，在独立后续任务、相同全成本与反馈条件下比较。现提案没有该控制，且降低交互违规率仍不是药物功能效益。

## 决定

不建议为该提案重启ALMANAC或Jurkat数据资格/新实验。需要支持者先给出一个不能被上述标准约束投影与主动学习同操作表达的具体差异，以及为什么该差异保留有用功能信息的可证伪主张；当前文本没有。这个否定针对所写算子，不是因为“属于meta-learning家族”就笼统否决，也不是声称所有interaction约束无价值。

保留的有用点只是研究合同提醒：交互识别需要真实同背景组合信息；证书目标与药物功能目标应分离；任何改进器比较须common-start。它们不能替代一个新核心机制。现阶段完整目标ACTIVE / NOT_ACHIEVED。
