## Capability is distinguishable; novelty is a separate claim

An improver I1 may be a conventional learned optimizer and still demonstrate genuine operational improvement-of-improvement over I0. Code self-editing is unnecessary. The measurable claim is that from identical new model/program starts and initial history, I1 finds better future interventions/update programs under the same finite resource cap. This must not be inferred solely because I1 itself scores better at the downstream task or has inherited a better already-fitted model.

Let Q(I,z,B) be terminal or predeclared anytime utility of the best independently evaluated downstream program discovered by improverI, starting from common(z.model,z.archive), after charged search budgetB. The capability claim is E[Q(I1,z,B)−Q(I0,z,B)]>δ on independent later task families. This is not automatically true when U(I1)>U(I0). Source inheritance must be isolated from carrying a better incumbent: fork improver checkpoints while resetting the downstream model and initial archive. If knowledge is encoded inside an improver, that is allowed inherited capability, but the control gets the same external source traces and opportunity to learn its own proposer. We cannot demand both policies be internally identical and then ask for an advantage.

A faithful ordinary counterpart can use contextual bandit/Bayesian program optimization over the same executable update/search actions, with the same legal contexts, observations, source traces, derivative availability and parent archive; fit its proposal policy on source data and freeze before later tasks. Include fixed-base code-editor archive search faithful to DGM's no-self-improvement baseline. If the candidate's only operation is a specified coefficient update identical to bilevel learned optimization, this counterpart must implement that operation rather than handicapped random search. Exact equality of operations precludes algorithmic novelty for that literal rule; membership of the same broad family alone does not.

## Finite resource advantage must be nontrivial

Charge all source acquisition, candidate construction, evaluations, failed programs, retraining, validation and later deployment; wet-assay bundles and GPU/APIcost are separate resources, not interchangeable nominal calls. A finite-budget gain may come from a demonstrably better proposal distribution or cheaper informative evaluation, but comparator savings can fund more candidates. Same number of iterations or same nominal APIcalls does not suffice.

For amortized costs at matched utility, if source training costsCtrain and a later task savesΔc>0, break-even requires NΔc>Ctrain. No finite N rescues a claimed savings whenΔc≤0. This accounting identity is not a new algorithm or empirical result; it prevents claiming free inherited search. Under matched total cap, compare an ordinary control that spends its unused source budget on source learning or later search, with the allocation frozen before outcomes. A source-trained improver need not beat every possible optimizer, but must beat these explicit competent counterparts and useful-gain margins.

A valid RSI result would show checkpoint1 improves future search efficiency over checkpoint0 at common starts, beyond a fixed learned optimizer given the same traces, on independent later real functional task families; then updated checkpoint2 must improve this ability again if recursive progression is claimed. A single optimizer meta-training curve or selected best program is insufficient. The broadworld/agent/inheritance factorials are still needed separately; this narrowtest cannot replace them.
