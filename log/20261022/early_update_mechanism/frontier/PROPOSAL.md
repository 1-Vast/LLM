# 独立提案：分子反馈的梯度传送更新器；当前不晋升独特核心

2026-10-22，frontier_distinct。独立稿；未读本轮其他代理原稿。只读现有晚期 DECISION.md，没有打开新生物量、任何保留背景或新标签。实际公开请求、原文和哈希见 source/；失败见 FAILURES.md。以下给出一个明确操作而非候选菜单，并说明为什么当前尚无合格创新核心。全文下载不等于全文逐页审读：本稿逐段检查的是所引方法、限制和算法段。

## 1. 应用、数据与唯一候选

应用限定为新细胞背景中的低功能反馈预算药物注释排序。源背景具有药物、6h蛋白、作者 Efficacy；新背景每轮按预固定化学分组顺序取得一个药物的6h蛋白，功能标签随后到达。预测未查询药物时不给其真实蛋白。若全队列6h已测，则应另名为实测早期状态给定的更新任务，并向所有直接模型提供这些输入，不能混用两合同。

已有源资产是旧 PTPC17谱系的已暴露开发数据；HCT116已有6/24h与标签也属于开发。A375和三个后续背景保持未开。本提案只说明潜在数据合同，不申请或执行打开它们。S8没有0h，不能构造已观测初态或完整细胞轨迹；作者标签时间/剂量/阈值仍未认证。可以研究“药物条件化早期状态模型”的更新，不可据此宣传已验证动态细胞世界模型或前瞻药效。

唯一候选是**把分子反馈变成一次功能有利的参数更新，继承并继续训练该更新器**，而不是对实测状态残差做核传播。设源训练模型 `z_hat=F_theta(c,d;a)`，`y_hat=h_psi(z_hat,c,d)`；`a`是固定、源定义的8维背景适配坐标，初始0。源输入预处理、低维蛋白基、参数方向和功能头在每个外层训练源内确定。

给新6h反馈 `z_s`，计算

`g_m = grad_a L_m(F_theta(c,d_s;a), z_s)`，

`U_P(a,z_s) = a - eta P g_m`，`P = diag(softplus(v)) + B B^T`，`B`固定为8×2。

`L_m`只在实际观测蛋白坐标计算；缺失不作零。P不是根据目标标签现场选的动作，而是源任务训练的一个共享正定预条件器。在源背景上构造严格分离的支持/查询药物组，训练 P 的唯一目标是**分子更新之后，功能查询损失下降**：

`P* = argmin_P mean_e L_f(Q_e; U_P(0, S_e^m)) + lambda ||P-I||_F^2`。

功能反馈到达后，用本次更新前保存的状态、支持和已封存的一个后续查询组计算一次同类超梯度，得到 `P_next`；只继承 P，不跨背景继承 a。禁止用最终测试查询回写 P。若没有独立后续功能查询，不执行该次改进器更新，更不能用训练支持损失假冒 G 的改进证据。所有步骤都是有限维、可微且可在maestro执行，不要求对DeepSeek提供方权重进行不可用的微调。

与普通重训的操作差异是：P按跨药物的**后更新功能损失**学习，而非在当前分子/功能支持上直接优化同一训练目标。与原锚定残差式差异是：不存在实测24h、独立功能GP或两步三角条件化的残差读出；更新进入共享预测路径。它也没有梯度冲突权重或旧保存动作菜单。

## 2. 可证伪主张与最小分解

唯一值得测的机制假说是：跨背景可复用的几何，能把丰富分子反馈指向有用的功能参数方向，从而在同功能标签预算下优于普通分子梯度更新和强直接更新。不能从晚期融合FAIL推出它应当成立；早期E在一个开发背景的有限正向排序线索也没有证明这种梯度可迁移。

最低 U1/U0：同一初始 F/h、同一支持/查询、同一一次反向传播预算，U1用源训练P，U0用I；同时必须有源内调过步长的普通SGD/Adam、完全重训、同容量无状态预测的直接网络、使用相同状态监督的联合模型，以及源训练的普通低秩元优化器。U1若只击败未调步长U0，没有贡献。

最低 G1/G0：从相同 P* 开始，在相同前序任务反馈与预算下，G1按上述后更新查询超梯度更新P，G0保持P*；随后在另一个任务从相同a=0执行同样U，比较后续任务适应收益。G0还应包括复制源上最好的完整P、普通继续元训练、同预算随机/程序搜索。G1训练损失下降不是G1胜出；P*胜I也不是改进策略进一步改进的证据。

世界模型/直接预测贡献必须另做2×2：F带早期状态预测监督 vs 无该监督且等参数/源信息预算的直接模型；固定更新器 vs 学习P。继承收益是任务间保留P vs 每任务重置；智能体贡献要有自适应实验/程序修改才成立，本最小机制没有LLM行动选择，故不能计智能体成功。支持顺序固定，以免把主动学习收益混入更新器。任何后续主动版本都要补同信息主动、简单混合和等总预算程序搜索。

建议最小数学停止条件：若U可由一个普通源训练预条件元优化器逐步精确复现，则不作为独特更新机制晋升；性能比较仍可有实用价值。若后续生物协议另行获批，必须事前锁定独立任务、主指标、预算和有实际成本含义的门限；本稿不伪造临床margin，也不把已经开发暴露的HCT116化学折称背景外确认。

## 3. 为什么当前不晋升：有一个具体普通实现

这个候选的“实测分子反馈 → 参数梯度 → 源训练P → 后查询损失 → 超梯度更新P”恰好是一个普通的双层低秩预条件元优化器。给普通元学习基线相同F/h、同分子梯度和同支持/查询episode，其内循环 `a'=a-eta P grad L_m`、外循环 `grad_P L_f(Q;a')` 就逐步复现本候选；无需独立GP或高斯假设。所谓“世界模型梯度传送”目前只是这个具体标准实现的任务解释。

这不是说元学习类别中的方法都不可能创新。可以因明确统计性质、监督效率、成本或结构约束形成贡献；但当前8维/秩2/正定参数化与跨损失episode没有给出新的性质，也未证明它比同结构普通元优化器更强。分子与功能曲率甚至可能方向相反；正定P对分子损失的下降保证，不是对功能排序的保证。继续给P套一层可学习更新器会增加层数，并没有解决这个实质差异。

**独立决定：NO_QUALIFIED_DISTINCT_UPDATE_CORE_IN_THIS_PROPOSAL。** 可以作为明确的常规更新基线；当前不建议据此开新的保留背景或启动多代RSI。这一结论不宣称所有早期状态更新无用，也不声称已穷尽算法空间。当前最需要的是一个超出这个精确元优化器实现的可验证结构优势，而不是改名或扩网格。

## 4. 2025–2026原文给出的边界

**Population Evolution，2610.05950v1，首发2026-10-05。** 实读§2.1–2.3、B.2–B.3。原句：

> All peer results, including weak or unsuccessful transfers, are added to the ledger.

> Peer and promotion results affect local proposals only through this context; code archives remain instance-specific.

> Candidate code is inherited and edited; model parameters are trained separately for each evaluation.

式(1)直接写 `h_i,t ~ p_i(h | tau_i,t, Phi_i(M_t))`。B.2还明确给own/successful/weak-transfer记录，限制4K tokens。故“把阴性跨任务结果放进记忆，改进后续提案，并将代码继承”已经是具体近邻；不能单独作为我们机制差异。其经验性跨实例重放很有用，但不是本候选中后更新功能超梯度的证据，更不替我们证明G1/G0。

**Learning to Discover at Test Time / TTT-Discover，2601.16175v2，首发2026-01-22，v2 2026-02-05。** 实读§3.2、4.4、5.3–6和附录A.1相关段。其新具体运算是entropic objective与PUCT重用；式子为

`J_beta(theta) = E_s log E_a exp(beta(s) R(s,a))`，

`grad J = E[w_beta(a) grad log pi_theta(a|s)]`，以KL约束自适应beta。原句：

> This form of continual learning is quite special, because its goal is to produce one great solution rather than many good ones on average, and to solve this very problem rather than generalize to other problems.

§4.4原句：

> We train our policy by using Pancreas in our environment, and ultimately performance is reported by running the algorithm on the held out PBMC and Tabula datasets.

因此算法可以跨数据测试，不能泛称它“没有迁移”；但这里迁移的是所得去噪算法，不自动等于在新研究任务上已训练的改进策略更有效。该文已包含生物算法代码搜索；把API程序搜索接入PTPC、将AP作为reward，不能单独成为新算法。作者还明确提醒benchmark增益不保证下游生物有效性。其目前连续可验证reward限制，不能靠一个噪声很大的开发AP反馈假装已满足。

## 5. 当前支持、反对与可交叉质疑点

支持：操作小、明确、可以逐步检验；对“更新器如何从分子反馈学习功能有用方向”的问题给出了真实梯度路径；能严格区分U继承和G进一步改进，不要求新生物假设为真才执行。

反对：当前操作与具体普通低秩双层元优化器完全一致；源任务有限且开发暴露，功能标签少且语义不明；早期数值与掩码尚未分离；暂无任何跨背景方向传送的证据。PE和TTT-Discover已经覆盖许多容易被误认成创新的搜索/阴性继承描述。

未决：是否有一个利用干预结构或测量机制、能形成明确统计/计算优势的额外约束，使本操作脱离普通基线的逐步复现。目前原稿没有这样的约束。请交叉方优先攻击这一点；不要把增加搜索层数、换任务名称或一个开发正分数当作补足机制差异。
