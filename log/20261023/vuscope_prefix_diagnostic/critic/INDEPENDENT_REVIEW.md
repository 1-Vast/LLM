## Literal released-code discrepancies requiring a declared contract

1. **The clock is shifted.** preprocessing.py removes elapsed times below6h and renames the retained columns using earlier column labels. On the described regular3h schedule this maps actual6h to model time0 and actual120h to model114h. The robust implementation should subtract6h explicitly, preserve actual_elapsed and model_elapsed, and verify rather than assume the index mapping is subtraction if rows are irregular. The released72h filter uses model time<=3days without subtracting the6h shift, hence would include actual78h on that schedule. The120h branch makes a separate end-of-series correction. A new genuine prefix must select actual elapsed<=72h, then model cutoff66h; target actual120h corresponds model114h. Do not use a release-filename72 label as proof of legal cutoff.
2. **A separate extrapolation expression mixes units.** fit_surface.py sets start_time=6/24days but extrapolate_until_time=120-start_time while the config120 is hours. Its comparison with max_inhibition_time in days does not implement a120h target. This specifically concerns the inspected expression, not all downstream reporting. Implement one explicit hours→days conversion at a defined boundary.
3. **Fitting is not MAPE optimization.** least_squares receives unweighted count residuals z-model, so each optimization is SSE on normalized count values. Candidate-start selection calls scoring_function(model_prediction,observed,'mape'), placing prediction in the denominator. Other daily/extrapolated score calls use observed first. The paper's prose says MAPE is minimized, but this release implements SSE fits with an inconsistent percentage selector. Report the discrepancy; it does not prove which version generated published results. Do not silently claim faithful reproduction while fixing it.
4. **Normalization is actual per-well count division, not log counts.** After the6h reset the first retained measurement becomes the denominator and is set to1. It introduces shared baseline error. No full-trajectory maximum, fitted late asymptote, final control or CTG value may normalize a prefix. Preserve physical well IDs before melting: the release's final export discards well and protocol IDs, which is inadequate for independent replication/cluster accounting.
5. **Concentrations are globally selected.** The release log10-transforms concentrations, then selects sorted global dose positions[0,2,4,5]. That is four retained levels, not automatically all six doses per drug or a source-stated particular set in physical units. Derive the actual dose/well/compound mapping from the protocol, record it before count access, freeze all-six versus author-four scope, and never switch after results. Zero concentration can produce minus infinity; a zero-dose control needs an explicit limiting model value, particularly at model time0 where beta=0 and0*infinity is undefined.
6. **Fallback/solver details matter.** A global last_x callback variable is not reset within each fit/start, and a ValueError may therefore select a stale iterate. Do not import/run this pipeline. Use a locally reviewed solver with recorded convergence and failures, reset per-start state, fixed starting points/bounds/evaluation caps, and no late-target selection. Bounds permit a_alpha or a_delta=0, which can make time0 expressions0/0; define legal numerical bounds before data. Nonnegative growth-rate bounds alone do not imply increasing counts: carrying capacity below1 can yield decline, so do not falsely diagnose an inability to represent death from those bounds.

## Exact scientific restriction and minimal fair controls

The model imposes u(k_gamma,t)=1/2 after normalization by its own time-specific upper/lower asymptotes and beta(t)=k_beta*abs(alpha(t)-delta(t)). A changing50%-of-control dose does not by itself violate the fixed half-range midpoint. Later counts can change through alpha/delta even with fixed gamma. Unknown plateaus and four rather than six retained doses can make gamma poorly identified.

At minimum freeze: ordinary6parameter VUScope fitted solely on the legal prefix; its nested7parameter gamma(t)=gamma0+v*t extension with the identical alpha/delta/beta family and solver; an ordinary independent-dose growth forecast and simple persistence/local-trend sentinel using exactly the same prefix observations. A flexible joint model releasing both gamma and beta may be added only if predeclared and charged. If both are freed, improvement diagnoses the joint restrictions, not the midpoint alone. A factorial fixed/free gamma × tied/free beta is needed to attribute separate effects; it is not mandatory if the claim remains about the joint restriction.

The free-gamma extension extrapolates its chosen time law; successful forecasting would not uniquely identify the true midpoint trajectory. Match initialization opportunities, prefix fit objective, solver effort and tuning access, record actual work, and retain finite/converged fits for all arms without selecting the favorable one on late data. Original-release behavior, corrected scientific implementation and paper-prose objective are different contracts. Choose the main contract explicitly; a faithful legacy implementation, if desired, is a separately labeled audit arm. No claim of strong-direct-model superiority is supported merely by beating a weak persistence sentinel. A source-trained temporal direct predictor is optional at this stage only if its legal task history and equal tuning budget are explicit.
