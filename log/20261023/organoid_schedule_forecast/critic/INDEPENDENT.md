# Independent protocol/code review

Read only PROTOCOL.md, forecast.py and test_isolation.py before any current-phase peer report, real released response value or execution. Reviewed numerical formulas and execution order statically. No GET, real-data run or synthetic run by critic at this point.

Disposition: numerical/protocol design is a defensible minimal ordinary feedback diagnostic; one meaningful isolation-test gap should be repaired before execution. No additional metadata qualification is required for the scoped anonymous-coordinate prediction.

The descriptive continuation gate is falsifiable and matches implementation: strict ridge MAE improvement for each of three informative batches, plus campaign aggregate superiority to both cumulative mean and cumulative nearest-neighbor. g1 is excluded from continuation and checked for algebraic equality. Zero improvement margin is correctly described as descriptive, not clinical/statistical. The gate is demanding for ridge and does not imply every ordinary feedback predictor must fail if ridge fails. Protocol preserves counterexamples and prohibits same-panel rescue.

Ridge features correctly include fixed-category onehot, G0-scaled t0/t1, and category interactions. Centering the lawful training design/response yields an unpenalized intercept; solving XcTXc+I is sum-loss ridge alpha1. Preprocessing scaler comes solely from initial records. Full-category all-zero columns correctly yield zero category-specific coefficients for absent categories; shared duration terms remain. Nearest-neighbor implements the declared squared duration distance plus category penalty2 and averages exact ties without consulting responses. These are ordinary direct controls with fixed hyperparameters, not a strong-model novelty suite. Equal family specification between frozen/refit is fair for the narrow different-feedback-amount question.

Main filters initial gen0, history gen<g, query gen==g. action drops response and cv_err; only seq/t0/t1 enter features/distance, gen/number remain IDs. Labels remain raw; no clipping, global response normalization, tuning or error-based weighting. Archive validation reads all numeric responses before prediction but does not use their values for selection beyond prespecified finite-value validity; the protocol explicitly disclaims secure blinding. Main materializes legal historical labels for later forecasts; this does not make earlier forecasts secretly blinded.

Every batch prediction is created before target errors. FORECASTS.json and FORECAST_SEAL.json are written before metric evaluation. Campaign alignment explicitly follows forecast-generation and within-file query order; batch truths use the same filter/order. Paired differences are cumulative-minus-frozen for both metrics. File exclusivity prevents silent overwrite of pilot. No stochastic operations or API calls are present. No implementation bug in these paths was found by static review.

Required small verification repair: existing test_future_feedback_not_earlier_prediction calls predict_batch twice with identical earlier inputs, placing the synthetic future row only into a separately explicit later call. It demonstrates lack of global mutation, and that added labels can affect cumulative output, but does not exercise main's actual history/query builder. If main included all rows as history, this test would still pass. Thus it does not substantiate the protocol's end-to-end future-response invariance claim.

Requested remedy: an additional synthetic orchestration test can mock read_tables with tiny campaign records spanning all expected generations and OUT with TemporaryDirectory, call main without the real archive, modify highest-generation synthetic labels, rerun in a second temporary directory and compare forecast objects for all batches through the changed generation. Check stored history gen<querygen, initial gen0, and query absence of cv/cv_err. This catches actual future-label construction leakage and uses existing code without speculative abstractions. Keep the primitive tests for rejection/g1 identity. Do not require numerical real-data exposure or extra learned models to satisfy this verification.

Scope remains ordinary real-feedback utility under a historical adaptive design. Neither passing this review nor passing the eventual gate establishes novel U, world model, agent, inheritance or improved improver.
