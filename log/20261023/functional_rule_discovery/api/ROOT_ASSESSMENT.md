## Proposal 1: signed response-amplitude feature

API proposes yhat_q=y0_q+alpha*sigma_theta(q,s)*abs(y0_q-ybar_s), inheriting sigma/alpha. Define the fixed feature d_q=sigma_theta(q,s)*abs(y0_q-ybar_s). At fixed source sigma, source/support ybar and legal inputs, this is exactly y0_q+alpha*d_q. If alpha remains inherited and fixed and neither s nor ybar uses current target feedback, no current target functional feedback enters the output. If s or ybar includes purchased target feedback, the output can depend on that context even with frozen parameters; this is not automatically a learned updating rule. This scope correction was raised by frontier after its independent seal. If alpha is refit from target support using squared loss plus ridge, the explicit solution is alpha=(sum_S d_s*(y_s-y0_s))/(sum_S d_s^2+lambda), ordinary one-feature residual ridge. Other choices of fitting loss give ordinary one-parameter robust/calibration fitting, not automatically a distinct mechanism. A source-learned sigma may still be a useful feature; it must be given to ordinary same-information controls and its pretraining cost counted. This algebra does not declare every learned sign-field model equivalent to scalar calibration; it applies to the stated fixed-feature output operation.

No biological evidence is supplied for cross-intervention residual-sign stability or the choice of amplitude abs(y0-ybar). The known MAE sign-collision does not imply signs are more transferable than magnitudes, and does not justify treating prediction spread as the correction amplitude. Support-only selection of 'same-sign feedback' needs a lawful pre-outcome rule, not unseen-query residual signs. A target mean must come from available controls/support, not all outcomes.

API suggests old CDK/CXCL9/Norman/TG-GATES entrypoints despite the prompt's explicit stops. Its 'availability pending' language does not override existing historical decisions. No old data fitting is reopened. Held doses/interventions within one background are not automatically independent later biological tasks; practical utility/power and drug ranking cannot be reduced to an unspecified significance gate.

Disposition: do not nominate the stated scalar output operation as a new core. A new empirically justified transferable sign-field restriction could be a separate hypothesis, but no such evidence or estimator is provided here. Do not run another calibration toy to establish this elementary substitution.

## Proposal 2: source-update selection

API trains p(update_query_gain>0 | lawful task features), selects a source updater and gates it by support sign consistency. This is an implementable ordinary conditional algorithm/source selection outline, not itself a changed update law or an improvement of the strategy that generates later updaters. The required gain labels must be computed from source-only support/query splits; its costs, failed source trials and baseline selector capacity are charged. A learned selector is not refuted by its family name, but the proposal supplies no specific cell structure, different operator or finite-cost analysis beyond standard algorithm selection/validation weighting.

The suggested half-feedback versus full-budget criterion is not an automatic fair comparison: total source/search/training costs and the best ordinary selector at each feedback budget must be matched. Actual task count/power and a prospectively meaningful error/decision margin are unspecified. No exact universal equivalence to all routers is claimed; no useful or novel selector demonstrated.

Disposition: useful reminder to study predictable update heterogeneity, no nominated new core or experiment authorization. Neither proposal establishes a world-model contribution, agent contribution, inheritance benefit or RSI.
