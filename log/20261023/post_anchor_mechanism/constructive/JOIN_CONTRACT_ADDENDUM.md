## What these sources establish

The sample index names pre-AraC sample3 as multiplexed HL60/TF1/OCI-AML3 and post-AraC sample4 as multiplexed HL60/TF1 control/treated flasks. The pre founder-tag file explicitly combines mouse sample2 and human sample3. Thus the file name does not itself select HL60. Both lineage receipts authenticate a stats header containing readName and sequence/alignment fields, not a ready cellID/founder table. No records have been inspected to validate the documented readName layout.

extractReadInfo splits readName by underscores and takes the second component R1[0:16] as cellBC and R1[16:28] as UMI. The preprocessing then merges cellBC against whitelist.FB_bc to obtain GEX_bc. Exact chemistry/version-specific FB→GEX conversion, library identity and 10x suffix handling are necessary; raw 16mer equality across independent libraries is not physical-cell identity. The function shows a schema hypothesis to test, not a demonstrated successful join.

HL60 founder construction has no supplied founder whitelist: it filters tags, clusters cell/tag co-occurrence, removes ambiguous tags and ranks resulting founders by observed cell abundance. Clone labels are also ranked within founders. Independently reclustering or ranking baseline and endpoint cannot preserve identity. H1 at baseline need not mean H1 at endpoint. Sequence-based fixed identities, with separate display names, are needed.

## Minimal identity audit, before functional modeling

1. Authenticate library manifests, chemistry-specific FB_bc→GEX_bc reference and sample3/sample4 barcode namespaces. Qualify actual row schema/lengths only under a separately frozen identity-only acquisition contract; no expression matrix or functional payload is needed for this step.
2. Obtain the MULTIseq tag→species/cell-line/flask/timepoint map and per-cell demultiplex calls or reproducible raw demultiplex inputs. Separate mouse sample2 from human sample3 and HL60 from other human lines using authenticated sample identity; species separation alone cannot distinguish HL60/TF1/OCI-AML3. Drop negative/doublet/ambiguous assignments by fixed rules. If multiplex identities are unavailable, STOP HL60 prospective qualification.
3. Join within library using declared whitelist conversion and suffix rules. Predeclare checks for one-to-one mapping, collisions, unmatched fractions and demultiplex/tag conflicts. Publish counts and ambiguity, never repair a poor join by maximizing phenotype correlation or endpoint clone overlap.
4. Learn a sequence-keyed founder dictionary using only eligible baseline HL60 cells, with predeclared preprocessing, error-correction, co-occurrence and ambiguity rules. Freeze its content/hash and all mapping parameters before endpoint founder-tag exposure. Founder dictionary construction uses baseline identity/tag data, not response, endpoint RNA, endpoint trees or clone fitness.
5. Assign endpoint cells independently to the frozen founder dictionary. Exact high-confidence reference matches are the cleanest initial identity criterion; any error tolerance must be fixed and ambiguity-rejecting. Do not jointly rerun abundance-weighted Starcode or Louvain across baseline/end, alter baseline dictionary, or independently rename by endpoint size. Unmatched/new/mixed tags stay unassigned and are explicitly reported. Founder identity should survive sequencing-error sensitivity checks without selecting thresholds from functional outcomes.
6. Only after a frozen join passes its predeclared coverage/ambiguity gate, qualify culture/time/assay linkage and freeze the endpoint, task partitions and label acquisition. Baseline RNA features are then permitted under that contract. Whole founder/culture lineage units, not individual descendant cells, determine uncertainty. A missing baseline founder remains unobserved rather than newly invented or assigned using endpoint state.

## Baseline dictionary: what it can and cannot establish

Yes, freezing a baseline sequence dictionary and subsequently assigning endpoints can avoid one important form of retrospective identity leakage. Its validity requires founders to carry stable, sufficiently distinguishable baseline tags and baseline sampling to cover the intended population. This is a prospective reconstruction choice, not exact replication of the authors' pooled clustering or H-rank labels. A frozen finder may legitimately lose rare founders; endpoint absence conflates biological loss, sampling and technical failure. Do not infer extinction or zero viable abundance from an unobserved founder without an observation model.

Founder tags and evolving lineage-recording alleles serve different roles. A founder dictionary need not reconstruct endpoint trees. Baseline clone-tag dictionaries, if attempted, need their own stable-tag contract; endpoint-acquired/evolved edits cannot be backfilled into baseline features. Future biological clones may not exist as separable baseline units.

Passing identity checks would establish a lawful barcode/lineage bridge and coverage diagnostics, not absolute viable growth, treated-minus-control causality, model utility, reusable update laws, world-model necessity or RSI. Founder fractions remain compositional. Day36 treated/day43 control remains unmatched. A functional claim still needs same-time, culture-linked controls and independently authenticated count/viability endpoints. This new information narrows qualification work; it does not authorize performance fitting.

## Static reproducibility limitations

The published snippets contain missing external variables and version/interface inconsistencies: do_clusters is called with tag/algorithm arguments while the supplied utility signature accepts only data/res, and preprocessing refers to target_cols before its shown definition. These are reasons to specify and audit a minimal reconstruction, not to execute the author scripts blindly or claim the dataset unusable. No code repair or execution was attempted here.
