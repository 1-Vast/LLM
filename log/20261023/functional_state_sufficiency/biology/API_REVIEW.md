## Literal contract differences

1. Existing BeatAML task buys **8 different drugs in one patient's context**, then predicts that patient's unbought drugs. API replaces it with **8 patients measured for each target drug** and predicts new patients/strata for that drug. These are different intervention budgets, axes and meanings of transfer. A legitimate eight-patient/new-drug adaptation study is possible in principle, but must have its own frozen source/patient/drug split and scientific application; it is not the already demonstrated8-feedback task and is not automatically authorized on exposed data.
2. In the original same-patient query, `bar r_d` for an **unbought query drug d** is not available from that patient. Query drug residuals cannot be smuggled in as feedback. It can be lawful if explicitly computed from source patients or from paid distinct target support patients under the new contract; those options must be distinguished and all predictors receive them. This is a conditional legality finding, not a claim that a per-drug mean is always leakage.
3. In the API's **unseen-drug** proposal, source-learned `u_d` is undefined for the heldout drug. “Nearest neighbour or freeze” supplies neither a drug representation nor a distance or source-only mapping. Patient basal phi(x) does not define a drug identity embedding for an unseen item. A learned chemical/target descriptor-to-loading map could make a *different* valid operation, but has new data/priors/costs and needs explicit controls. Do not silently repair this gap by reusing a heldout drug's source loading.
4. `bar r_pool` requires a specified pool of paid source/target observations. The paragraph allowing only that drug's8 target patients is inconsistent with an unspecified target multi-drug residual pool. A source-only pool can be legal but means a different adaptation dependence. Explicit observation indices are necessary.

## The operation does not establish the claimed new freedom

The actual covariance baseline already has query-drug/support-drug-identity-dependent coefficients `C_QS(C_SS+I)^(-1)`. Constancy for **fixed S** does not mean the coefficients cannot depend on drug identity. The API's assertion that such identity dependence is the newly uncovered freedom is incorrect. A patient-state-dependent interaction is operationally different, but is already within ordinary contextual regression and must have its own evidence/resource rationale.

`a_d * mean(r_d)` is a drug-specific **intercept correction**, once support residuals are observed. It is not automatically a slope for mapping `f0` to y. Comparing it only with a two-parameter slope+intercept refit overstates its parameter advantage: ordinary one-parameter offset EB, ridge residual calibration and same-feature reduced-rank regression are necessary competent controls. The term `u_d(v^T phi(x))*bar r_pool` can be written as a bilinear low-rank interaction using fixed context features; its useful rank constraint is an empirical hypothesis, not a new estimator established by its name.

Eight observations do not imply diag+rank1 is the “unique identifiable” structure. Many regularized function classes can be fit under8 observations; parameter identification depends on design, assumptions and priors. Separate u/v also has scale/sign ambiguity unless normalized, although predictions from uv can still be well defined. Variance`proportional to1/8`, a twofold parameter-count assertion and concentration of source `u_d` do not establish measured finite-budget superiority. No valid prespecified per-drug “u distribution concentrated” subgroup is operationally defined for a new drug with no loading.

No empirical defeat follows just from conventionality. If a lawful new-drug task and descriptor restriction are independently justified, compare this exact rank constraint against offset EB, ordinary low-rank contextual residual regression, context-aware direct/multitask models, head/union refit, and relevant same-cost CL/AL/search. Historical STOPs must first be checked for the *specified* task; do not decree all ranks banned or silently reopen an exposed failed low-rank state branch.

## Biological/source corrections

API's ending says CellHealth health is predicted rather than truth. That is **wrong for the genetic training cohort**: independent targeted assay measurements exist for357 guide×line consensus conditions. It is correct for70 phenotypes *predicted on the drug imaging collection*. The actual PRISM drug validation is independently measured but not exact-dose/samewell, so its limitations are separate. Static genetics can support an ordinary finite feedback prediction question; lack of dynamics does not by itself make real phenotype labels illegal. BeatAML also has multiple patient backgrounds within one cohort; calling it literally one background is overbroad. It has no authenticated postintervention molecular transition in the inspected contract.

## Whether current CellHealth supports the proposed state issue

Constructive's samecell joint/copula hypothesis requires **within-cell joint samples of the relevant state variables** and an independent matched condition functional target. The Cell Painting singlecell data may in principle support morphology-feature co-occurrence, but cannot be read as joint expression of specific genes. CellHealth and Cell Painting lack replicate/cell matches; that invalidates a samecell state→samecell health alias experiment, not all condition-level distribution→mean-health prediction. Marginally similar consensus vectors cannot prove identical state distributions, nor a conditional disagreement prove a hidden state without repeatability controls.

Frontier's strict-input alias benchmark is a useful template, but exact identical transformed input in a designed software branch differs from approximately similar noisy cell conditions. A summary-distance collision requires a prespecified metric and measurement tolerance, source-only choice and independent measured phenotype difference, while pair selection after health labels is exploratory. Three cell lines restrict transfer scope; they do not prohibit a finite component experiment. At present no extra feedback propagation/witness rule beyond original morphology→health and ordinary conditional/refit controls has been proposed with authenticated data semantics. I therefore nominate no numerical CellHealth task yet, while retaining it as a legitimate candidate source for a concrete later diagnostic.
