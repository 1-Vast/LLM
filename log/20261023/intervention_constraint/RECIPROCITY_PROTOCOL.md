# Proposed narrow quadratic-potential compatibility gate (before access)

Full-goal mechanism candidate, not a new performance method: does an exact positive-amplitude, same-coordinate quadratic-potential response constraint even fit the already-qualified single-RNA representation? This protocol is a proposal awaiting independent pre-access review; no candidate response submatrix has been inspected. No function target, pair RNA, development/protected response or raw count replay is needed.

Declare the state coordinates to be the panel target genes' declared log1pCP10K control-centered means. Suppose the entire finite perturbation range stays in one common quadratic potential V(x)=.5(x-x0)^T H(x-x0), H symmetric positive definite. Suppose CRISPRa of targetj is a positive scalar conjugate force s_j e_j in these exact measured coordinates. Its finite response is R[:,j]=H^-1[:,j]*s_j. This is stronger than a generic nonlinear potential or a local infinitesimal derivative statement. It is not asserted as established biology. Different coordinates, composition, off-target forcings, state-dependent noise, observation offsets, nonlinear finite response, heterogeneous survivors and batch differences can invalidate this interface while leaving other cellular potential models possible.

Necessary condition: R_ij/s_j=R_ji/s_i; every nonzero reciprocal pair has the same sign, and products R_ij R_jk R_ki = R_ji R_kj R_ik on every fully nonzero triple. Diagonal entries must be positive for positive s_j. Sign/cycle conditions alone do not prove SPD, force identity, causality, prediction or useful function. Generic unknown H-metric or unknown dense force mapping is not tested by coordinate reciprocity. A data-estimated dense force map would eliminate this gate's intended restriction and require a separate identifiable model and strong direct controls.

Inspect only gene-symbol metadata to map all103 existing singleRNA targets to exactly one matrix feature, using the four frozen originalaliases; do not select target subpanels using responses. If any absent/duplicate mapping, report and stop rather than pick favorable rows. Read full already-used singleRNA features only after mapping and biological prefit review. Construct R_i,j=features[j,index(target_i)]. No new normalization, gene filtering, SVD, magnitude threshold tuning or target-response subgroup selection. Retain signed zero; use fixed numerical tolerance1e-12 solely for floating-point-zero accounting, not a significance or biological relevance threshold. Report all103targets, complete reciprocal signs, diagonals and all fully nonzero triples, continuous normalized cycle defect. No asymmetry significance without replicate uncertainty and no arbitrary useful-gain threshold.

Prospective consequence: one opposite-sign reciprocal pair or nonpositive diagonal excludes the exact positive-amplitude quadratic same-coordinate model for the saved numbers. Cycle violations likewise exclude exact symmetrizability on that support. They do not reject generic potentials, equilibrium biology or softened approximate constraints, because assay uncertainty and interface assumptions are unqualified. Do not fit a reciprocal-constrained world/updater as an exact physiological law or tune thresholds to rescue it. If conditions hold, this is only necessary compatibility and cannot justify model/agent/RSI promotion. A useful approximate bias could be tested later only with a distinct hypothesis and frozen same-information ordinary symmetrized factor/direct predictors, source-only uncertainty handling and actual function/decision utility. Current diagnostic does not test agent/inheritance/joint/recursive contributions.

Minimal synthetic validation before any realRNA numeric access: SPD susceptibility with positive column amplitudes passes sign/cycle identities; an explicit asymmetric opposite-sign pair fails; finite derivatives of a nonlinear shared potential can differ at finite forces (not automatically a contradiction); dense forcing breaks observed reciprocity despite SPD state susceptibility. Keep code/tests research/ and evidence log/. Review and exact implementation precede execution. No code/output from the API response is used.
