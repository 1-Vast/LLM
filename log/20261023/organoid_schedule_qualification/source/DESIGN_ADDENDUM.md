## Dataset and variable semantics

The archive names four collected datasets: FAC/concurrent35rows, FAC/sequential32, OLA-IBET/concurrent50 and OLA-IBET/sequential27. Sequential columns are seq,t0,t1,cv,cv_err,gen,number. Concurrent columns include conc*,ci,cv_exp and error/reference fields. These headers do not authenticate raw replicate arrays or independent organoid IDs. README identifies MCF-7/FAC versus breast-organoid OLA-IBET but supplies no full mapping from FAC letters a..f to drug permutations, no unit conversion for collected t0/t1, and no formal definition of replicate aggregation.

FAC sequential design projection has gen0..3 with eight numbered schedules each; OLA-IBET has gen0..2 with nine each. Numbers restart1 per generation, supporting within-batch proposal labels, not unique donor/sample identities. Primary explicitly describes those GS batches in chronological optimization order. A limited campaign-generation-ahead evaluation may use increasing gen as declared batch order. It must not call this authenticated collection dates, independent biological tasks or proof every experiment was actually performed in file row order. Code assigns gen0 or gen2 and within-proposal number=index+1 in OLA scripts, corroborating the campaign-label meaning; FAC scripts leave metadata handling largely to the supplied table/manual workflow.

Root ACTION_DESIGN inventory further reports four concurrent/sequential gen counts and no exact action repeats across generations. That is useful for proposed unseen-action batch prediction; it is root's separate projection, not an independent raw duplicate audit by this reviewer. ## Major clock/encoding issue: runner grids differ from collected units

Collected t0/t1 cannot be treated directly as physical hours or blindly fed into each historic runner. Primary anchors provide compelling crosschecks for a2-hour canonical unit in collected data:

- FAC GS2-7 has seq=b,t0=4,t1=16. The primary identifies the corresponding selected schedule DOX8h ->5-FU32h ->CPA8h. A2h unit yields first two durations8/32h and remainder8h from48h total; therefore b is supported as this DOX/5-FU/CPA ordering.
- FAC GS0-4 has seq=d,t0=4,t1=14. Primary describes CPA8h ->5-FU28h ->DOX12h, again consistent with2h units and supporting d as that ordering.
- All OLA sequential projected rows have t0+t1=48 while primary treatment total is96h. GS2-2 has seq=b,t0=33,t1=15, matching IBET66h then OLA30h when combined with Fig7 validation drug durations. This supports b as IBET-first and the complementary a as OLA-first given exactly two permutations, but the inference should be disclosed; it is not an explicit dictionary in README.

These anchors establish a strong design-derived interpretation for the named rows and overall totals, not a complete source-authenticated mapping for all FAC letters or a complete schema/unit dictionary. A full physical-duration benchmark should freeze this convention with explicit evidence and unresolved categories before response analysis. One may instead use categorical seq and raw canonical t units for a transparently limited endpoint regression, while not naming every drug order or claiming a mechanistic action model.

FAC early GS0-GS2 runners define t0/t1 between1 and10 with sum<=11, consistent with a12-unit48h grid. But released rows in those generations contain t values up to20 and sums up to22. GS3 runner uses bounds1..22 and sum<=23, consistent with24 units and2h resolution. Therefore collected designs and early runner input coding differ; an unmodified replay of consolidated CSV through early scripts does not represent the historic experiment. The source has identity assignments where comments say convert discrete times: actual conversion is absent. Some historical re-encoding/manual handling must be distinguished from an observed algorithmic update.

OLA GS0 runner defines t0 in1..11, derives t1=12-t0, whereas collected GS0 rows sum48. This is a fourfold representational difference, not a96h physical-total contradiction once inputs are re-encoded. Released GS0 t0 values are multiples of4 canonical units; with2h units their physical spacing is8h. The code12-unit total across96h independently points to8h initial units. This differs from the primary's general statement that initial organoid duration interval is4h. The later OLA runner defines total48 and bounds1..47 plus12<=t0<=36, consistent with2h units and a24-72h restricted first duration. Keep the initial4h-versus8h narrative discrepancy and candidate-domain changes explicit; do not silently claim exact reproduction or repair the paper's grid statement.

## All versus partial feedback: precise new code evidence

Sequential runners load a local OBS_FILE='data.csv', drop rows only when declared parameters are missing, build observation dictionaries from every remaining row/all columns and pass the entire resulting list to gryffin.recommend. They then append proposed rows and write a CSV/backup. No gen-based history truncation or explicit selective winner-only feedback appears in the reviewed sequential runners. Therefore the code uses ALL parameter-complete rows of the user-supplied observation file, including earlier objectives where present. Objective NaN is expressly allowed as infeasible experiments by the comments; this is not proof every row is a successful real response.

Important limit: historic per-generation data.csv snapshots are not supplied in the reviewed archive paths; consolidated data_*_seq.csv files live elsewhere and runners do not point to them directly. Thus this is all supplied-file feedback, not proof all released final campaign outcomes were historically available or passed at every call. Replaying final files without gen restrictions would leak future experimental generations. Missing grid conversion, manual metadata assignment and human acquisition-setting changes further prevent asserting byte-exact historical replay. Error columns, number and gen entering the observation dictionaries do not establish that Gryffin uses them as optimization features; declared parameters are seq/t0[/t1], objective cv.

README's boilerplate install instructions use a Gryffin master branch and old TensorFlow/Python stack. A pinned archive does not pin the optimizer implementation or recover random-state/runtime history. Do not execute author scripts as a read-only audit: they print observations and overwrite/backup input CSVs. No such execution occurred here.

## Eligible next diagnostic and stopping boundary

With gen labels and legal design metadata, it is reasonable to freeze a G0-trained terminal-response predictor and compare it to ordinary cumulative feedback refitting when predicting later measured batches. Fix formula/hyperparameters and scoring before response decoding; at step g fit only lower-gen labels, predict all gen-g queries before scoring/updating. The fixed-G0 model receives the same known query design; cumulative models receive legally observed prior-batch labels. Keep whole-generation forecasts and schedule identities together, record changes in resolution/constraints, and avoid tuning on a later batch before its prediction. Small G0 sizes and three/four sequential batches imply very limited power; they do not establish a task series or a learned updater. A fair distinct updater would still need strong direct/refit/mixture/CL/AL and search controls; ordinary BO feedback is not novel by itself.

This can test narrow endpoint prediction under the historical adaptive selection process. It cannot estimate what another acquisition policy would have discovered across the unmeasured action space, prove unseen-patient generalization, identify within-organoid state transitions or validate improved-improver inheritance. If physical seq dictionary cannot be recovered, do not invent it; restrict the claim or stop the physical-action world-model task. If historic unit coding is ambiguous, freeze a declared released-design convention with limitations rather than treating raw t as hours. No new response decoding/model run is warranted merely by this design addendum; this is qualification evidence for root's next protocol decision.
