## Endpoint and data scope

Official EmeraldBay card: 1,831,648 single-cell profiles, 52 cell lines, 91 drug treatments including combinations, five-day endpoint. Summary card describes 4,992 rows, 52 lines and 93 conditions including DMSO_T0, with `cell_line`, `condition`, `growth_rate`. These are **author metadata claims, not verified table counts**. The loader drops null growth, multi-drug conditions, and parsed DMSO_T0; then arithmetic-means each (cell_line, condition). It does not reconstruct growth from counts. Config still points to internal `/nvme-shared/.../growth_rate_long.parquet` and internal pdex/delta paths; a locally equivalent public loader requires explicit remapping, not unmodified execution. A/B half variants also point to internal files: declared A/B availability is not public acquisition or independent-well proof.

No explicit growth formula appears in the inspected card, notebook body, loader, trainer, or config. The presence of T0 controls alone does not authenticate a GR normalization. From proportions p_i=N_i/sum N_j alone, multiplying all final counts by an arbitrary positive constant leaves every p_i unchanged and changes absolute growth: absolute pool survival requires additional total/count calibration or an explicit reference assumption. This is a general identification fact, not evidence that the authors computed the endpoint incorrectly. A relative-composition endpoint can still be useful if named and evaluated as such.

## Heldout information contract

`prepare_sensitivity.make_splits` holds out exactly those rows whose context and condition occur in the TOML test mapping; all other rows remain training, including observed support conditions in heldout contexts. It is fewshot unseen combinations, not entirely unseen contexts. The inspected split_0 header claims five heldout lines, 14 heldout drugs of 20, all doses of these drugs held out, 33 test conditions per heldout line, 2,175 train and 165 test rows of 2,340. These are **configuration comments, not our measured counts**. Drug identities/doses can be read without functional scores. All same-drug doses are grouped in this particular author split; random per-dose splitting would make a different and easier task.

Scalar ridge excludes every heldout context from fitting support-to-query coefficient matrices. Other heldout contexts can still inform the preceding pooled ALS because their permitted support rows are part of training; all competitors must be told this. Empty/unsupported predictions fall back to ALS.

## Exact feedback operators already implemented

Sensitivity scalar core fits additive `mu + cell[c] + treat[t]`, fills missing values from that fit, then for each heldout context h chooses observed support treatments D_x and query treatments D_y. Across nonheldout contexts it centers X=growth[:,D_x] and Y=growth[:,D_y], sets B=(X X^T+lambda I)^(-1)Y, and predicts mu_Y+B^T X (growth[h,D_x]-mu_X). Thus support functional feedback propagates to query through a conventional centered linear ridge. Canonical scalar default lambda=1. This is an actual ordinary support-to-query updater already available; merely learning propagation weights is not a new mechanism.

Feature ridge replaces X with flattened measured support-drug RNA summaries, retains scalar query growth targets, and uses the same dual ridge. Default feature ridge lambda=10 and blend weight=.25. The paper README's feature variant must not automatically be interpreted as support-only: actual default trainer also blends an MLP residual at .12. `_build_block` aligns both train and test rows from the complete feature map, passing query-row measured RNA as `X_test_features`; the residual MLP projects these query features and predicts with them. This is allowed under a retrospective query-RNA-observed information contract, but is additional information relative to only purchasing a support panel. It is not by itself label leakage or misconduct. Disable that branch or supply independently predicted query RNA if claiming no measured query RNA; this changes the evaluated variant and needs fresh validation.

Transcription fewshot `_compute_regression` stacks source contexts and genes to fit one drug-combination weight matrix, shared across genes, then applies it to heldout context's observed support RNA. It intersects support/query drugs across all nonheldout contexts, centers per drug across contexts, optionally adds prior weights/PCA/reduced rank. This is distinct from scalar ridge's ALS-filled coverage rule. Do not silently merge their contracts. The implementation already exposes W_prior and regularization toward prior drug weights; a proposal to inherit a coefficient prior must demonstrate a substantive difference.

The architecture document additionally describes a separate hit-discovery PCA/classifier pipeline with PCA fit on all labelled and unlabelled rows, explicitly transductive. It is not proof that the scalar sensitivity experiment uses this pipeline, and does not establish a prospective agent or improved-improver result.

## Fair ordinary competitors and necessary future checks

At minimum implement from scratch: train-only treatment mean; train-only additive effects; source-group nested-tuned ordinary support-growth ridge matching above; support-RNA ridge under the same purchased panel; concatenated support function/RNA direct ridge and tuned simple mixture; matched query-RNA direct ridge/nonlinear predictor when query RNA is allowed; dose-aware hierarchical/direct predictor with whole-drug dose groups and matching controls; ordinary retraining/conditional covariance update under identical feedback. Missing-feature policy, normalization, tuning, support purchases, API and fit cost must all match. Author hyperparameters and reported R2 .26/.31 are source claims, not our replication or evidence that these stronger controls are beaten.

For a virtual-cell claim, predict query state without measuring it, compare function predicted from that state with direct support-to-function competitors, and separately test whether actual query RNA would help. For agent/inheritance/RSI claims, require independent later contexts/tasks and equal total-cost acquisition/program-search comparators. Existing source contains no proof of those MAESTRO claims.

Before labels are opened: authenticate exact endpoint derivation, identify available replicate/sample/count fields and absolute calibration, establish group-disjoint support/query/task inheritance split, freeze data transform and baseline set. If only relative pool phenotype is authenticated, narrow the endpoint name and decision claim accordingly; do not infer selective absolute killing or clinical sensitivity. If public functional summary is genuine but independent replicates cannot be reconstructed, an exploratory retrospective benchmark is possible, with inference at context/drug group rather than per-cell pseudoreplicates.
