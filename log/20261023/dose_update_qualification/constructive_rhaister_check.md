## Main finding: two RNA permissions coexist in the feature model

The author's scalar sensitivity implementation does not have one uniform “RNA-enhanced function prediction” contract. Its two added branches use different information:

1. `_drug_regression_features` uses **support/panel RNA only in the held-out context**. It defines D_x from `obs_mask[hc]`, the treatments whose functions are in training/support for held-out cell hc. Its predictor is `feat_mat[hc,D_x]`. Non-holdout cells contribute the same D_x RNA as X and D_y functional labels as Y. It does not index the held-out cell's D_y/query RNA. This is a concrete ordinary support-RNA->query-function transfer estimator.
2. The additional MLP residual branch receives `X_test_features`, which `_build_block` creates by directly looking up `(test_cell,test_treatment)` in the measured feature map. `_mlp_residual` passes these values as `f_te` into `net(c_te,t_te,f_te)` at inference. This branch therefore uses **measured query-perturbation RNA**, subject to actual source coverage. It is not generated by Rhaister's RNA world or inferred from the support panel.

The feature variant defaults set HP_FEAT_RIDGE_W=0.25 and HP_MLP_W=0.12, and both branches run when features are attached and those weights are positive. Thus the complete default “with features” method structurally has query-RNA access. Its result cannot establish that support RNA alone explains a functional improvement. The README's reported R2 feature increment is an author summary; this read-only check does not prove the exact hyperparameter command or branch settings used to produce every table value. Reproduction instructions, result records and ablations would be needed before assigning that number to any specific branch.

Disabling MLP would produce a support-RNA-only feature-ridge ablation; that is a sensible ordinary baseline or new frozen diagnostic, not a result already reproduced by us. If measured query RNA is purchased, strong direct row-wise function predictors must receive it too. If it is not purchased, query RNA must be masked before prediction and preprocessing, and the MLP route must be disabled or explicitly consume lawfully generated predictions. Quietly replacing measured query features by predicted ones changes the information distribution and needs a separately trained/tested contract.

## Scalar baseline already transports real functional support

With HP_FEATURES unset the sensitivity model first fits additive ALS to source/support scalar function, then performs ordinary drug regression. It constructs a dense y_imp matrix from ALS, overwrites observed entries with y_train, defines D_x as the held-out cell's observed treatments, and predicts D_y from ridge over non-holdout cells. Training cells can have imputed values for missing entries. This is a concrete same-function-feedback baseline; a candidate cannot claim inheritance by comparing only against no-support direct RNA models.

The split reader defines test entries by held-out cell **and** listed test treatments; all other rows remain training. The saved split_0 comments describe five partially held-out cells and query drugs/doses; the implementation therefore is few-shot unseen-pair prediction, not total withholding of every observation from those cells or withholding the query drug globally. Actual source coverage must be checked from the dataset if numerical work proceeds; TOML comments alone do not certify it.

The architecture document describes a separate PerturbHD pipeline: predicted RNA is pivoted, joined to sensitivity labels, then a classifier ranks hits. It also states that PCA is fitted on all labeled and unlabeled feature rows. That pathway is distinct from the scalar sensitivity trainer above and has an explicit transductive feature preprocessing contract. Do not use its description as proof that the scalar feature trainer receives predicted rather than measured query RNA. The README's main fewshot/zeroshot RNA model descriptions likewise do not override the actual scalar feature lookup.

## Data boundary and what remains unverified

`_apply_filters_and_aggregate` removes configured null labels, multi-drug conditions and DMSO_T0, then averages growth_rate by `(cell_line,condition)`. This authenticates how the loader consumes the released relative phenotype; it does not authenticate its experimental growth formula, absolute cell recovery, biological replicate independence or measurement noise. Dataset config calls A/B files “independent half-replicates,” but source naming/comments alone do not prove independent wells/cultures; there is no A/B generation implementation in the files checked here.

Even without the growth formula, a properly isolated experiment can predict the **released relative phenotype**. It should preserve the source's limited interpretation and cannot claim absolute viability, intrinsic growth-rate pharmacology, clinical efficacy or independent functional confirmation. The README for EmeraldBay says phenotype derives from same-five-day cell-count proportions. Same-endpoint expression/function coupling, survivor selection and cell-recovery effects therefore remain material explanations.

Features can contain cell_eval deltas, pdex fold-change, p-values or FDR transformed by -log10. These are measured assay summary statistics; p-value/FDR information depends on depth and controls as well as biology. `_build_block` uses observed-training-row moments for feature scaling, but also builds dense feature coverage across all mapped cell/treatment keys. Missingness/coverage and upstream pdex/cell_eval preprocessing need an explicit cost and leakage contract. Source-only z-scoring alone does not establish upstream data isolation.

The source includes oracle/diagnostic baselines. `_adjacent_dose_pred` explicitly reads y_test from another query dose of the same curve and documents itself as an oracle/titration ceiling. `_a_vs_b_pairs` reads query-pair A/B values. They are legitimate disclosed diagnostics, not deployable same-feedback competitors unless those extra measurements are lawfully purchased and charged. Do not copy them into a finite-support baseline with free query labels.

## Fair minimum comparison for a future frozen functional diagnostic

- **Function-only support contract:** same source contexts, same support drug/dose functions and same query sets for additive/low-rank, scalar Rhaister ridge, conditional EB, nonlinear same-forward curve models and union refit. No query function or RNA.
- **Support-RNA contract:** add measured RNA only for the acquired support packages to all methods. Compare support-RNA feature ridge, ordinary direct episodic predictors, conditional/non-Gaussian EB and proposed updater from identical starts/history. RNA acquisition, control packages and source fitting are charged.
- **Query-RNA contract:** if purchased for every query, all direct models receive the exact row features and count/QC/missingness. Score incremental information above that strong direct contract, not above a cheaper function-only method while claiming world-model necessity.
- **Predicted-query-RNA contract:** query measured RNA is unavailable to training/selection/inference except as separately isolated evaluation if declared. Train the functional readout on lawfully source-predicted or cross-fitted features to handle generated-state error. Compare direct feature/function prediction at matched history/cost. This is the pathway capable of testing simulated intervention-state value; it has not been verified by the scalar feature-source lookup.

Count panel functional and RNA assays as joint feasible packages where appropriate, with controls, repetitions, source construction and search cost. A shared cell panel or pooled assay does not create free independent feedback per row. Drug-dose aliases, all doses/replicates of a withheld drug/context and related batches must follow the predefined isolation contract. Exact same-pair public historical labels are lawful lookup baselines whenever available to the purported user.

## Decision

**GO only for bounded implementation/data qualification; no mechanism or numerical replication GO is implied.** The official implementation supplies a stronger ordinary functional-support and support-RNA baseline than a vague gene/module prior. It also exposes why a feature gain cannot automatically establish support-RNA value or world-model contribution. A future experiment must choose one information contract before opening new response values. No new updater, functional performance, agent necessity, inheritance, joint or RSI result is established by this check.
