# Literal API margin rule: pre-execution check

The API PROPOSAL.md is already visible; it itself gives the witness. This is a post-proposal independent operation check, not a novel counterexample, prospective biological test or performance benchmark. No candidate code will be executed.

Implement the printed update literally with a common fixed observed single baseline b=0, eta=3/5, delta0=0. Both indicator predicates are evaluated against the OLD delta. Same two feedback records A=3/10 and B=-1 are supplied in AB and BA order. Check all intermediate indicator/update values by Fraction arithmetic. A third prediction q=2/5 is accepted iff q>=b+delta. Hypothesis claimed by the proposal: a reusable shared margin is batch-order invariant. Falsifier: unequal final deltas and different third-candidate acceptance.

Scope: a common baseline and offline replay isolate the update. Online policies can legitimately depend on feedback order, and different adaptively collected data need not be exchangeable. This test only rejects the literal stated invariance claim on identical available records; it does not disprove all threshold adaptation or show biological regret. With this fixed baseline there is also no convention ambiguity from b updating.

Additional evidence audit: the cited 9.77x cost concerns a different RNA-conditioned nuclear-completion versus no-RNA computation. It cannot be transferred to threshold-versus-direct-refit here. No runtime advantage or functional direction is established. The K562 endpoint direction and matched single-to-double decision contract must be authenticated before any future biological decision experiment.
