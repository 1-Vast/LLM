# PROTOCOL E148（预注册）：把哨兵检查扩到**连续列**——工具线的最后一处已知盲区

2026-10-27，R159。**在任何计算前冻结。** 只读 `gdsc_combinations`。

## 为什么

R158 的 `SENTINEL_OUTSIDE_VOCAB` 只对**指示列**生效。连续列上的哨兵值（例如浓度里的 −999、缺失被填成 0）**仍会漏**。

## 要加的规则

对连续列，检测"**某个极端值反复出现**"：

1. 该值出现比例 **≥ 2%**；
2. 它落在**其余取值范围的之外**；
3. 它与其余取值范围最近一端的距离 **> 0.5 × 其余取值的极差**。

三条同时满足才算哨兵。**第 3 条是为了不误伤"合法的重复极值"**（例如被截顶的、或量化的特征——那时其余取值范围会紧邻该值）。

## 验证（本轮的实验）

| 用例 | 期望 |
|---|---|
| `clean_continuous` | **PASS** |
| `minus999`（3% 的行填 −999） | **FLAG** |
| `zero_fill`（3% 的行填 0，其余为正） | **FLAG** |
| **`legit_capped`**（把上 3% 截到同一个值） | **PASS** ← **误伤检验** |
| `clean_onehot_design`（R158 的干净设计） | **PASS** |

## 预测（写死）

- **H384（新规则有效且不误伤）**：五个用例全部符合期望。
- **H385（误伤或漏检）**：任一不符。

**若 H384 成立 → 工具线的已知盲区关闭，`feature_audit` 达到"可交给下一位使用者"的状态。**

## 边界

- 三条阈值是拍的（2%、0.5 倍）；本轮只验证行为符合设计，不验证最优性。
- 只覆盖"极端值哨兵"；**中间值哨兵（例如把缺失填成均值）不可检测，也不打算检测**——那在数值上与真实值无法区分。
- 回顾性；不涉及机制、临床、药物选择；不做元学习/RSI。
