2026-10-27。**R172 指出：若 `merck_2016` 的整数码能映射回真实药名，那份未饱和的读数就能用。本轮把这条路走完。**

## 1．逐项检查结果

| # | 检查 | 结果 |
|---|---|---|

## 2．判决：H411 成立——分布物里没有映射

**格式支持真实名字（README 写明有 `treatment_names` 字段），但发布的文件把它填成了整数码，而仓库与 Zenodo 都没有提供反向对应的表。**

## 3．还有一层更硬的障碍

**即使 NCI-ALMANAC / Merck 2016 / GDSC-sq 这三套公开数据集的化合物清单在别处可得，也仍然不够。**

**因为缺的是“这个 h5 里的第 7 号处理 = 哪一个化合物”这一层索引对应。没有它，清单再全也挂不上去。**

> **所以 `merck_2016` 那份未饱和的读数，在本项目的能力范围内无法变成可用赛场。**

## 4．结论的边界（我没有检查什么）

- 未下载论文 PDF、未读其补充材料（bioRxiv API 只给元数据，不给附件清单）；
- 未逐页搜索 `batchie.readthedocs.io`；
- 未联系作者。

**所以准确的说法是：“我没有在分发的代码仓库、Zenodo 记录与 README 里找到映射”，而不是“映射不存在于世上”。**

## 5．这对“解冻条件”意味着什么

**R172：三个候选赛场数据内容不满足（无身份）。R173：身份也没法从配套材料里补回来。**

**两条合起来，“跨数据集复现”在本机的能力范围内已经走到尽头：**

- **不是没去找映射**（R173 找了）；
