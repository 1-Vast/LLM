# E005（预注册）：跨背景可比设计普查——这个归档里到底存在多少对可比的序比较

2026-10-27。R4 第二项，**只读设计元数据，不读任何响应值**。目的：判断"多对序聚合"路线在本资源上是否可行，即是否存在足够多的"同一药对、同一双方剂量、在 ≥2 个细胞背景、每个背景 ≥2 个重复文件"的比较单元。E004 给出的能力界是：单对序差需 ≥0.08–0.10 才可读出；若要用符号聚合检出高出随机 0.2 的反序比例，理想噪声下需 ≥39 个独立对比较。因此这个计数直接决定 I003 主张 A 是否准入。

## 只允许的计数

对每个 file 计算布局签名 = sorted(Well → (Drug 1, Conc 1, Drug 2, Conc 2))。按 (Iteration, 布局签名) 分组。

- 组内每个 cell 的文件数 n_cell_files。
- **可比单元（comparison unit）** = 一个具体的 (药 1, 剂量 1, 药 2, 剂量 2, Well)，它在 ≥2 个 cell 的布局里以**同名同剂量**出现，且这些 cell 每个在该布局下都至少有 1 个文件。
- 报告：
  1. 按 (Iteration, 布局) 分组的 cell 数分布、每 cell 文件数分布；
  2. 跨背景可比单元总数（全归档、以及排除 `dmso`/`high control`/`low control` 后的"真双药"子集）；
  3. 每个比较单元涉及几个 cell；
  4. **可用独立对比较数**：把"同一布局下每个 cell 对 (c1,c2) × 可比单元"计为一次跨背景序比较机会，并给出上界与去重后的量级；
  5. 每个 cell 的重复文件数：≥2 文件（能做板内重复平均）的布局占多少。

## 明确不做

- 不读 Viability / Raw count，不按响应筛任何单元（脚本里对这两列显式不加载使用）。
- 不把可比单元数当"独立生物学重复"；同一布局的多个 cell 共享同一批药板，可能有共同制备误差。
- 不据此宣称任何生物结论；这是**资源能力**普查。
- 若可用独立对比较数 < 39，则 I003 主张 A 在本资源上不可行，本资源对"序竞争可辨识性"的贡献到此为止，转为证据缺口报告（需要多少重复深度/多少背景）。

## 执行后补记（2026-10-27，读数不涉及响应值）

普查结果与后续必须带上的限定：

1. 371 个 file、19 个 cell、184 个布局组，其中**只有 18 个布局是跨 cell 的**。184 组里 166 组只含 1 个 cell。
2. 18 个跨 cell 布局共给出 **54,642** 个"双药、双方剂量相同、≥2 个 cell、且该 cell 有 ≥2 个重复文件"的机会对（含 dmso 单药时为 69,431）；唯一 (药对, 双方剂量) 键 3,818 个。相对 E004 的聚合需求（理想噪声下 ≥39 对），机会数是需求的上千倍——**样本量不是瓶颈**。
3. 这 18 个布局中有 13 个的 `Iteration` 字段为空。逐一核名后确认：它们的文件名是 `Batchie Project_Validation_Plate A–F_<cell>[_2].xlsx`，即**同一批 6 个药板在最多 12 个细胞系上各跑 2 块重复板**的成对设计（最大者 Plate A：12 cell × 2 files = 24 files / 252 个双药单元）。这正是"同一药物板在多个背景上重复"的设计形态。
4. **必须披露的暴露事实**：R2 已经把这些 Project_Validation 板的读数当作它 5 个新背景的**评分为终点**（309/314/315/315/314 个组合）。因此它们**不是新鲜确认集**：可作预注册的**次级/描述性**跨背景检验（因为从未用于选择"共享序 vs 背景特异序"这一假说），**不能**当作独立确认或新数据。
5. 因此 E005 的结论只能是：**聚合路线的样本量在资源内充足，但确认性检验仍缺独立来源**；I003 主张 A 的准入条件改为"用这 18 个成对布局做透明的次级检验 + 另找独立来源做确认"，而不是"资源不足"。
